# lifelog-extraction-v3 (현행)

PLAUD 라이프로그 노트의 구조화 필드와 요약·제목을 한 번에 추출한다.
`automation/plaud_sync/lifelog_extract_live.py`가 마커 아래를 읽고
`build_prompt`가 `{{SUMMARY}}`와 `{{TRANSCRIPT}}`를 치환한다.
v1·v2는 동결한다. v3는 v2에 title 만 더하며 추가 모델 호출은 없다.
title 은 Plaud 가 제목을 붙이지 못한 녹음에서만 이름 자리에 선다 — 로컬 전사 경로는
클라우드 요약도 전사도 **빈** 녹음을 골라 동결하므로 그런 녹음의 name 은 시각뿐이다
(2026-09-07 실측: "2026-09-07 11:39:11" → 노트 이름 `2026-09-07-113911--…`).
민감도 게이트를 통과한 녹취만 전달한다. Plaud 요약이 있으면 노트는 그것을 우선한다.

<<<PROMPT>>>
아래는 한 음성 녹취의 요약과 전사본이다.

요약:
{{SUMMARY}}

전사본:
{{TRANSCRIPT}}

이제 이 녹취에서 다음 키를 가진 JSON 객체 하나만 출력하라.

people: 대화에 등장한 사람의 실명 또는 호칭 문자열 배열. 전사본에서 실제로 불린 대로만 적는다("김 교수님", "박영희"). 이름을 지어내지 말고, 누구인지 불린 적 없으면 넣지 마라. "화자1" 같은 전사 라벨은 이름이 아니므로 제외한다.
places: 대화에 등장한 구체적인 장소 문자열 배열("3층 회의실", "역 앞 카페"). "여기·거기" 같은 지시어나 추상적인 표현은 넣지 마라.
decisions: 대화에서 합의되거나 확정된 사항. text(결정 내용)와 at(근거가 된 전사본 줄의 시각, MM:SS 또는 HH:MM:SS, 없으면 "") 키의 객체 배열. 아직 논의 중이거나 보류된 이야기는 결정이 아니다.
todos: 앞으로 해야 할 후속 조치. text(할 일)와 owner(담당자)와 due(기한)와 at(근거 줄의 시각) 키의 객체 배열. owner와 due는 대화에서 실제로 말한 경우에만 적고, 말하지 않았으면 ""로 둔다. 기한은 말한 그대로 쓴다("다음 주 화요일", "이번 달 말").
summary: 녹취 전체의 핵심을 한국어 마크다운 불릿 3–6개로 요약한 문자열. 각 불릿은 "- "로 시작하고 줄바꿈으로 구분한다. 요약할 내용이 없으면 ""로 둔다. 전사본에 없는 사실을 만들거나 항목 수를 채우려고 내용을 반복하지 마라.

title: 이 녹취가 무엇에 대한 것인지 알 수 있는 한국어 제목 한 줄(30자 이하). 예: "직장 동료들의 일상 대화: 업무, 진로, 취미". 날짜·시각이나 "녹음"·"대화" 같은 껍데기 말만으로 채우지 마라. 전사본에 없는 사실을 제목에 넣지 마라. 제목을 지을 근거가 없으면 ""로 둔다.

at은 근거가 된 전사본 줄 맨 앞 대괄호 안의 시각을 그대로 옮긴다. 근거 줄을 특정할 수 없으면 ""로 둔다. 각 text는 한 줄로 줄여 200자를 넘기지 마라.

녹취에 없는 내용을 지어내지 마라. 해당하는 것이 없는 배열 키는 빈 배열로, summary는 빈 문자열로 둔다. 설명 금지, 마크다운 펜스 금지, JSON 객체 하나만 출력하라.
