# Runtime Python packages: release source -> account-home deployment.
#
# Why this exists: the RAG watcher imports ~/.hermes/rag_ingest_runtime, not the
# immutable release. On 2026-08-22 that runtime was still dated 2026-07-15..22:
# release comparison found same=13, DIFF=5, ABSENT=1, while wrapper-only drift
# monitoring reported clean. In other words, release convergence did not deploy the
# package and the missing deployer made a month of fixes silently unreachable.
# memory_curator is the measured control (same=34, diff=0) and uses the same layout.
#
# Format: <account>|<release-subpath>|<home-relative-runtime-path>|<policy>[|<selector>|<profile>[|<deployed-python-files>]]
# Four fields remain backward-compatible: the check's primary node and recursive Python
# snapshot are defaults. `rag|tree` selects NODE_RAG_NODE_NAME and hashes the complete
# managed tree because Dockerfiles, Compose, pyproject/locks, service/env examples, and
# dockerignore files can change deployment/build behavior. Node-only .env.secrets and
# cache directories are always excluded. `deployed-python-files` is a comma-separated,
# deployer-derived list relative to the release subpath: it narrows the release snapshot
# only, so a stale extra runtime file still fails. Only verified layouts belong here.
# interop_runtime: reason=deploy-skill.sh stages GATE_HELPERS, GATE_INTEROP_HELPERS and the separate OWNER_NOTICE_HELPERS facade import closure into agent automation/ without pruning retained files, so a recursive source snapshot reports intentional omissions and extras; alternative=hash each helper named by those three deploy-skill.sh allowlists after staging.
# reminder_poller_runtime: reason=the flat poller_core.py and reminder_store.py imports are deployed before the wrapper by automation/reminder_poller/deploy.sh; alternative=the package deploy-manifest.txt declares both runtime files for per-file watcher drift checks, avoiding a recursive source snapshot that miscounts the separately deployed wrapper.
