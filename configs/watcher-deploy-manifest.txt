# Hermes no-agent cron 래퍼: 릴리스 소스 → 계정 홈의 배포본.
#
# 이 파일들은 릴리스 트리가 아니라 **계정 홈**(`~/.hermes/scripts/`)에 산다. 2분 리컨실러는
# 릴리스만 수렴시키므로, 워처를 고쳐 머지해도 사람이 그 스킬/패키지의 `deploy.sh` 를 돌리기
# 전까지 노드는 옛 코드를 계속 돌린다 — 그리고 그 사실을 말해 주는 것이 없었다. mailon 런타임이
# 19일간 그렇게 방치됐고, 2026-08-20 실측에서도 `memory_curator_watch`·`memory_relocate_watch`
# 두 개가 조용히 낡아 있었다.
#
# 형식: <account>|<릴리스 소스 경로>|<홈 기준 목적지>|<policy>
#   policy=required        배포돼 있어야 한다. 없거나 다르면 FAIL.
#   policy=optional:<사유>  없을 수 있다(그 사유가 설계다). 배포돼 있으면 드리프트는 여전히 FAIL.
#
# 목적지 이름은 소스 이름과 다를 수 있다 — 「confirm 워처 배포 파일명은 스킬별로 고유」 규칙 때문에
# calendar 는 `confirm_reaction_watch.py` 를 `calendar_confirm_reaction_watch.py` 로 배포한다.
# 그래서 이름 추론이 아니라 이 표가 진실이고, conformance 테스트가 `deploy.sh` 와 대조한다.
#
# 재배포 명령은 소스 경로 앞 두 조각에서 유도된다: `skills/mail/scripts/x.py` → `skills/mail/deploy.sh`.
#
# **행을 늘리거나 account·destination 을 바꾸면 노드 래퍼도 함께 갱신해야 한다.**
# healthcheck 는 전용 키로 노드에 ssh 하고, 그 키는 authorized_keys 에서
# `command="~/.local/libexec/autophagy-healthcheck-probe"` 강제명령에 묶여 있다.
# 그 래퍼는 `SSH_ORIGINAL_COMMAND` 의 sha256 **정확 일치**만 허용하고 나머지는 exit 126 이므로,
# 여기 행을 더하면 그 행이 내는 명령의 해시를 래퍼에 넣기 전까지 프로덕션에서는 읽힐 수 없다.
#   해시 계산: printf '%s' "sudo -n -u <account> -H bash -c 'sha256sum \"$HOME/<destination>\" 2>/dev/null | cut -d\" \" -f1'" | sha256sum
# 래퍼는 리포에 설치기가 없는 손 유지보수 자산이라 이 결합을 산문으로만 들고 있다(follow-ups 기록).
