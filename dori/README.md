# dori/ — 도리 기반 사이토플라즘의 저장소 층

cytoplasm 은 그대로 제품 저장소이고, 이 폴더가 그 위에 **도리**(상시 메신저 에이전트)를 얹는다.
도리 코드 자체는 포크 `orientpine/omo-dori-mode-experimental` 에 있고, 여기에는 그 포크를
어느 커밋으로 받을지와 기본 도리 구성의 틀만 있다.

| 층 | 어디 | 담는 것 |
|---|---|---|
| 범용 도리 | 포크 저장소 | lane·질문 카드·스레드·5분 완료 확인 같은 공통 동작 |
| 기본 도리 구성 | 이 폴더(공개) | 포크 고정 커밋, 역할 템플릿, 아바타 |
| 설치별 설정 | 각 설치의 `~/.dori/`·작업 폴더 | 봇 토큰·채널·소유자 id, 소유자가 고쳐 쓴 지침 |

## 무엇이 있나

- `pin.toml` — 포크 URL 과 고정 커밋(40자 SHA). 설치기는 이 커밋만 받고 `git rev-parse HEAD`
  가 같은지 확인한다. 서명 릴리스 태그가 이 파일까지 덮으므로 서명되지 않은 도리 코드가 설치되는
  길이 없다. 배포 영수증(`/srv/autophagy-private/deploy-all/receipt.json`)의 `dori_pin` 이 이 값을
  그대로 말한다.
- `roles/roles.toml` — 역할 목록. 리드(짱도리)와 비서(유도리)는 기본, 옥도리(카톡)·
  무도리(회사 업무·긴 문서)·공도리(연구)는 선택이다. 포크 공통 지침은 긴 문서를 무돌에게 맡기라고
  하는데, 무도리를 깔지 않은 설치에서는 역할 템플릿이 그 일을 유도리에게 돌린다.
- `roles/<역할>/AGENTS.md.tmpl` — 그 도리의 역할 규칙. 설치기가 `{{OWNER_CALL}}`(도리가
  소유자를 부르는 말)과 포크 경로를 채운다. 실명·채널 id·경로·토큰은 들어 있지 않다.
- `roles/<역할>/avatar.md` — 그 도리의 아바타 이미지 프롬프트(소유자 확정본, 원문 그대로).
- `roles/<역할>/avatar.jpg` — 소유자가 만든 원본 그림(메타데이터 지움). 저장소 템플릿으로만 두며, 설치기는 `avatar.md` 만 깔고 이 그림은 깔지 않는다.

## 설치

```bash
python3 -m automation.install.wizard            # 메뉴에서 1. dori (기본)
python3 -m automation.install --dry-run         # 계획만 (쓰기·네트워크 없음)
python3 -m automation.install.dori --role okdori --owner-call 형
```

이미 있는 파일은 덮지 않는다. 같으면 넘어가고, 다르면 차이만 보여 주고 그대로 둔다. 이미 있는
`~/.dori/src` 가 고정 커밋이 아니면 아무것도 설치하지 않는다. 자세한 것은
[설치 가이드 「도리 프로필」](../docs/guide/install.md#도리-프로필)과
[기능 소개](../docs/기능소개/도리-저장소-층.md).

## 고정 커밋 올리기

포크 main 을 자동으로 따라가지 않는다. 올릴 때는 `pin.toml` 의 `commit` 을 바꾸는 PR 하나를
만들고, 릴리스 노트에 "도리 포크 <짧은 SHA>: 바뀐 것" 을 적는다.
