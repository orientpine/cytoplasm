# automation/ — 오케스트레이션·게이트·워처·배치 코어

에이전트 실시간 로직 밖의 모든 자동화. 순수 로직은 stdlib 전용, 외부효과는 승인 게이트 경유.
대부분 서브패키지는 `python3 -m automation.<pkg>` 또는 `<pkg>/*_cli.py`로 실행.

## 루트 스크립트/모듈
- `deploy-skill.sh` — 스킬 배포 4단계 게이트 (SANDBOX→REVIEW→owner ✅→MOUNT). `peer_attest_mode=discord|signed`를 명시적으로 전달하고 signed 모드에서는 peer stdout의 단일 SSH 서명 레코드를 gate stdin으로 운반한다(공유 상태 없음, unset=거부). owner 결정은 시간 비만료, peer 증명만 TTL 만료 시 같은 바인딩 자동 재검증. 스킬별 실행 lease가 refresh→consume을 직렬화한다. 배포 판정=live 심링크 해시.
  - `autophagy-supply-chain-watch`의 같은 2분 틱이 미응답 `skill-deploy`를 `approval_lifecycle.remind_owner_approval`로 넘긴다. `automation/supply_chain_remind.py`는 메시지 snowflake에서 실제 게시 시각을 복원하고 `ReminderJournal`로 due 시간 구간을 claim한 뒤, 실제 전송 edge에서만 레코드의 channel을 `skill_gate_surface.surface_for(...).stored(record)`로 재검증해 원 `#approvals` 메시지의 guild 점프 링크를 전송한다(disabled/not-due/terminal은 channel·guild 조회 0). 별도 cron·승인 메시지·resolver를 만들지 않으며 전송 실패는 배포 재개 판정을 바꾸지 않는다.
  - **자가 스킬 이름 충돌 차단(SS-1)**: 배포가 계정의 자가 저작물을 덮어쓰지 못하게 `SELF-SKILL-COLLISION-BLOCK`(exit 4)으로 멈춘다. agent 쪽은 `assert_agent_root_has_no_self_skill`이 `mountpoint`로 두 토폴로지를 구분한다 — 레거시 read-only bind가 남아 있으면 governed 전건이 그 루트에 보이므로 판정을 유보하고(`governed-mount`), 반전된 뒤에는 그 루트가 자가 저작 공간뿐이라 깊이 2까지(Hermes는 자가 스킬을 카테고리 디렉터리 아래에 둔다) 동명 디렉터리를 찾으면 차단한다. peer 쪽은 `peer_skill_root_state`가 같은 루트를 샌드박스 staging과 함께 쓰므로 3분류다 — `.usage.json`이 agent-created라고 말하거나 frontmatter에 `author: autophagy-agents`가 없으면(`foreign`) 차단하고, 우리 자신의 잔여 사본만(`staging-residue`) 덮어쓴다. **읽지 못하거나 분류가 모호해도 같은 코드로 멈춘다**(fail-closed). 가드는 순수 로컬 검증 뒤·stage 1 앞에 놓여 ops 동기화·실행 lease·peer staging 어느 것도 그 전에 일어나지 않고, `--remove`는 대상이 아니다(충돌에서 **빠져나오는** 길이다). 반대 방향(자가 스킬이 배포 이름을 선점)은 Hermes `skill_manage(create)`가 어느 루트든 동명이 있으면 거부해 막는다.
- `update_trust.py` + `git_tag_signature.py` — 공개 `origin/main`과 같은 commit을 가리키는 annotated tag만 임시 bare repo에서 가져와 update trust principal로 검증한다. 미서명 head·lightweight tag·교체 전 키는 pre-convergence에서 차단하고 healthcheck 기존 티켓 경로로 사유를 낸다. **서브커맨드가 둘이고 섞지 않는다**: `resolve`는 노드의 `require_signed_updates`를 따르는 **호환용**이고(리포 안에 호출자가 없다), `resolve-signed`는 config를 아예 읽지 않고 floor·신뢰루트를 호출자에게서 받는 **인가용**이다. **root로 설치하는 경로는 반드시 후자만 쓴다** — `converge_origin_main.sh`가 `~ops/.hermes/node.toml`을 전자에 넘기던 동안, ops는 그 헬퍼에 NOPASSWD sudo 권한을 가진 채 자기 홈 파일 하나로 서명 요구를 끕 수 있었다(2026-08-21 수정). 같은 이유로 `deploy-skill.sh`도 by-value 수렴을 쓰지 않고 인자 없는 특권 헬퍼를 부른다. 상세: [소개](../docs/기능소개/서명-전용-특권-수렴-경계.md).
- `skill_gate.py`(+`skill_gate_review.py`·`skill_gate_e2e.py` 서명 주입 E2E 경로) / `skill_review.py`(결정론적 해시 바인딩 보안 리뷰) / `skill_store.py` — 배포 승인·리뷰·레지스트리.
- `skill_gate_retire.py` — pending 레코드 **회수(retirement)**: MOUNT 성공 후 `consume`(=`(skill, hash, message_id)` compare-and-swap 삭제, 실패해도 마운트를 되돌리지 않음 — deploy-skill.sh가 `CONSUME-WARN`으로 경고만) + 소유자 결정이 소비될 수 없을 때의 감사 탈출구 `abandon`(3필드 완전 일치 강제, `logs/approval-abandons.jsonl`에 fsync 감사 후 삭제, Discord 메시지는 절대 삭제하지 않음). 요청 경로와 **같은 key lease**를 사용.
- `healthcheck.sh` + `runtime_package_probe.sh`(릴리스 밖 Python 런타임은 재귀 sha256, RAG 노드는 전체 빌드 입력과 실행 중 MCP 핵심 모듈까지 다중 노드에서 fail-closed 탐지) · `provision-agent.sh`(멱등) · `provision-skill-roots.sh`(스킬 루트 토폴로지 **반전** 프로비저너 — 멱등, root 실행: 레거시 read-only bind 해제와 fstab 2행 제거, 1차 루트를 계정 소유 0700으로, `.hub` 상태를 taps.json sha256 readback과 함께 비파괴 이관, config에 `external_dirs`+`guard_agent_created` 패치 — 기존 `skills:` 블록은 넘겨짚지 않고 `SKILLS-BLOCK-BLOCK`으로 멈춘 뒤 부족한 줄을 출력하고, 마지막에 `hermes skills list`로 external 발견을 선검증한다. peer arm은 잔여 사본을 3중 조건(이름·author 마커·repo 존재)으로만 지우고 현역 자가 스킬을 pin한다) · `peer_attest.py`(Discord 또는 `autophagy-peer-attest` namespace SSH 서명 생성·refresh) + `peer_attest_runtime.py`(CLI 입력·Discord transport·승인 표면 해석) + `peer_attestation.py`(두 모드 공유 wire contract + attestation 시각 기준 TTL·root-owned 공개키 검증기) · `deploy_execution_lock.py`(기존 `FileKeyLease` 재사용) · `bootstrap-accounts.sh` — 노드 운영·프로비저닝.
- `selfskill_root_probe.sh` — `healthcheck.sh`가 배선하는 자가 스킬 루트 토폴로지 프로브(읽기 전용): 1차 루트가 mountpoint가 아니고 계정 소유 0700인지, config에 `external_dirs` 항목과 `guard_agent_created`가 있는지 대조하고, 어긋나면 재실행·롤백 경로를 함께 낸다.
- `sudoers.d/`, `*/systemd/` — 배포 대상 권한·유닛 정의.

## 이 디렉터리의 규칙
- **cron 워처는 Discord 리액션만 폴링** (메시지/첨부는 실시간 에이전트 단독 소유 — 경쟁 소비자 금지).
  예외: 행동 없는 수동 인덱서(`rag_ingest`, `report_hub` 폴링, `managed_sync` git remote 폴링).
  별도 분류: **Discord 수신 없는 내부 큐 executor**(`repair_report_consume_watch`) — Discord 메시지·첨부를 수신하거나 폴링하지 않고, capability-bound 내부 큐를 소비해 카드 readback 뒤 보고를 송신하므로 실시간 에이전트와 경쟁 소비자를 만들지 않는다.
- **no-agent cron**: `~/.env.secrets` 자가 로드 + repo `sys.path` 래퍼 + 자식 subprocess에 자격증명 `env=` 명시 전파.
- 상세 설계 규약: [docs/guide/watcher-cron-설계규약.md](../docs/guide/watcher-cron-설계규약.md).
- **구독자 틱은 둘이 아니라 하나다** — `managed_sync/cron/managed_sync_watch.py`를 Hermes cron(`managed_sync/deploy.sh`)과 systemd 타이머(`managed_sync/systemd/`, 설치기 opt-in)가 함께 쓴다. 놓은 잠금·자격증명 전파·D3 경계를 배포 경로별로 다시 구현하지 말 것. 같은 tick 안에서도 skill tag fetch와 roster ref fetch는 같은 mirror를 쓰되 호출·실패 상태를 분리한다 — roster 브랜치 부재가 skill 배달을 막으면 안 된다.
