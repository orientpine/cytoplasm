  - **손댈 수 없는 것은 `follow-ups-deferred.md`로 옮긴다**(2026-08-26 분리): 소유자·노드에서만 닫히는 것(OWNER), 동결·벤더에 막힌 것(BLOCKED), 조건 성립 전에는 조치하지 않는 것(OBSERVE), 이미 닫힌 것(해소). 요약표는 `follow-ups.md`만 센다 — 보류분은 "지금 남은 일"이 아니다. 삭제가 아니라 **이동**이며, 원 `##` 헤딩을 양쪽에서 유지해야 회계 가드(A9)가 이동과 삭제를 구분한다. 묶음 하나가 `##` 헤딩, 불릿마다 "문제 → 조치" + 영향 범위·심각도. 상세 규칙: 루트 `AGENTS.md`「후속 과제 기록 규칙」.
  - **불릿은 3줄 안에 끝낸다.** DONE의 「최대 3줄」이 효과를 증명했다 — 상한이 없던 후속 과제만 평균 623자까지 부풀었다. 넘치는 근거는 `docs/qa/` 증적으로 밀어낸다.
- **DONE** — 구현·검증이 끝난 기능. **본문은 `done.md`**. 항목당 설명 **최대 3줄**, wave ID 병기.
  - 증적은 `docs/qa/<wave-id>/`, 인프라 변경 기록은 `docs/patch/` 참조.
- 상태 매핑: 계획 문서의 `[x]`(완료) → DONE / `[~]`·`[ ]`(차단·보류·부분·미착수) → PLAN "개발 예정"에 유지.
  부분 완료는 완료분만 DONE에 적고 잔여분을 PLAN에 남긴다(예: W1-7).
- **작업 종결 시 정리 (cha 지시, 2026-07-29)**: 한 사이클을 닫을 때 **PLAN·후속 과제에서 끝난 부분을 DONE으로 옮기고 정리하는 것까지**가 종결 조건이다.
  - **PLAN·후속 과제는 열린 일만 남긴다.** 해소된 항목을 `[해소됨]` 표시만 붙여 쌓아두면 무엇이 남았는지가 보이지 않게 된다.
  - **기능은 DONE으로, 교훈은 해당 DONE 항목 안으로** 접어넣는다. 조치가 필요 없는 단순 기록은 그 한 줄로 충분하다.
  - **부분 완료는 쪼개서** 완료분만 DONE으로 옮기고 잔여를 PLAN에 남긴다 — 잔여 불릿은 무엇이 남았는지를 그 자리에서 읽힐 수 있게 다시 쓴다.
  - **옮길 때 내용을 버리지 않는다.** 증적 경로·커밋·기능소개 링크는 DONE 항목에 그대로 달고 간단히 압축한다. 옮기기 전후로 `git diff --stat`을 확인해 설명되지 않는 삭제가 없음을 본다(「커밋 전 diff 확인 규칙」).
  - **계획 문서가 `[~]`로 둔 항목은 임의로 옮기지 않는다** — 「개발 예정」은 `.omo/plans/`가 단일 진실이므로 근거 없이 재분류하면 두 문서가 어긋난다.
- **프로젝트 전체를 한 화면에서** 보려면 [인터랙티브 소개 페이지](기능소개/autophagy-agents-intro.html)를 브라우저로 연다 — 승인 게이트를 직접 ✅/⛔ 눌러보고, 17개 스킬을 검색하고, 배포 4단계와 7개 웨이브를 펼쳐볼 수 있다. 이 현황판이 "무엇이 어디까지 됐나"라면 그쪽은 "이 시스템이 무엇인가"다.
