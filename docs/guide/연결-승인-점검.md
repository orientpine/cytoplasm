# 연결·승인 점검 (doctor)

설치기와 healthcheck 는 **인프라**(계정·유닛·릴리스·타이머)가 맞는지를 본다. 그 둘이 모두
통과해도 사람이 해야 하는 연결 — 모델 로그인, Discord 봇, 승인 채널, Google 동의 — 이 빠졌거나
만료됐으면 에이전트는 답하지 못하고 승인 카드는 게시되지 않는다. 정기 작업이 매시간 실패해도
그것을 알리는 곳이 없었다.

`python3 -m automation.doctor` 는 그 **사람 몫의 연결 상태**를 계정 안에서 읽기만 해서 판정하고,
끊긴 항목마다 누가 어디서 무엇을 승인해야 하는지 절차를 함께 낸다. 설치 마법사가 설치 끝에 이것을
돌려 하나씩 안내하고, 설치 뒤에는 매시간 점검해 **바뀔 때만** 소유자에게 알린다.

## 1. 실행

```bash
# 운영자 계정(또는 root)에서 — agent·peer 두 계정을 sudo -n 으로 각각 진단해 모아 보여 준다
cd /srv/autophagy-agent-current && python3 -m automation.doctor

# 한 계정만
cd /srv/autophagy-agent-current && sudo -u agent -H python3 -m automation.doctor
```

| 옵션 | 뜻 |
|---|---|
| `--offline` | 네트워크 검사(Discord API·Google 토큰)를 건너뛰고 로컬 파일만 본다 |
| `--json` | 기계용 출력 |
| `--account NAME` | 운영자 모드에서 진단할 계정(반복 가능, 기본 agent·peer) |
| `--notify` | 바뀐 문제만 소유자에게 알린다 — 서비스 계정 전용, 보통 워처가 쓴다 |

종료코드: **0** 고장 없음 · **1** 고장 있음 · **2** 사용법 오류. 확인(WARN)은 종료코드를 바꾸지 않는다.
`sudo` 비밀번호가 필요하거나 그 계정이 코드를 읽지 못하면 `[WARN] doctor-run` 과 수동 명령이 나온다
(설치 직후라면 릴리스가 수렴하는 약 2분 뒤 다시 실행한다).

## 2. 판정 읽는 법

- **`[PASS]` 통과**
- **`[WARN]` 확인** — 선택 기능이 꺼져 있다, 권한이 일부 없다, 판정할 수 없었다. 필요할 때 켠다.
- **`[FAIL]` 고장** — 필수 연결이 없거나, 구성했는데 동작하지 않는다. 절차대로 고친다.

| 항목 | 무엇을 보나 | 사람이 승인·연결하는 곳 | 끊기면 멈추는 것 |
|---|---|---|---|
| Hermes 런타임 | `~/.local/bin/hermes` | 계정에 Hermes 설치 | 에이전트 전체 |
| Hermes 게이트웨이 | `systemctl --user is-active` | (설치·재시동) | Discord 대화·승인 버튼 |
| 주 모델 | `config.yaml` 의 `model.provider` 와 그 로그인 | ChatGPT 구독 계정의 기기 코드 승인 | 모든 대화·요약·배치 모델 호출 |
| 폴백 모델 | `fallback_providers` 와 그 로그인 | xAI 계정의 기기 코드 승인(선택) | 주 모델이 막혔을 때의 대체 응답 |
| Discord 봇 | 토큰 유무, 온라인이면 토큰·인텐트·권한·채널(GET 전용) | Developer Portal 과 개인 서버 초대 | 대화·승인 카드·결과 통지 |
| 승인 채널 (agent) | `interop/config.json` 의 채널·소유자 id | 개인 서버 `#agent-chat`·`#notifications` | 모든 승인 요청 |
| Google Workspace (agent) | 자격증명 파일, 온라인이면 토큰 유효성·서비스별 권한 | Google 동의 화면(OAuth) | 메일 발송·캘린더·Drive·과제비·할 일 |
| Drive 산출물 발행 (agent) | `DRIVE_PUBLISH_ENABLED=1` | `~/.env.secrets` | 산출물의 Drive 발행 |
| 기관메일 (agent, 선택) | 세 값이 모두 있는지 | 기관 계정 | 기관메일 조회·발송 |
| 로컬 음성 전사 (agent) | whisper.cpp 실행 파일·모델 경로 | 설치·경로 설정 | 녹음 → 전사본 → 회의록 |
| 정기 작업 | Hermes cron 상태 — 3회 이상 연속 실패는 고장 | — | 리액션 처리·리마인더·일일 보고 |

주 모델이 `custom:<이름>`(예: 로컬 LiteLLM)이면 로그인 대상이 아니므로 `custom_providers` 에 그 이름이
선언돼 있는지만 본다. 개인 서버 `#approvals` 의 채널 id 가 config 에 없는 것은 고장이 아니다 — 런타임이
채널 이름으로 찾는다.

## 3. 승인·연결 절차

아래 명령의 `agent`·홈 경로는 설치의 서비스 계정에 맞춰 바꾼다(doctor 출력은 실제 값으로 채워 준다).

### 주 모델 — Codex 구독 OAuth

```bash
sudo -u agent -H /home/agent/.local/bin/hermes auth add openai-codex --type oauth
```

화면에 나온 주소를 브라우저에서 열고 표시된 코드를 입력해 ChatGPT 구독 계정으로 승인한다. 확인은
`hermes auth status openai-codex` 가 `logged in` 을 내는 것이다. 다른 공급자를 쓰면 그 공급자로
`hermes auth add` 하거나 `custom_providers` 에 선언한다([라우팅 정책](../../configs/routing-policy.md)).

### 폴백 모델 (선택)

```bash
sudo -u agent -H /home/agent/.local/bin/hermes auth add xai-oauth --type oauth
```

`fallback_providers` 에 적힌 공급자는 로그인이 없으면 실제로는 동작하지 않는다 — doctor 가 그것을 짚는다.

### Discord 봇

1. Discord Developer Portal 에서 앱을 만들고 Bot 토큰을 발급한다. **Message Content Intent 를 켠다.**
2. 계정 홈의 `~/.env.secrets`(0600) 에 `DISCORD_BOT_TOKEN=<토큰>` 한 줄을 둔다. 채팅·화면에 붙여넣지 않는다.
3. 봇을 개인 서버에 초대한다. 권한·초대 URL·채널 구성은
   [제3자 런타임 전제 §1](third-party-runtime-prereqs.md#1-discord-앱봇서버채널) 이 단독으로 소유한다.
4. 토큰을 바꿨으면 게이트웨이를 재시동한다(agent·peer 함께, [설치 가이드 §6.1](install.md)).

### 승인 채널

`~/.hermes/interop/config.json` 에 다음을 적는다.

- `agent_chat_channel_id` — 개인 서버 `#agent-chat`. 없으면 승인 요청이 게시되지 않는다(fail-closed).
- `owner_id` — 소유자 Discord 사용자 id. 이 id 의 ✅/⛔ 만 승인으로 인정된다.
- `owner_notice_channel_id` — 정기 통지·doctor 알람을 받을 `#notifications`. 비우면 DM 으로 간다.

### Google Workspace

`gws` CLI 한 벌이 메일 발송·캘린더·Drive·Sheets·Tasks 를 모두 맡는다. 동의는 **브라우저가 있는 PC** 에서
하고, 암호화된 자격증명만 노드로 옮긴다.

1. Google Cloud 콘솔에서 프로젝트를 만들고 Calendar·Gmail·Drive·Sheets·Tasks·Meet API 를 사용 설정한다.
2. OAuth 동의 화면을 구성하고(개인 사용이면 테스트 상태로 두고 자기 계정을 테스트 사용자로 추가),
   **데스크톱 앱** OAuth 클라이언트를 만들어 JSON 을 `~/.config/gws/client_secret.json` 으로 둔다.
3. 필요한 권한만 요청해 로그인한다. 동의 화면에서 **Select all 을 누르지 않는다**. 검증되지 않은 앱 경고는
   자기 계정·자기 클라이언트라면 예상된 흐름이다.

   ```bash
   GWS_SCOPES='openid,email,profile,https://www.googleapis.com/auth/userinfo.email,https://www.googleapis.com/auth/userinfo.profile,https://www.googleapis.com/auth/calendar,https://www.googleapis.com/auth/drive,https://www.googleapis.com/auth/spreadsheets,https://www.googleapis.com/auth/gmail.send,https://www.googleapis.com/auth/gmail.readonly,https://www.googleapis.com/auth/tasks,https://www.googleapis.com/auth/meetings.space.created'
   gws auth login --scopes "$GWS_SCOPES"
   rm -f ~/.config/gws/token_cache.json && gws auth status   # token_valid: true
   ```

4. `credentials.enc` · `.encryption_key` · `client_secret.json` 세 파일을 노드 서비스 계정의
   `~/.config/gws/` 로 옮긴다(디렉터리 0700, 파일 0600, 소유자 = 그 계정). 노드에도 `gws` 가 있어야 한다.
5. 노드에서 `sudo -u agent -H /home/agent/.local/bin/gws auth status` 가 `token_valid: true` 인지 본다.

권한을 하나 더할 때 `gws auth login --services <서비스>` 를 쓰지 않는다 — 저장된 자격증명이 그 서비스
권한만으로 **교체**되어 나머지가 한꺼번에 끊긴다. 항상 위 전체 목록에 새 권한을 붙여 다시 동의한다.
doctor 는 서비스별로 빠진 권한을 이름으로 짚는다(`권한 없음: 할 일` 처럼).

### 선택 기능

- **Drive 발행** — `~/.env.secrets` 에 `DRIVE_PUBLISH_ENABLED=1`. 규약은 [drive-publish](drive-publish.md).
- **기관메일** — `MAILON_ID` · `MAILON_PW` · `MAILON_TOTP_SECRET` 세 값을 모두. 일부만 있으면 고장이다.
- **로컬 음성 전사** — whisper.cpp 를 빌드하고 `SPEECHTOTEXT_WHISPER_BIN` · `SPEECHTOTEXT_WHISPER_MODEL`
  을 실제 경로로. 경로가 사라지면 고장이다.

### 정기 작업

```bash
sudo -u agent -H /home/agent/.local/bin/hermes cron list --all   # 실패 문구
sudo -u agent -H python3 /home/agent/.hermes/scripts/<스크립트>    # 원인 재현
```

고치면 다음 실행에서 통과로 바뀌고, 알람이 「해결됨」을 알린다.

## 4. 설치 중 안내

- 설치 마법사 **① 전제 확인** 이 「설치가 끝나면 사람이 승인·연결해야 하는 것」 목록을 보여 준다.
  doctor 와 같은 레지스트리에서 뽑으므로 판정 항목과 어긋나지 않는다.
- 설치가 성공하면 **⑦ 연결·승인** 에서 doctor 를 돌린다. 대화형이면 절차대로 승인한 뒤 Enter 로 다시
  점검하고, 고장이 없고 모든 계정을 진단하면 끝난다(`q` 로 나중에). 설치 종료코드는 바뀌지 않는다.
- `quickstart.sh` 도 설치가 성공하면 doctor 를 한 번 보여 준다.

## 5. 알람

`doctor-watch` 가 agent·peer 계정마다 매시간 `--notify` 로 점검한다. 문제 집합(상태·항목·대상)이 바뀔
때만 소유자 통지 채널(`owner_notice_channel_id`, 없으면 DM)로 「새로 확인된 문제」와 「해결됨」을 보낸다.
같은 문제를 매시간 되풀이하지 않는다. 전송이 실패하면 상태를 전진시키지 않아 다음 점검이 다시 보낸다.
상태는 `~/.hermes/doctor/state.json`(0600) 에만 있다.

배포 경로는 둘이고 같은 래퍼를 돈다.

- **프로필로 설치한 노드** — 설치기 컴포넌트 `doctor-watch`(systemd 타이머)가 네 프로필 모두에 포함된다.
  프로필 없이 설치했다면 `--with-component doctor-watch` 로 더한다.
- **오케스트레이터에서 배포하는 노드** — `automation/doctor/deploy.sh` 가 Hermes no-agent cron 으로 둔다.

둘이 한 노드에 겹쳐도 알람 상태 잠금이 한 번만 보낸다. Discord 봇 자체가 끊기면 이 알람도 도달하지
못한다 — 그 경우는 healthcheck 의 별도 통지 경로와 doctor 명령으로 확인한다.

## 6. 안전 경계

- **읽기 전용이다.** 네트워크 호출은 온라인 검사의 Discord GET 과 `gws auth status` 뿐이다.
- 비밀은 「있다/없다」로만 읽고 값은 출력·JSON·알람 어디에도 싣지 않는다. 정기 작업의 오류 문구는
  토큰처럼 긴 문자열을 가린 뒤 120자로 자른다.
- 승인 게이트를 대신하지 않는다 — 연결 상태를 알릴 뿐 어떤 외부효과도 실행하지 않는다.
