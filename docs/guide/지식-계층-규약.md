# 지식 계층 규약 — Knowledge Adoption Contract v1

이 문서는 Obsidian, 개인 RAG, LLM wiki를 읽는 모든 스킬의 단일 계약이다.
세 저장소의 역할은 영구 고정한다: **Obsidian은 사람이 쓴 원천 노트**, **wiki는
소유자가 승인한 정리된 사실·판단**, **RAG는 두 계층과 기타 기록을 찾는 검색 인덱스**다.
`automation.knowledge`는 읽기 전용이며 새 승인 표면, 워처, 쓰기 또는 노드 mutation을
만들지 않는다.

## 불변 규약 R1-R6

- **R1 진실의 방향**: 사실이 충돌하면 wiki(active, 비만료, 소유자 ✅) > Obsidian
  원문(명시 날짜 최신) > RAG 기타(conversation/team/agents-log) 순이다. RAG score는
  관련성이지 진실성이나 최신성의 증명이 아니다.
- **R2 쓰기 경계**: Obsidian 쓰기는 `obsidian_write`/`memory_relocate` 게이트만,
  wiki 쓰기는 `wiki_cli draft` 후 소유자 ✅만, RAG 쓰기는 인제스트 파이프라인만 한다.
  지식 파사드와 소비 스킬은 세 저장소를 변경하지 않는다(SI-5, SI-6 유지).
- **R3 읽기 경계**: 스킬은 저장소를 직접 읽지 않고 `automation.knowledge`만 호출한다.
  wiki 자체 CLI, `rag_ingest`, `twin_*` 쓰기 측만 예외다. 스킬별 검색과 출처 렌더를
  따로 구현하지 않는다. `test_knowledge_adoption_conformance.py`가 이를 강제한다.
- **R4 민감도**: RAG 행은 `sensitivity` 메타, 주 모델 non-GLM 게이트, 센티널이라는
  recall v2 규칙을 공유한다. wiki/twin 직접 행은
  `automation.rag_ingest.sensitivity.classify`와 같은 rules로 다시 분류하며 rules를
  읽거나 분류할 수 없으면 제외한다. patent-sensitive 근거를 받는 소비 스킬은 기존
  라우팅 규칙으로 codex-only를 선택한다. `[[PATENT-SENSITIVE-RECALL]]`가 든 content는
  GLM에 보내지 않는다.
- **R5 출처와 무결성**: 산출물은 팩의 `E1`... id만 인용한다.
  `validate_citations`는 팩 밖 id를 제거한다. 근거가 없으면 결정론 문구 "근거 없음"을
  쓴다. 날짜는 메타데이터나 지원 경로에 명시된 값만 사용하고 추측하지 않는다.
- **R6 위치**: 이 규약이 정본이다. 역할 설명은 `개인-위키.md`, 코드 경계는
  `automation/AGENTS.md`와 `skills/AGENTS.md`가 함께 가리킨다.

## 계약 v1 API

모든 값 객체는 stdlib의 `@dataclass(frozen=True, slots=True)`다.

- `KnowledgeQuery(text, purpose, sources, tags, limit, caller)`
  - `purpose`: `cite | synthesize | entity | judgment`
  - `sources`: `rag | wiki | twin`의 부분집합. 소비자는 줄일 수만 있다.
  - `limit`: 1 이상 20 이하.
- `EvidenceItem(id, store, source_type, ref, title, doc_date, date_basis, score,
  grounded, authority, expired, sensitivity, content, sha256)`
  - `store`: `obsidian | wiki | rag`
  - `date_basis`: `created | updated | day | path | none`
  - content는 전체 chunk/노트이고 sha256은 그 UTF-8 바이트 해시다.
- `EvidencePack(version="knowledge-v1", query, verdict, items, layers, notes)`
  - `verdict`: `hit | no_evidence | unavailable`
  - items는 R1 우선순위, `doc_date` 내림차순(없으면 뒤), score 순이며 id가 재부여된다.
  - layers는 `rag`, `wiki`, `twin`의 `hit/no_memory/none/conflict/unavailable/skipped`
    상태를 담고 notes에는 건수와 실패 종류만 담는다.
- `collect_evidence(query, *, clock, env) -> EvidencePack`: MCP는 한 번만 호출한다.
  0단계 entity fallback flag가 켜지고 1차가 비었을 때만 엔터티 앵커 호출을 한 번 더 한다.
  재시도나 임계값 변경은 없다.
- `render_citations(pack, style="footnotes|sources|consult") -> str`: 출처를 만드는
  유일한 함수다.
- `validate_citations(text, pack) -> CitationReport`: 팩 밖 `[En]`을 제거하고 사용 및
  제거 id와 유효 인용 유무를 보고한다.

## 출처 형식

`render_citations`만 다음 형식을 만든다.

```text
[E1] Obsidian: <folder>/<relpath> (created 2026-05-02)
[E2] RAG/note: research-trends/research-trends-20260818.md (2026-08-18, path)
[E3] wiki: <slug> (principle, authority=default, updated 2026-07-30)
```

명시 날짜가 없으면 `(날짜 미상)`이다. 스킬은 이 문자열을 재조립하거나 별도
`출처:` 목록을 만들지 않는다.

## 근거 없음과 조회 불가

`no_evidence` 팩은 프롬프트에 아래 문장을 넣는다.

```text
EVIDENCE: none — write '근거 없음' for any factual claim about the owner's past/notes
```

산출물 머리는 다음 형식이다.

```text
근거 없음 — 세 저장소에서 관련 근거를 찾지 못함(rag:<상태>, wiki:<상태>)
```

모든 요청 계층이 내려가면 `unavailable`이며 `근거 수집 불가`를 표시하고 생성은 계속한다.
재시도하지 않고, 임계값을 낮추지 않고, 자체 검색으로 우회하지 않는다.

## 테스트 픽스처

공유 픽스처는 `tests/fixtures/knowledge/`에 있다. `rag_rows_*.json`은 hit, 무관한
상위 결과, 민감도, 날짜 유무를 고정한다. `wiki_vault/`는 legacy, twin, 만료,
충돌, 민감 노트를 담고 `sensitivity-rules.yaml`로 재분류한다.
`automation.knowledge.testing.FakeSources`를 `collect_evidence(..., env=fake)`로 주입한다.
scenario는 `KNOWLEDGE_FAKE_PACK=<json 파일 또는 JSON>`을 사용한다. 검색 동작 자체를
스킬별로 재현하지 않는다.

## 스킬 채택 체크리스트 (8항)

1. `skills/<s>/scripts/<s>_knowledge.py` 한 파일에 `KnowledgeQuery` 구성과 `collect()`만
   둔다. lazy import하며 ImportError는 `unavailable`로 fail-closed한다.
2. 프롬프트에 EVIDENCE 블록과 `Use only MATERIAL/EVIDENCE, cite [En], do not invent`를 둔다.
3. 생성 후 `validate_citations`를 적용하고 근거 없음/불가 문구를 결정론적으로 붙인다.
4. `render_citations` 결과와 mode 0600 `*.evidence.json` 사이드카를 개인 디렉터리에 쓴다.
5. 근거 텍스트를 기존 민감도 라우팅 입력에 합치고 센티널은 GLM에서 차단한다.
6. `--with-evidence` opt-in과 `evidence` 미리보기 명령을 둔다. JSON에는
   `evidence_count`와 `layers`만 싣고 원문은 싣지 않는다.
7. 주입 팩 hit/no_evidence/unavailable와 민감 팩 테스트, 오프라인 scenario를 둔다.
8. SKILL.md에 이 규약 링크를 넣고 conformance `KNOWLEDGE_ADOPTERS`에 등록한다.

## `_EXEMPT` 정책

`test_knowledge_adoption_conformance.py`의 `_EXEMPT`는 이름과 구체적 사유를 함께 가진다.
1단계 예외는 recall(대화 전면과 recall-v1 호환), wiki 자체 CLI, twin_distill 쓰기 측뿐이다.
예외 대상 디렉터리가 사라지거나 채택으로 경계가 바뀌면 같은 PR에서 항목을 제거한다.
새 예외는 병렬 검색 구현을 허용하는 수단이 아니며 규약 변경 근거가 있어야 한다.
