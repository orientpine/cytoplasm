# 기억 저장 라우팅 운영 규약

소유자가 "기억해 / 기억해줘 / 앞으로도 이렇게"라고 말했을 때 **무엇을 어디에 저장하는가**를
정하는 단일 규약이다. 구현은 `automation/memory_routing/`(classifier → adapters → flow)이고,
진입점은 `flow.classify_then_store` **하나뿐**이다. 분류는 요청당 정확히 한 번 수행되며,
그 판정 하나로 canonical 저장과 (선택적) 병기 저장이 순서대로 실행된다. 병렬 저장 경로를
새로 만들지 않는다.

## 저장소별 책임

| 저장소 | 무엇을 맡나 | 승인 |
|---|---|---|
| **위키 노트(canonical)** | 명시적 기억 요청의 **기본이자 유일한 정본**. 개인 RAG는 런타임 단일 문서 쓰기 API가 없고 위키 소스를 인제스트하므로, 위키에 저장하면 Recall에서 검색된다 | 기존 위키 게이트(`wiki_cli.py draft` → 소유자 ✅). **새 승인 표면을 만들지 않는다** |
| **MEMORY.md** | 짧고 안정적이며 전역적으로 유용한 사실만 **병기**(정본 아님) | 위키 정본 저장이 성공/중복일 때만 실행 |
| **skill** | 재사용 절차·템플릿·체크리스트 | 스킬 배포 4단계 게이트 |
| **tasks** | 7일 이내에 바뀌는 임시 상태. 만료 시각 필수 | — (영구 저장소 기록 금지) |

## MEMORY.md 병기 조건 (모두 만족해야 함)

1. 명시적 기억 요청일 것(`기억해`/`기억해줘`/`앞으로도 이렇게` 계열).
2. **짧을 것** — 정규화 후 120자 이하(분류), 실제 기록은 200자 이하(어댑터).
3. **안정적일 것** — `항상`·`선호`·`내 이름은` 등 시간이 지나도 유지되는 진술.
4. **전역적일 것** — 답변 언어·호칭·말투·시간대·단위처럼 대화 주제와 무관하게 쓰이는 사실.
5. 정규화 비교(불릿·공백·대소문자·끝문장부호 무시) 결과 **같은 사실이 이미 없을 것**.

위 중 하나라도 어긋나면 병기하지 않는다. 특히 **모호한 입력**(내용 없는 `기억해`, 지시대명사
만 있는 `앞으로도 이렇게`)은 보수적 기본값으로 위키 초안만 만들고 **MEMORY.md를 절대 추정해서
쓰지 않는다**. 프로젝트 지식·긴 서술은 길이와 범위 때문에 위키 단독이다.

## 절차 중복 금지

재사용 절차는 **skill에만** 저장한다. 같은 절차를 MEMORY.md에 복사하지 않는다 — 사본이 생기면
갱신이 갈라지고, 어느 쪽이 진실인지 판정할 수 없다. 절차 요청의 `co_write`는 항상 비어 있으며,
어댑터는 skill 저장 경로가 MEMORY.md를 삼키는 위치(상위/동일 디렉터리)면 저장 자체를 거부한다.
근거 설명이 필요하면 위키 노트를 **선택적으로** 따로 남긴다(의무 아님).

## 민감도 게이트

경계에서 민감 태그가 붙으면 `needs_sensitive_approval=True`가 되고, 소유자 승인이 함께 오지
않는 한 **어떤 어댑터도 호출되지 않는다** — 자식 프로세스도 뜨지 않고 평문 파일은 바이트 단위로
그대로다. 흐름은 `sensitive_rejected`를 반환하고 모든 저장소는 `not_attempted`로 보고된다.
어댑터에도 같은 가드가 중복으로 있다(fail-closed 2중 방어).

승인이 있어도 위키 게이트가 거부하면(rc=1 = 소유자 확인 부재, rc=2 = 스키마 거부) 정본이
없으므로 병기는 시도조차 하지 않는다.

## 실패·재시도

어댑터 결과는 네 가지다 — `success` / `rejected`(정책·스키마 거부, 재시도해도 같음) /
`duplicate`(이미 저장됨) / `retryable_failure`(I/O·프로세스 등 일시적 장애).

| 상황 | 흐름 결과 | 후속 |
|---|---|---|
| 정본 성공(+병기 성공) | `stored` | 없음 |
| 정본 거부 | `store_rejected`, 병기 `not_attempted` | 내용을 고쳐 재요청 |
| 정본 일시 실패 | `store_failure`, 병기 `not_attempted` | 동일 요청 재시도 |
| 정본 성공 + 병기 실패 | `partial_failure` | **정본 성공은 보존된다** — 재시도 시 정본은 `duplicate`, 병기만 실행 |
| 동일 요청 재전송 | `duplicate` | 저장 1건 유지 |

멱등 키는 정규화된 본문(`dedupe_key`)이다. 같은 요청을 다시 보내도 위키 자식 프로세스는 다시
뜨지 않고(승인 메시지 단일성 규칙) MEMORY.md에도 두 번째 줄이 생기지 않는다. 위키 중복 판정은
호출자가 넘긴 **대기 중 승인 키 목록**(`WikiTarget.pending_keys`)으로 이뤄지므로, 호출자는
승인 대기 중인 요청의 키를 보관해야 한다.

## 관련

- 구현: `automation/memory_routing/{classifier,adapters,flow}.py`
- 회귀: `tests/unit/test_memory_routing{,_adapters,_flow,_e2e}.py`, 증적 `docs/qa/RTS-3/b4-memory-e2e.txt`
- 위키 게이트: `skills/wiki/`(이 규약은 위키를 **CLI로 재사용**하며 수정하지 않는다),
  `docs/guide/개인-위키.md`, `docs/guide/decision-twin-스키마.md`
- 승인 규약: 루트 `AGENTS.md` 「Owner-confirm 이모지 컨벤션」·「승인 메시지 단일성 규칙」
