# 용어 교정 규약 — 어디서 고치고, 무엇을 보고 고치는가

이 문서가 절차·경로·환경변수의 **단독 정본**이다. AGENTS.md 「용어 교정 위치 규칙」은
불변식만 들고 있고 여기를 가리킨다.

## 한 줄

교정은 **음성→전사본** 이 아니라 **전사본→산출 문서** 단계에서 하고, 문서 종류마다
중첩된 교정 참고 문서를 쓴다. 문서에 실린 **원문 인용 구역은 고치지 않는다**.

명시적 예외는 노드별 기본 꺼짐인 [Plaud 동결 전 전문 교정 훅](../기능소개/plaud-전사-동결전-교정.md)이다.
노드 지정 명령이 lifelog 전문의 메모리 사본만 교정하고 원본 파일은 보존한다.
실패하면 원문으로 진행하며, 이 문서의 용어집 엔진·다른 원문 인용 정책은 그대로다.

## 참고 문서 쓰는 법

파일 이름은 `용어집.csv`(정본)이고, 이름을 바꾸기 전에 써 둔 `용어집.txt` 도 계속 읽는다.
Drive 가 `.csv` 를 Sheets 로 열어 주므로 소유자는 표로 편집한다.

| 행 | 뜻 |
|---|---|
| `한전기술` | **바른 용어**. 틀린 표기를 몰라도 된다 — 자모 거리로 오인식을 찾아 고친다 |
| `열기환기,열교환기` | 소유자가 직접 짝지은 치환. 문자열 그대로 바꾼다 |
| `영무=업무` | 옛 형식. 같은 뜻이고 계속 읽는다 |
| `# …` | 메모 |
| `틀린표기,올바른표기` | 머리글 — 항목이 아니다 |

**바른 용어 한 칸을 먼저 쓴다.** 실측(2026-09-05): 1:1 쌍으로 이미 교정된 9,625 어절 전사본을
같은 파일의 바른 용어 4개로 다시 훑으니 놓친 오인식이 7회 더 있었다(열기환기·열기완기→열교환기,
항정기술→한전기술). 소유자가 그 표기들을 몰랐기 때문이다.

세 음절 미만(`업무`)은 자모 거리로 고치지 않는다 — 이웃이 너무 많다. 그런 낱말은 두 칸 행으로
직접 짝지어 준다.

## 층 — 문서 종류를 따라 중첩된다

    autophagy/용어집.csv                       모든 산출물 (가장 약함)
    autophagy/<문서 종류>/용어집.csv           그 종류의 문서 (회의록·전사본·라이프로그 …)
    autophagy/<문서 종류>/<과제>/용어집.csv    그 과제의 그 문서 (가장 강함)

`DRIVE_LAYOUT=para` 노드는 같은 세 층을 형의 PARA 자리에서 읽는다: `3_Resource/용어집/용어집.csv` →
`3_Resource/용어집/<문서 종류>/용어집.csv` → `1_Project/<연도>_<과제>/용어집.csv`(과제 층은 전사본·회의록이 함께 쓴다).
옛 층은 한 릴리스 동안 먼저 읽고(더 약함) PARA 층이 이긴다. 새 낱말은 PARA 층에만 쓴다.

깊은 층이 같은 낱말을 덮어쓰고, 나머지는 바깥 층이 그대로 준다. 폴더 이름의 정본은
`automation/drive_taxonomy.CATEGORIES` 이며(`회의록`·`전사본`·`문서`·`제안서`…), Drive 산출물이
아닌 문서 종류만 `automation/term_glossary.EXTRA_FOLDERS` 가 채운다(`lifelog` → `라이프로그`).
형이 지적한 전사 교정은 유돌이 `glossary-add`(`term_glossary.add_pair`)로 라이프로그·회의록 층에 한 줄씩 쌓는다.

없는 폴더는 만들지 않는다 — 조회는 `find_folder_path` 이고 `ensure_folder_path` 가 아니다.

## 코드에서 쓰는 법

```python
from automation import term_correction, term_correction_log, term_glossary

pairs = term_glossary.glossary_for("meeting", project)      # 층 병합 (바깥 → 안쪽)
fixed, corrections = term_correction.apply(text, pairs)      # 지목 치환 → 바른 용어 근접 교정
term_correction_log.record(
    corrections, document="meeting", label=label, project=project, stage="minutes"
)
```

- 교정은 **렌더 전 해석 결과**(요약·결정·액션·논의·사람·장소)에 건다. 렌더된 문서 전체에 걸면
  원문 인용 구역까지 함께 고쳐진다.
- 원문 인용 구역은 손대지 않는다: 회의록 부록 `### C. 원문 전사본`, lifelog `## 전문`,
  메일 회신의 `-----원본 메시지-----` 아래.
- 교정은 로컬 계산이다 — 모델을 부르지 않는다.

## 환경변수와 경로

| 이름 | 뜻 | 기본값 |
|---|---|---|
| `DRIVE_PUBLISH_ENABLED=1` | Drive 층 조회 옵트인 | 미설정이면 캐시만 읽는다 |
| `TERM_GLOSSARY_FILE` | 명시 파일 하나로 대체(샌드박스·테스트) | — |
| `TERM_GLOSSARY_CACHE` | 노드 캐시 루트 | `~/.hermes/term-glossary` |
| `TERM_CORRECTION_LOG` | 교정 로그 | `~/.hermes/term-glossary/logs/corrections.jsonl` |

캐시는 종류·과제마다 파일이 따로다(`meeting.csv`, `meeting--해양고신뢰성.csv`). 캐시는 언제나
사본이지 정본이 아니다 — Drive 가 "아무것도 없다"고 답하면 캐시를 **비운다**(은퇴한 이름이
돌아오지 못하게).

## 실패 마커 (전부 fail-soft — 문서 생성을 멈추지 않는다)

| 마커 | 뜻 |
|---|---|
| `GLOSSARY-FETCH-FAIL kind=…` | Drive 가 답하지 않아 노드 캐시로 내려갔다 |
| `GLOSSARY-DRIVE-ABSENT kind=…` | Drive 에 층이 하나도 없다 — 캐시를 비웠다 |
| `GLOSSARY-CACHE-FAIL` | 캐시를 쓰지 못했다 |
| `CORRECTION-LOG-FAIL` | 교정 로그를 쓰지 못했다 |

## 로그

한 줄에 교정 하나, 필드는 `at·document·label·project·stage·kind·term·before·after` 아홉 개.
**어절만** 담는다 — 문맥을 함께 남기면 문서 본문이 로그로 새어 나간다. 고친 것이 없으면 파일을
만들지 않는다. 디렉터리 0700 / 파일 0600.

`kind` 는 `exact`(소유자가 짝지은 치환) / `fuzzy`(자모 거리로 기계가 판정)이고, `stage` 는 그
문서의 어느 경로가 고쳤는지다(`minutes`·`note` …).

## 새 스킬을 붙일 때

1. 그 문서 종류의 폴더 이름이 `drive_taxonomy.CATEGORIES` 에 있는지 본다. 없고 Drive 산출물도
   아니면 `term_glossary.EXTRA_FOLDERS` 에 한 줄 더한다.
2. 렌더 직전 해석 결과에 `term_correction.apply` 를 걸고 `term_correction_log.record` 로 남긴다.
3. `tests/unit/test_term_correction_conformance.py` 의 인벤토리에 그 스킬을 올린다. 아직 붙이지
   않을 이유가 있으면 `_EXEMPT` 에 **사유와 함께** 적는다 — 주석에 적으면 검사는 통과하고
   동작은 없는 상태가 조용히 만들어진다.
