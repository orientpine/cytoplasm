# 프로젝트 대시보드 (v2) — 설계·설정·운영

v1(기관 메일 수집·원본 보관·중복/실패 이력)은 메일 스킬의 mailon 동기화와 첨부 아카이브가 이미 한다.
이 문서는 그 위에 얹은 v2 — 분석 → 담당자 검토·확정 → 승인된 프로젝트 데이터 → 웹 대시보드 → 실행 기록 — 의
규약을 단독으로 소유한다. 사용 시나리오는 [소개](../기능소개/프로젝트-대시보드-v2.md).

## 1. 상자 → 모듈 (`automation/project_board/`)

| 단계 | 모듈 | 불변식 |
|---|---|---|
| 입력(v1 결과) | `sources.py` | MailOn `state.db`·저장 markdown·첨부 파일을 **읽기만** 한다. 경로 해석은 메일 래퍼와 같다(`MAIL_WRAPPER_REPO`·`MAIL_WRAPPER_DB`, 기본 `~/.hermes/mailon-runtime/current`). 회의록은 `meeting_minutes.finalized_view` 로 부록 위만 읽는다(「산출물 출처 규칙」) |
| 분석 | `llm.py`·`analysis.py`·`mail_watermark.py`·`prompts/project-analysis-v1.md` | 제공자 인터페이스 하나. 기본 `hermes` = `automation.codex_llm`(계정 주 모델·폴백, 코드에 모델 이름 없음). `openai-compatible` 은 설정으로만 고른다. 답은 엄격 파싱 — JSON 아니면·날짜 아니면 실패(추측 금지), `relevant:false` 면 제안 없음. `mail_watermark` 는 수신 시각 기준 분석 경계를 저장한다 |
| 검토·확정 | `proposals.py`·`proposal_gate.py`·`proposal_render.py`·`cli revise` | 제안 하나 = 카드 하나. `action_hash` = 정규화 제안 JSON 의 sha256. 수정은 같은 key 의 새 판 → 공용 lifecycle 이 미결 옛 카드를 지우고 같은 스레드에 새 카드. ✅/⛔ 된 제안은 고치지 않는다 |
| 승인된 항목만 반영 | `proposal_watch.py`·cron `project-board-watch`(2분) | 소유자(봇 아님) 리액션만, ⛔ 우선. 반영 직전 동결 파일을 다시 해시해 레코드와 대조 |
| 승인 데이터 | `board_store.py`(SQLite `~/.hermes/project-board/board.db`, 0600) | 제안 id 로 멱등. 진행 기록은 상태·진척만 바꾸고 할 일을 만들지 않는다 |
| 대시보드 | `dashboard.py`·`server.py`·사용자 유닛 `autophagy-project-board` | 자체 완결 HTML(외부 폰트·CDN 없음). 서버는 루프백 전용(비루프백 bind 거부)·토큰 필수·체크 POST 는 토큰 2중+같은 Origin |
| 실행 → 기록 | `cli progress`·대시보드 체크 | 기록마다 이벤트 원장 한 줄, 대시보드 파일 재생성 |
| 외부 메일 | `cli digest --request-mail` | 메일 스킬 `compose --attachment` 의 **표준 메일 승인 카드**로만 나간다. 이 패키지는 메일을 보내지 않는다 |

## 2. 설정 (`~/.hermes/project-board/config.json`, 없어도 됨)

```json
{
  "llm": {"provider": "hermes"},
  "analyze": {"enabled": false, "max_per_tick": 5},
  "dashboard": {"port": 8810},
  "digest": {"to": ["<수신 주소>"], "subject": "프로젝트 현황 일일 요약"}
}
```

- 로컬 LLM 으로 바꾸기: `"llm": {"provider": "openai-compatible", "base_url": "http://127.0.0.1:8000/v1",
  "model": "<서버의 모델 id>", "api_key_env": "<키가 필요하면 환경변수 이름>"}`. 모델 id·주소는 이 파일에만 둔다.
  확인: `python3 -m automation.project_board status` 의 `MODEL` 줄.
- 확정 회의록: `analyze.enabled` 가 켜져 있고 `DRIVE_PUBLISH_ENABLED=1` 이면 같은 틱이 Drive 산출물 트리의
  `회의록/<과제>/<연도>/*.md` 도 읽는다(읽기 전용 — 폴더를 만들지 않는다). 첫 틱은 지금 있는 회의록을 "본 것" 으로만
  적고(`minutes-state.json`), 그 뒤 새로 생긴 회의록만 틱당 `max_per_tick` 개까지 분석한다. 분석과 근거 보기에는
  회의록의 **결론부만** 쓴다(`meeting_minutes.finalized_view` — 부록의 원문 전사본은 빠진다). 결론부는
  `<보드 루트>/minutes/gd-<파일 id>.md`(0600)에 남아 근거 링크 `/source/meeting/gd-<id>` 가 Drive 를 다시 부르지 않는다.
  같은 회의 시리즈(제목에서 날짜·「회의록」·차수를 뺀 것)는 한 업무라 결정 전에는 카드가 하나만 서고 등급도 함께 간다.
  메일과 겹치는 일은 "이미 있는 할 일" 목록으로 걸러진다. 끄려면 `"analyze": {"minutes": false}`.
- `analyze.enabled` 기본 false — 릴리스만으로는 카드가 올라가지 않는다. 켜면 첫 틱은 워터마크를 "지금"으로
  잡기만 하고(과거 메일함 전체를 제안하지 않는다) 그 뒤 새 메일만 본다. 틱당 상한 `max_per_tick`.
  메일 기준은 저장 시각 `saved_at` 이 아니라 **수신 시각 `recv_date`** 다. 재동기화가 옛 메일을 다시 저장해도
  새 메일로 보지 않는다. ISO 시각은 UTC로 정규화하고, 시간대 없는 MailOn 시각은 수집기와 같은 런타임의
  로컬 시간대로 해석한다(수집기·분석기는 같은 시간대 설정을 유지해야 한다).
  `analyze-state.json` 의 `mail_received_at` 과 그 시각에서 처리한 UID 목록 `mail_received_uids` 를 원자적으로
  기록한다. 같은 시각의 메일이 틱 상한으로 나뉘거나 더 작은 UID로 늦게 들어와도 빠뜨리거나 중복 분석하지 않는다.
  기존 `mail_saved_at` 만 있는 상태는 **이관 틱의 현재 수신 시각부터 다시 시작**하며 그 틱에는 분석하지 않는다.
  과거 재저장 기록으로부터 수신 경계를 복원할 수 없으므로 밀린 메일은 따라잡지 않는다(첫 활성화와 같은 정책).
  수신 시각이 없거나 해석할 수 없으면 저장 시각으로 대신하지 않고 건너뛰며, 경고에는 해당 건수만 남긴다.
  모델의 일시 오류는 해당 메일 앞에서 멈추고 워터마크를 전진시키지 않아 다음 틱에 재시도한다.
- 상태 경로 덮어쓰기: `PROJECT_BOARD_ROOT`, `PROJECT_BOARD_CONFIG`, 회의록 폴더 `PROJECT_BOARD_MEETING_DIR`.
- 도리 지시를 받는 도리 이름: `"orders": {"receiver": "<도리 이름>"}`(40자 이내, 없으면 「관리 도리」). 지시 칸 안내 문구와
  각 지시의 「받는 도리」에 쓰인다. 실제로 누구에게 넘기는지는 노드 밖 전달 유닛이 정한다(아래 「도리에게 지시」).
- 과제 목록(카탈로그): `"projects": [{"name": "<과제 이름>", "aliases": ["<별칭>", …], "note": "<한 줄 설명>", "grade": "<기본 보안 등급>"}]`
  (`grade` 는 선택, 없으면 `과제내부` — 아래 「업무 보안 등급」).
  분석은 이 목록에서 **글자 그대로** 하나를 고르고, 맞는 것이 없으면 `미분류` 로 답한다(새 이름을 짓지 않는다).
  실제 과제 이름은 노드 설정 파일에만 둔다 — 코드·저장소에 적지 않는다(「개인화 코드 금지 규칙」).
- 프롬프트 판본: `"analyze": {"prompt": "v3"}`(기본). v2 는 광고·자동 알림·전 직원 일반 공지를 사유와 함께 거르고,
  받는 사람에게 요구된 행동만 할 일로 뽑으며, 대시보드에 이미 열린 할 일과 같은 일은 빼고, 상대 날짜도 계산한다.
  v3 는 v2 에 업무 보안 등급 **제안**을 더한다. `v1`·`v2` 는 비교용으로 남는다.

## 3. 명령

```bash
python3 -m automation.project_board analyze --mail <uid>        # 또는 --meeting <회의록.md>; 카드 게시 + APPROVAL-THREAD 줄
python3 -m automation.project_board revise <제안> --set-due 1=2026-10-24 --set-owner 2=담당자 --drop 3 --add '제목|담당|2026-11-01'
python3 -m automation.project_board proposals                  # 제안과 상태
python3 -m automation.project_board revise <제안> --grade 대외비         # 등급 바꾼 수정 카드(올리기·낮추기 모두 카드로)
python3 -m automation.project_board grade <todo_id> 기관지정            # 승인된 업무의 등급 올리기만(그 업무 할 일 전부)
python3 -m automation.project_board progress <todo_id> --status 완료|진행|보류|열림 [--progress N] [--note 메모]
python3 -m automation.project_board orders [--status 받음|넘김|'처리 중'|끝] [--undelivered] [--json]   # 도리 지시 목록(오래된 것 먼저)
python3 -m automation.project_board order-update <번호> --by <쓰는 도리> [--status …] [--dori <맡은 도리>] [--post-url https://…] [--note 메모]
python3 -m automation.project_board order-delivered <번호> --to <받은 도리>   # 전달 유닛이 넘긴 뒤 한 번만 기록
python3 -m automation.project_board build                      # 대시보드 파일 다시 만들기
python3 -m automation.project_board serve                      # 127.0.0.1:<port> (유닛이 상시 실행)
python3 -m automation.project_board digest [--request-mail]    # 날짜별 스냅샷, 메일은 승인 카드로만
python3 -m automation.project_board dryrun --days 28 --limit 120 --out <체크아웃 밖 경로>.jsonl [--prompt v1|v2|v3]
python3 -m automation.project_board dryrun --minutes 8 --out <체크아웃 밖 경로>.jsonl   # 최근 확정 회의록 8개(읽기 전용)
```

## 데모 보드

```bash
python3 -m automation.project_board demo
python3 -m automation.project_board demo --port 8811 --root /tmp/project-board-demo
```

첫 줄의 `DEMO http://127.0.0.1:<port>/?t=<token>` 주소를 브라우저로 열면 가상의 프로젝트 4개,
지연·이번 주 마감·완료 할 일, 보관한 프로젝트 1개와 검토 대기 제안을 볼 수 있다.
근거 메일도 가상 내용이다. 실제 보드·메일·설정·승인 카드는 건드리지 않고 외부 서비스를 호출하지 않는다.
기본 포트는 빈 포트 자동 배정이며 접속은 루프백과 매번 새 토큰으로 제한한다.
Ctrl-C로 끝내면 서버를 닫고 자동 생성한 임시 폴더만 지운다.
`--root`로 지정한 폴더는 남기며, 실제 보드 경로와 그 하위 경로, 이미 `board.db`가 있거나 비어 있지 않은 폴더는 종료 코드 2로 거부한다.
데모의 한 할 일(`demo-1-5`)은 실제 메일만큼 긴 제목·담당·장소·근거 제목을 가진다. 아래 화면 감사가 긴 값을 재현하는 자리다.

## 화면 감사 (`layout_audit.mjs`)

```bash
PLAYWRIGHT_DIR=<node_modules/playwright 가 있는 폴더> node automation/project_board/layout_audit.mjs \
  [--engines webkit,chromium] [--shots <폴더>] [--out <결과.json>] [--url <대시보드 주소>]
```

`--url`이 없으면 데모를 스스로 띄우고 끝에 닫는다. 모든 탭, `#archive`, 화면에 링크된 `#todo/`·`#person/`·`#project/`·원문 화면을
폰(390x844, 주소창이 펼쳐진 390x664)과 데스크톱(1440), 밝은·어두운 모드로 열어 찾는다: 서로 다른 요소의 글자 줄·배지·버튼이
같은 자리를 차지함(겹침), 넘침으로 잘린 글자(「…」 말줄임 포함), 화면 밖 글자, 줄 맨 앞에 떨어진 구분점 「·」, 가로 스크롤, 11px 미만 글씨, 끝까지 내렸을 때
아래 탭에 가린 내용, 이웃한 카드(카드·지표 타일·안내 상자, 위아래나 옆) 사이가 간격 토큰 `--gap-card`와 다름(`gap` — 2026-10-22
소유자 "균일한 간격을 가져야지", 요약의 세션 카드와 「도리에게 지시」 상자가 0px로 붙었다. 토큰의 2.5배를 넘는 간격은 사이에 제목이
있는 것이라 세지 않는다), 목록 묶음이 공통 접기가 아님(`fold` — 2026-10-22 소유자 "접는 기능이 있으면 모든 리스팅에 적용해야지":
`details` 는 「기록 N건 더 보기」(`details.more`)만 빼고 모두 `details.fold[data-fold] > summary.fold-head` 에 제목·개수가 하나씩,
제목과 `ul > li` 목록을 가진 카드·안내 상자는 접기 밖에 있으면 안 된다. 근거를 적은 예외는 `data-nofold`). 찾은 것마다 `FINDING` 한 줄, 없으면 종료 코드 0, 있으면 1, 실행할 수 없으면 2(`LAYOUT-AUDIT-UNAVAILABLE`).
입력칸 안 아이콘처럼 글자가 없는 아이콘과 상자의 겹침은 설계라 세지 않는다. 사파리 엔진(WebKit)을 꼭 함께 돌린다:
2026-10-21 할 일 화면의 보안 등급·근거 겹침은 WebKit에서만 생겼다. `--url`로 실 대시보드를 재면 읽기만 하고,
캡처는 형 데이터이므로 비공개 자리에만 둔다. 로컬 CI에는 브라우저가 없어 돌지 않고, 화면을 바꾼 PR이 직접 돌려 결과를 싣는다.

## 테일넷에서 열기 (tailnet 전용, 공개 아님)

서버는 노드의 루프백(`127.0.0.1:<port>`)에만 붙는다. 소유자 기기에서 https 로 열려면 **테일스케일 운영자 권한이 있는
호스트**(게이트웨이)에서 `tailscale serve` 를 쓰고, 그 호스트가 SSH 포워드로 노드 루프백에 닿게 한다. Funnel(공개)은 쓰지 않는다.

1. 노드 설정 `~/.hermes/project-board/config.json` 에 게이트웨이 주소와 허용 로그인을 적는다(값은 설치별, 저장소에 적지 않는다):
   ```json
   {"dashboard": {"tailnet": {"origins": ["https://<게이트웨이>.<tailnet>.ts.net:<port>"], "logins": ["<소유자 로그인>"], "token": false}}}
   ```
   서버는 1시간마다 다시 뜨므로(`RuntimeMaxSec`) 그 안에 반영된다. 즉시 반영하려면 `systemctl --user restart autophagy-project-board`.
2. 게이트웨이에서 노드 루프백으로 가는 상시 포워드(사용자 유닛, `Restart=always`, 사용자 linger 켜기):
   `ssh -N -o ExitOnForwardFailure=yes -o ServerAliveInterval=30 -L 127.0.0.1:<로컬포트>:127.0.0.1:<port> <노드>`
3. 게이트웨이에서 `tailscale serve --bg --https=<port> http://127.0.0.1:<로컬포트>` — `tailscale serve status` 에 `(tailnet only)` 로 보여야 한다. serve 설정은 tailscaled 가 저장해 재부팅 뒤에도 유지된다.
4. 소유자 기기(테일스케일에 소유자 계정으로 로그인)의 브라우저에서 `https://<게이트웨이>.<tailnet>.ts.net:<port>/` 를 연다. 토큰은 묻지 않는다.

규칙: 테일넷 이름으로 들어온 요청이나 `Tailscale-User-Login` 헤더가 붙은 요청은 그 로그인이 `logins` 에 있어야 한다(아니면 403,
로그인이 없어도 403). 그 로그인이 맞으면 **토큰 없이** 열린다 — 소유자 결정(2026-10-14): "토큰 빼기 — 테일스케일 + 형 계정만으로".
남는 위험: `tailscale serve` 는 그 헤더를 호출자의 실제 신원으로 덮어쓰지만, 노드·게이트웨이의 다른 로컬 프로세스는 루프백에
헤더를 위조해 보낼 수 있다(소유자가 받아들인 위험). 다시 막으려면 `"token": true` — 그때는 테일넷에서도 처음 한 번 `?t=<토큰>`
(노드 `~/.hermes/project-board/serve.token`)이 필요하다. 토큰 없이 들어온 TODO 체크(POST)는 테일넷 `Origin` 이
**반드시** 붙어 있어야 한다 — 설정된 출처이거나, 브라우저가 연 그 주소 자신(`https://` + 요청의 `Host`) — 소유자 브라우저에
열린 다른 사이트가 serve 를 거쳐 체크하지 못하게. 자기 주소를 받아 주므로 대시보드가 다른 테일넷 호스트로 옮겨 `origins` 가
옛 주소로 남아도 저장은 막히지 않는다(2026-10-21 호스트 이동 뒤 모든 체크가 403 이던 문제). 열어 둔 화면은 저장이 401·403 이면
한 번 스스로 화면을 다시 받아 새 값으로 한 번 더 보내고, 그래도 안 될 때만 「권한이 없어 저장하지 못했습니다」를 보인다.
서버 재시작은 같은 `serve.token` 을 다시 읽으므로 열어 둔 화면의 저장에 영향이 없다. 테일넷 설정이 없으면 신원 헤더가
붙은 요청은 모두 거부되고, 테일넷이 아닌 루프백 접속(SSH 포워드 등)은 예전처럼 토큰이 필요하다.

보드 DB 는 스키마 판본(`PRAGMA user_version`)을 갖는다. 코드보다 새 판본이면 쓰기 전에 멈추고("run the released code"),
실제 보드(`~/.hermes/project-board/board.db`)의 스키마는 릴리스 런타임(`/srv/autophagy-agent-releases/…`)에서 돈 코드만 바꾼다 —
릴리스 전 코드로 노드에서 시험할 때는 **반드시** `PROJECT_BOARD_ROOT` 를 샌드박스로 둔다(2026-10-14 사고: 드라이런이 실제 보드를
이관해 배포된 코드의 반영 틱이 실패했다). 과제 목록을 읽는 `dryrun`·`status` 는 보드를 읽기 전용으로만 연다.

`dryrun` 은 운영 전 분류 점검용이다 — 최근 받은 메일을 그대로 분석해 결과를 비공개 JSONL(0600) 한 파일에만 쓰고,
제안·카드·프로젝트 데이터·대시보드는 하나도 만들지 않으며 메일함은 읽기만 한다. git 체크아웃 안 경로는 거부한다.

MailOn 런타임의 `data/` 는 배포본에서 공유 상태 디렉터리(`mailon-runtime/state/data`)로 가는 링크다. 원문·첨부
경로는 런타임 루트 또는 그 `data/` 실경로 안일 때만 읽고, 그 밖으로 풀리는 경로는 거부한다.

종료 코드: 0 완료, 2 입력 오류, 3 카드 게시 거부, 4 모델·원천 일시 불가(재시도).

## 업무 보안 등급

등급은 `공개 < 과제내부 < 대외비 < 기관지정` 네 단계이고 단위는 과제가 아니라 **업무**다. 업무 키는 카드가 이미 쓰는
대화 키다 — 메일은 제목에서 Re/Fw 를 뗀 스레드, 회의록은 원본 id. 업무의 등급은 `board.db` 의 `tasks` 표에 한 줄로만
있고 할 일은 그 줄을 읽으므로, 등급을 바꾸면 그 업무의 할 일 전부가 같이 바뀐다(최근 기록에 「보안 등급 변경」).

- 정하는 순서: 이미 승인된 업무면 그 등급을 그대로 쓴다. 처음 보는 업무면 분석의 제안과 과제 기본값(`projects[].grade`,
  없으면 과제내부) 중 **더 엄격한** 쪽이다 — 분석은 기본값보다 느슨하게 만들지 못한다.
- 확정: 카드(판본 `project-proposal-v2`)에 「보안 등급: … — 이 업무의 할 일·이후 카드 전부에 같은 등급」 줄이 실리고 소유자의
  ✅ 가 확정이다. 바꾸려면 `revise --grade` 로 수정 카드를 올린다. `grade` 명령은 승인된 업무를 **올리기만** 한다.
  이미 게시된 `project-proposal-v1` 카드는 그대로이고, 등급 없는 옛 제안은 직렬화가 같아 승인 해시도 그대로다.
- 내보내기: 대시보드는 소유자 화면이라 배지로 보인다. 밖으로 나가는 사본(일일 요약 메일 첨부 `digest`, 이후의 외부 연동)은
  `snapshot(exported=True)` 하나만 쓰며, 대외비·기관지정 할 일·근거·기록·대기 제안과 그것만 가진 과제 이름까지 빼고
  "N건은 이 사본에서 뺐습니다" 만 남긴다. `tests/unit/test_project_board_grade.py` 가 이것을 막는다.
- 내용으로 경로를 고르거나 막지 않는다(2026-10-09 민감 판정 제거 그대로) — 등급은 소유자가 확정한 표지일 뿐 모델 경로를
  바꾸지 않는다.

## 4. 화면

위 메뉴는 **탭**이다 — 누르면 그 화면 하나만 보이고 나머지는 숨는다. 주소 `#summary`·`#projects`·`#todos`·`#schedule`·
`#sources`·`#sessions` 가 탭을 기억해(보관함 `#archive` 는 2026-10-21 소유자 Q347 로 탭에서 빠져 프로젝트 탭 맨 아래
「보관함 N」 줄로 들어가는 화면이 되었다 — 옛 주소도 그 화면을 연다) 새로고침·뒤로 가기가 그대로 동작하고, 첫 화면은 요약이다. 메일 첨부용 파일도 같은 탭이며
스크립트가 꺼진 메일 뷰어에서는 모든 화면이 위아래로 펼쳐진다(외부 의존 없음). 빈 화면은 "아직 비어 있습니다. 새 메일과
회의록을 분석한 제안이 승인되면 이곳에 할 일과 일정이 채워집니다." 로 채운다. 보드가 통째로 비어 있으면(할 일도
승인 대기도 없음) 요약 맨 위에 **첫 사용 안내**가 나온다 — 메일·회의록을 읽고, 승인 카드로 확인하고, 여기서 진행을
챙긴다는 세 단계와 데모 명령(`python3 -m automation.project_board demo`).

요약(「오늘의 현황」: 지연·이번 주 마감·진행 중·승인 대기 타일 — 승인 대기가 0이면 그 자리는 「최근 7일 새 할 일」, 마감이 없는 할 일이
있으면 「마감이 정해지지 않은 할 일 N건」 줄, 프로젝트 카드 대신 「프로젝트 N개 보기」 한 줄(소유자 Q346), 승인 대기 제안은 데이터와 분리 표시, 최근 기록) · 프로젝트 카드(진척 막대와 퍼센트,
완료/전체, 지연 건수, 다음 마감 날짜와 D-day) · 할 일(프로젝트별 체크리스트, 프로젝트·검색·상태 필터) · 일정(지연/이번 주/다음 주/이후/미정) ·
근거(메일 제목·보낸 사람·요약·첨부, 만든 할 일) · 최근 기록(「「할 일」 완료로 바꿈」처럼 문장, 「2일 전」 같은 상대 시각). 할 일·근거·대기 제안에 업무 보안 등급 배지가 붙는다
(대외비·기관지정은 「외부 비공개」). 데스크톱과 390px 폭에서 가로 스크롤 없이 읽힌다.

**모양**(2026-10-16 소유자 지시 "판매용으로"). 색·간격·글자 크기·모서리는 `dashboard_theme.py` 의 토큰 한 벌에서만 나오고
(카드와 카드 사이는 어느 탭에서나 `--gap-card` 하나, 16px — 타일·프로젝트 카드 격자, 한 줄 카드, 안내 상자, 접기 묶음, 근거 카드,
도리 지시 상자까지)
어두운 모드는 같은 토큰을 덮어쓰는 한 블록이다 — 기기 설정(`prefers-color-scheme`)을 따른다. 머리에는 브랜드 자리(그림 아이콘과
제품 이름, 기본 「팔란티르」 — 2026-10-31 소유자 Q402 "팔란티르로 하자")가 있고, 휴대폰 폭(640px 이하)에서는 탭이 화면 아래 고정 탭 막대(아이콘+이름,
높이 52px, 탭 일곱 개)가 된다. 누르는 것은 모두 44px 이상이고, 글자 대비는 밝은·어두운 모드 모두 4.5:1 이상이다(실제 브라우저로 잰 값).
상태는 색만으로 말하지 않는다 — 배지에는 글자가, 지표 타일에는 아이콘과 이름이 있다. 제품 이름은 설정
`{"dashboard": {"brand": "<이름>"}}`(한 줄, 40자 이하)로 바꾼다 — 머리·탭 제목·폰 홈 화면 이름과 파일 사본·오류 화면이 같이 바뀐다.
**아이콘**(2026-10-31 소유자 지시 "페이지 아이콘 만들어줘", Q402 "팔란티르 느낌나는 아이콘", "반지의 제왕에서 나올법한 테마로")은
이름과 상관없는 그림 하나다 — 별이 몇 개 뜬 밤하늘 돌 바탕 위, 룬 무늬를 새긴 낡은 청동 받침이 검은 유리 구슬을 받치고 그 안에서 주황 불꽃이
소용돌이친다(`dashboard_theme.icon_svg`, 직접 그린 그림). 머리의 이름은 시스템 세리프 글꼴(`.brand-name`: Noto Serif KR·
AppleMyungjo·나눔명조·바탕 순, 외부 글꼴 없음)로 쓴다.
같은 그림이 탭 아이콘(SVG), 머리의 이름 옆, 폰 「홈 화면에 추가」 아이콘(`apple-touch-icon`, 180px 불투명 256색 PNG — 폰이 모서리를
직접 둥글린다, `dashboard_icon_png.py`)으로 쓰이고, 홈 화면 이름은 `apple-mobile-web-app-title` 과 웹 앱 manifest 의
`name`·`short_name` 이 제품 이름을 그대로 싣는다. 모두 data URI 라 페이지가 따로 받아 오는 것이 없고 파일 사본에도 주소 글자가
없다 — 서버의 CSP 는 이 manifest 만 들이도록 `manifest-src data:` 를 둔다(그 밖은 그대로 `default-src 'none'`). 그림을 바꾸면
`icon_svg(full_bleed=True)`를 180×180 으로 다시 그려 256색 PNG 상수를 바꾼다.
**실패는 그 자리에서** 알린다: 체크를 저장하지 못하면 체크가 되돌아가고 그 줄 아래에 이유(연결 끊김·권한 없음·
서버 오류)가 나오며 화면 읽기 도구에도 읽힌다(alert 창 없음). 「보관」은 제목·설명·「취소」·「보관하기」가 있는 확인
대화상자로 묻고(Esc·취소로 닫힘, 열리면 제목에 초점 — 화면 읽기 도구가 질문부터 읽는다), 「보관 해제」는 되돌릴 수 있는 일이라 묻지 않는다. 브라우저로 연
화면의 거절은 평문이 아니라 같은 모양의 안내 화면이다 — 접속 키 없이 열면 401 「로그인이 필요합니다」, 허용 밖
테일넷 계정은 403, 없는 화면·원문·첨부는 404 안내와 「대시보드로 돌아가기」. 상태 코드는 그대로고, 체크·보관 POST 의 거절은
예전처럼 짧은 평문이다(스크립트는 상태 코드만 읽는다). 근거 원문 화면도 같은 모양·어두운 모드이고 「근거 목록」으로
돌아간다. 보관한 프로젝트의 승인 대기 제안도 요약에 나오지 않는다. 아이콘은 Lucide(ISC) 선 아이콘을
한 번만 정의(스프라이트)해 외부 요청이 없다. 시각은 「10월 16일 14:04」처럼 보인다.
글자는 데스크톱 본문 15px·보조 14px·배지 13px, 휴대폰 본문 17px·보조와 배지 15px이다. 업무 보안 등급 배지는 상태색을 쓰지 않는
중립 테두리 배지이고 대외비·기관지정에는 자물쇠 아이콘이 붙는다 — 빨강은 지연, 초록은 완료만 뜻한다. 할 일 줄의 마감은 D-day 와
날짜가 한 묶음이고, 지표 타일은 그 묶음으로 바로 간다 — 지연은 일정의 지연 묶음(`#sched-late`), 이번 주 마감은 이번 주 묶음
(`#sched-week`), 진행 중은 상태가 진행인 할 일만(`#todos?s=진행`, 그냥 할 일 탭으로 오면 필터가 풀린다), 승인 대기는 대기 목록, 최근 7일 새 할
일은 최근 기록(`#events`). 상태 필터는 상태마다 건수를 보이고 할 일이 없는 「보류」는 뺀다. 최근 기록은 8건을 보이고 나머지(최대 30건)는
「기록 N건 더 보기」로 접힌다. 한국어 줄바꿈은 낱말 단위(`word-break:keep-all`)에 더해 「할 일」·날짜·짧은 「제목」·「보관 해제」로
같은 묶음이 줄을 넘어 갈리지 않게 붙어 있고, 목록 구분점 「·」은 줄 첫머리에 오지 않는다. 브라우저가 받으면 HTML 을 gzip 으로
보낸다(지어낸 데모 보드 92.5KB → 전송 15KB).

**누르면 그 정보로 — 대상마다 화면 하나**(2026-10-21 소유자 지시 "일정 항목에서 개별 요소 클릭해도 해당 정보로 안넘어가져",
"이런 연결성이 ssot 개념으로 잘 되있으면 좋겠어"). 할 일 하나는 `#todo/<id>` 화면 하나, 담당자 한 사람은 `#person/<이름>` 화면
하나, 프로젝트는 `#project/<이름>`, 메일·회의록은 원문 화면(`/source/<종류>/<id>`) 하나다. 일정 줄·할 일 줄·근거 카드의 「만든
할 일」·최근 기록·승인 대기·사람 화면 어디서 눌러도 같은 화면이 열리고, 화면마다 내용을 따로 그리지 않는다(`todo_href`·
`person_href`·`project_href` 가 주소를 정한다). 할 일 화면에는 상태(열림·진행·완료를 한 번에 바꾸는 버튼), 마감(누르면 그
프로젝트의 일정), 담당(그 사람 화면), 프로젝트, 보안 등급, 근거 메일과 보낸 곳·날짜·요약, 같은 메일에서 나온 다른 할 일, 기록이
있다. 승인된 제안이 시각·장소·마감 근거를 말했으면 마감 옆에 시각, 「장소」·「마감 근거」 줄이 붙고, 「캘린더에서 그날 보기」가 형 캘린더의 그날을 새 창으로 연다(분석 프롬프트 v4 가 `time`·`place` 를 뽑는다, 그 전 제안은 없는 줄은 비운다). 사람 화면은 그 사람이 맡은 할 일을 마감 순으로 보인다. 원문 화면은 그 근거의 프로젝트와 만든 할 일로 이어지고, 대시보드에서
열었으면 돌아가기가 연 화면(이름이 붙는다)으로 돌아간다. 상세 화면의 돌아가기도 연 화면 이름을 달고 그 자리로 돌아가며, 주소로
바로 열었으면 목록으로 간다. 할 일 줄의 D-day 는 그 프로젝트 일정으로 간다. 옛 `#todo-<id>` 주소는 할 일 목록의 그 줄을 강조한다
(필터·접힘을 풀어 준다). 브라우저 뒤로·앞으로 가기와 화면의 돌아가기 링크는 그 화면을 떠날 때의 스크롤 자리로 돌아간다 — 원문(근거 메일)을 열었다 돌아와도,
새로고침해도 같다(폰 사파리 포함, 2026-10-23 소유자 Q360 뒤 재점검). 자리는 탭(브라우저 세션) 안에서만 `sessionStorage` 의 `pb-seen` 에
화면별로 남고, 하단 탭을 누르면 그 탭을 떠난 자리로, 이미 연 탭을 다시 누르면 맨 위로 간다. 프로젝트 화면의 돌아가기도 할 일 화면처럼
연 화면(예: 일정)의 이름을 달고 그 자리로 돌아간다. 할 일 탭의 프로젝트 묶음은 머리 어디를 눌러도 접히고, 프로젝트 화면으로는 머리 끝의
「프로젝트」 버튼으로 간다(폰 폭에서는 꺾쇠만 남은 44px 버튼). 묶음 머리의 개수 배지는 제목 마지막 줄 바로 뒤에 붙는다. 메일 첨부용 파일에도 할 일·사람
화면은 있지만 원문 링크와 상태 버튼은 없다. 세션 탭은 맨 위 「먼저 볼 것」(멈춘·대기 레인, 마지막 실행이 실패한 예약 작업)이 그 묶음을 펼쳐 열고, 세 요약 카드(작업 레인·에이전트 세션·감시·서비스)가 각 갈래로 간다. 레인 하나하나는 세션 집계가 주소·id 를 싣지 않으므로(개인정보 원칙) 더 이어지지 않는다.

**세션 탭**(2026-10-16 소유자 지시 "같은 주소로 하고 탭만 새로 열고"). 마지막 탭 「세션」(`#sessions`)은 작업 컴퓨터 한 대에서
지난 7일 동안 돈 세션 — 작업 레인, 코딩 에이전트 세션, 상주 작업 창, 감시·웹·예약 서비스 — 을 조직도 모양으로 보여 준다.
휴대폰을 먼저 생각해 만들었다: 맨 위 「지난 7일 모든 세션 N개」 허브에서 세 갈래(작업 레인·에이전트 세션·감시·서비스) 카드가
왼쪽 줄기로 이어지고(640px 넘으면 위에서 아래로 갈라진다), 하루별 막대는 「9일 금 · 막대 · 3건」 한 줄씩이라 390px 에서도 글자가
줄지 않으며, 갈래마다 분야·플랫폼·서비스 묶음이 다른 목록과 같은 접기 카드(아이콘이 있는 머리 56px)로 시작하고 머리에 건수와 상태 글자가 이미 있다.
상태는 다른 탭과 같은 배지(완료 초록·진행 파랑·미완 빨강·확인 대기 테두리)이고, 레인에는 둘이 더 있다(2026-10-16 소유자
지적 「왜 멈춤으로 되어 있어?」). 사람이나 정해진 시각을 기다리며 쉬어 둔 레인(dori `paused`)은 **대기** — 시계 아이콘의 중립색
배지이고 문제가 아니다 — 이며, 그 레인이 든 카드 안에 한 줄씩 「대기 아침 다이제스트 화면 확인 · 10월 16일 18:56부터 대기,
10월 17일 08:00 예정」처럼 무엇을·언제부터·언제까지 기다리는지가 붙는다. 「부터」는 그 사유를 적고 쉬어 둔 시각이다(사유가
오래돼 지금과 다를 수 있어서다). 카드의 기간 줄은 상태 말 없이 시각만 말한다 — 열린 묶음은 「10월 11일 12:20 시작」, 다 끝난 묶음은
「…부터 …까지」. 묶음 시작 시각에 「대기 중」을 붙이면 그때부터 기다린 것처럼 읽힌다.
작업 창이 오류·입력 대기·질문으로 멈췄거나 꺼진 레인만 **막힘**(빨강)이고 「막힘 작업 창이 오류로 멈췄습니다」 한 줄이 붙는다.
묶음 머리와 개요의 건수도 「대기 N」·「막힘 N」으로 따로 센다. 서비스의 「멈춤」(유닛이 내려간 감시)은 그대로다.
예약 작업은 **마지막 실행 결과**로 말한다(2026-10-17 소유자 질문 「실패 있음 실패 5회 … 이것도 확인해」): 마지막 실행이 정상이면
「정상」(초록), 실패로 끝났으면 「실패」(빨강)이고, 그 주의 지나간 실패는 숨기지 않고 「7일간 2,082번 중 실패 5번, 마지막 실패
10월 17일 04:25」 한 줄로 남는다. 마지막 결과를 보내지 않는 예전 수집기의 집계는 예전처럼 「실패 있음」이다. 위에 「10월 16일 18:28 기준, 4분 전에 받은
집계입니다」가 있고 45분 넘게 새 집계가 오지 않으면 그 이유를 짐작할 수 있는 안내가 붙는다. 요약 화면 타일 아래에는 「작업 컴퓨터
세션 · 지난 7일 N개, 지금 진행 중 N개」 줄이 세션 탭으로 간다(집계가 있을 때만).

데이터는 노드가 아니라 작업 컴퓨터에 있으므로 **작업 컴퓨터가 보낸다**: 그 컴퓨터의 사용자 타이머가 10분마다
`automation/project_board/session_feed/feed.sh` 를 돌려 `collect.mjs` 로 메타데이터만 모으고(레인 키·제목·대화·경로는 넣지 않는다,
[세션-현황판.md](세션-현황판.md) 2·3장) 배포와 같은 SSH·`sudo -u <agent>` 경로와 `deploy_push.sh` 의 `push_file`(임시 파일 → 해시
확인 → 이름 바꾸기)로 보드 루트의 `sessions.json`(0600)에 쓴다. 노드는 포트를 새로 열지 않고, 대시보드는 요청마다 그 파일을
읽는다(`sessions.load_sessions` — 칸이 하나라도 틀리면 반쯤 보이지 않고 「읽지 못했습니다」). 대기 레인의 사유는 작업
컴퓨터에서 줄여 보낸다: 레인 기록의 가장 최근 `PAUSED:` 메모에서 괄호·링크·경로·이메일·긴 숫자 id·커밋 해시를 떼고, 영어 메모는
「소유자 승인(✅) 대기, v1.40.0 릴리스 카드」·「소유자 결정 대기, 질문 Q12」 같은 정해진 한국어 문구로 바꾼 뒤 70자 안에서 자른다
(`collect.mjs` 의 `waitReason`). 「10/17 08:06 KST」·「~00:15 KST」·「12:00 KST까지」 처럼 적힌 시각만 예정 시각(`until`)이 되고,
메모보다 이른 날짜나 「owner stop 10:25 KST」 같은 맨 시각은 이미 일어난 일이라 예정으로 읽지 않는다. 노드는 사유를
한 번 더 걸러(`sessions_view._plain`) 링크·경로·여섯 자리 넘는 숫자·해시를 화면에 내지 않고, 80자를 넘거나 줄바꿈이 든 사유는 집계
전체를 「읽지 못했습니다」로 돌린다. 예전 수집기가 보내는 `hold` 는 `wait` 로 읽는다. 호스트별 값(노드 주소·레지스트리 폴더·
분류 규칙·서비스 표)은 그 컴퓨터의 비공개 env 파일에만 둔다. **다른 계정의 도리**(2026-10-19 — 옥돌·무돌·유돌이 다른 컴퓨터의
각 계정으로 갔다)도 같은 탭에 나온다([소개](../기능소개/세션-탭-여러-도리.md)): env 의 `SESSION_FEED_PEERS` 에 이름을 적으면
`feed.sh` 가 `SESSION_FEED_PEER_RUN`(예: 그 계정으로 명령 하나를 돌리는 ssh+sudo 래퍼) 로 각 계정에서 같은 `collect.mjs` 를
같은 기준 시각(`SB_NOW`)으로 돌려 행을 합친다. 각 계정의 입력(레인 폴더·분류 규칙·서비스 표)은 그 계정의
`~/.config/session-feed/feed.env` 에 둔다. 한 계정이 실패하면 나머지는 보내고 그 실행은 종료 코드 3(서비스 행 「실패」)이다.
짱돌까지 그 컴퓨터로 가면 피어 실행 명령만 같은 컴퓨터의 sudo 로 바꾸면 된다. 파일이 없으면 「아직 비어 있습니다」, 밖으로 나가는 사본(`digest`)에는
세션을 싣지 않는다(「이 사본에는 싣지 않습니다」). 데모 보드는 지어낸 일주일치 세션을 보여 준다.

**프로젝트 순서**. 프로젝트 카드·드롭다운·할 일과 근거의 프로젝트 묶음은 모두 `dashboard.project_sort_key` 한 함수가 정한
순서를 따른다. 지금은 이름(가나다)순이고, 소유자가 말한 「주관 순서」가 정해지면 그 함수만 바꾼다.

**프로젝트 보관**(2026-10-15 소유자 지시). 프로젝트 화면 머리글의 「보관」을 누르면(확인 한 번) 그 프로젝트가 요약·프로젝트·
할 일·일정·근거·최근 기록과 드롭다운에서 사라지고 보관함 화면(`#archive`, 프로젝트 탭 맨 아래 「보관함 N」 줄)에만 카드로 남는다. 카드에는 보관 시각과
누가 보관했는지가 붙고, 눌러 들어가면 할 일·일정·근거가
그대로 있으며 「보관 해제」로 되돌린다. **표시만 바꾸고 지우지 않는다** — `board.db` `projects` 행의 `archived_at`·`archived_by`
두 칸(스키마 v3)과 최근 기록의 「보관」·「보관 해제」 한 줄이 전부이고 할 일·근거·등급은 그대로다.

**누가 했는지**. 보관과 할 일 체크는 같은 신원을 남긴다(`server._actor`, 최근 기록의 `events.actor` 칸, 스키마 v3) —
테일넷으로 열면 `tailscale serve` 가 넣은 테일스케일 로그인(평소 경로, v1.27.0 부터 토큰 없이), 노드에서 루프백으로 직접
열면 `노드 로컬 접속(127.0.0.1)` 처럼 접속 주소가 기록된다. 화면에는 로컬 접속이 「이 기기에서」로 보이고 주소는 나오지 않는다
(기록에는 남는다). 소유자 화면은 보관함 카드와 최근 기록 줄 끝에 그 신원을 보여 주고,
밖으로 나가는 사본은 싣지 않는다. 그전에 기록된 체크는 신원 칸이 비어 있다. 권한은 할 일 체크와 같다:
`POST /project/<이름>`(`archived=1|0`)은 토큰(쿠키+헤더, 같은 출처) 또는 허용 목록의 테일넷 로그인+테일넷 `Origin` 이 있어야
하고 아니면 401/403 이다. 밖으로 나가는 사본(`digest`)은 보관함과 보관 시각만 싣고 누가 보관했는지는 싣지 않으며, 보관 버튼도
없다. 보관한 프로젝트에 새 카드가 승인되면 할 일은 들어가되 프로젝트는 보관함에 그대로 있고(해제는 소유자가 한다),
놓치지 않게 보관함 안에서만 알린다 — 위 메뉴 「보관함」 옆에 보관한 프로젝트 수와 「새 N」, 보관함 카드에 「보관 뒤 새 할 일 N」.
요약을 포함한 메인 화면에는 보관한 프로젝트가 어떤 형태로도 나오지 않는다(소유자: 메인에서는 싹 다 사라지게).

**되돌리기**. 스키마 v3 이전 판(v1.34 이하)의 코드는 v3 보드를 열지 않는다("newer than this code"). 보통은 앞으로 나가는
릴리스로 고친다. 그래도 옛 판을 돌려야 하면 대시보드 유닛을 멈추고 `board.db` 를 복사해 둔 뒤 아래를 실행한다 — 보관
표시와 기록의 신원만 사라지고 할 일·근거·등급은 남는다(옛 코드가 `projects` 에 칸 네 개로 쓰므로 칸을 지워야 한다,
SQLite 3.35+). `tests/unit/test_project_board_archive.py` 가 이 블록을 그대로 실행해 v2 칸과 같아지는지 확인한다.

```sql
ALTER TABLE projects DROP COLUMN archived_at;
ALTER TABLE projects DROP COLUMN archived_by;
ALTER TABLE events DROP COLUMN actor;
PRAGMA user_version = 2;
```

**목록 접기**(2026-10-15 소유자 지시, 2026-10-22 "도리에게 지시도 접을수있게"·"접는 기능이 있으면 모든 리스팅에 적용해야지").
대시보드의 목록 묶음은 모두 같은 접기 하나(`dashboard_theme.fold`)를 쓴다: 요약의 「승인을 기다리는 제안」·「도리에게 지시」·「최근 기록」,
할 일 탭의 프로젝트 묶음, 일정의 지연·이번 주·다음 주·이후·미정 묶음, 근거 탭의 프로젝트 묶음, 프로젝트 화면의 할 일·일정·근거·
「이 프로젝트에 대한 도리 지시」, 할 일 화면의 「같은 근거에서 나온 할 일」·「이 할 일에 대한 도리 지시」·「기록」, 지시 탭의 진행 중·끝난·
시험 지시, 지시 화면의 「기록」, 세션 탭의 「먼저 볼 것」과 분야·플랫폼·서비스 묶음. 머리는 어디서나
꺾쇠 · (아이콘) · 제목 · 개수 배지 순이고, 필요하면 제목 아래 한 줄(지시 상자의 「진행 중 N건」, 세션 묶음의 상태 수)과 끝에
버튼·상태 배지가 붙는다 — 「지시 쓰기」는 접힌 머리에서도 그대로 눌린다. 머리를 누르거나 Enter·Space 로 접고 펴며, 머리에
`aria-expanded` 가 붙는다. 접힘과 펼침 둘 다 브라우저 저장소(`localStorage` 의 `pb-fold:<묶음>`, 값 `0`/`1`)에 남아
새로고침해도 유지된다 — 기기마다 따로이고 서버는 모른다. 처음에는 대부분 펼쳐져 있고, 끝난 지시(진행 중인 지시가 있을 때)와
시험 지시만 접혀 있다. 접지 않는 것: 숫자 타일, 한 줄짜리 링크 카드(마감 미정·프로젝트 N개 보기·작업 컴퓨터 세션), 화면 전체가
목록 하나인 곳(프로젝트·보관함 카드 격자, 사람 화면), 세션 개요와 하루별 막대, 첫 사용 안내, 목록 안의 「기록 N건 더 보기」.

## 도리에게 지시 (2026-10-21 소유자 지시)

소유자가 대시보드에서 도리에게 일을 맡기는 칸이다. 하단 일곱 번째 탭 「도리 지시」(2026-10-23 소유자 Q360: 누를 것이 없던 장부 탭을
없애고 그 자리에 둠, 라이브 화면에만 — 파일 사본은 탭 여섯 개)와 요약의 「도리 지시」 상자(탭 이름과 같다, 폰에서 한 줄)가 `#orders` 를 연다(지시 칸·진행 중인 지시·끝난
지시, 진행 중인 지시가 없으면 끝난 지시를 펼쳐 둔다), 지시 하나는 `#order/<번호>`(지시 내용, 받음→넘김→처리 중→끝 단계 — 지난
단계는 ✓, 받는 도리와 전달 시각, 맡은 도리, 도리 방 글, 관련 할 일·프로젝트 링크, 메모, 기록). 요약 상자는 폰에서 짧게(2026-10-22
소유자 "안 고쳐졌는데? 도리에게 지시 탭이 부자연스러워"): 진행 중인 지시(세 건까지)와 그 아래 「최근 결과」 한 건 — 가장 최근에
끝난 지시와 메모 — 만 보이고(상자는 머리를 눌러 접을 수 있고 접혀도 개수·「진행 중 N건」·「지시 쓰기」가 남는다, 「목록 접기」), 나머지는 「지시 탭에서 전부 보기」로 간다(상자에 없는 실제 지시가 있으면 「(N건 더)」, 시험 지시는 세지 않는다). 요약 줄에는 할 일·프로젝트 링크를 싣지 않는다.
목록 한 줄은 「상태 · 때 · 누가 갖고 있나(아직 전달 전 / <받는 도리>에게 전달됨 / 맡은 도리 <이름> / 끝난 지시는 「<도리>가 끝냄」과
끝난 때)」, 그 아래 메모, 그 아래 「할 일 <제목>」·「프로젝트 <이름>」·「도리 방 글 보기」가 한 줄씩이다(긴 할 일 제목이 구분점 줄을
밀어 「·」가 홀로 떨어지지 않게). 메모는 유돌이 적은 말 그대로 저장하되, 화면에서는 괄호 속 상태 번호(`(200)` 같은)와 문지기·게이트
이야기 구절을 빼고 보인다. 본문이 `[시험]`으로 시작하거나 전달 유닛이 「시험(보내지 않음)」으로 표시한 지시는 경로 확인용 시험이라
요약 상자와 개수에서 빠지고 `#orders` 맨 아래 접힌 「시험 지시」 묶음에만 있다(지우지 않는다, 지시 화면도 그대로, 「시험이라 보내지
않음」으로 적힌다). 기록은 바꾼 줄에만
바꾼 도리를 적고(만든 줄의 로그인 주소·127.0.0.1은 보이지 않는다 — 보낸 기기 칸이 말한다), 문지기가 잇달아 쓴 근거 확인은
「쓰기 근거로 확인됨 (N번)」 한 줄로 묶는다. 할 일 화면과 프로젝트 화면에는 그 할 일·프로젝트에 대한 지시 목록과 「이 할 일로/이
프로젝트로 도리에게 지시」(그것이 미리 골라진 지시 칸)가 붙는다. 할 일을 고르면 프로젝트 칸은 잠기고 「고른 할 일의 프로젝트로
정해집니다」가 보인다. 보내면 새 지시 화면이 열리고 맨 위에 「보냈습니다 …」 한 줄이 한 번 보인다. 지시 목록에서 연 지시의
뒤로 가기는 「도리에게 지시」로 돌아간다. 지시는 소유자의 말이라 밖으로 나가는 사본(`digest`·파일 모드)에는 싣지 않는다
(2026-10-22 폰·데스크톱 재점검, `layout_audit.mjs` 0건).

- **저장**: `POST /order/new`(`text` 1~1000자, 선택 `todo`·`project`) — 할 일 체크와 같은 권한(토큰+같은 출처, 또는 허용
  목록 테일넷 로그인+테일넷 `Origin`), 아니면 401/403. 없는 할 일·프로젝트는 400. 할 일을 고르면 프로젝트는 그 할 일의 것.
  지시는 보드 옆 별도 파일 `orders.db`(0600)에 쌓인다 — 승인된 보드 스키마와 릴리스 전용 이관은 건드리지 않는다.
  누가 썼는지(`created_by`, 테일넷 로그인 또는 노드 로컬 주소)와 경로·기기를 남긴다. `via` = `owner-device`(허용 로그인이
  `dashboard.tailnet.owner_devices`에 있는 형 기기에서 보냄) | `tailnet`(테일넷이지만 형 기기가 아님 — 노드 자신·다른 서버 포함,
  노드가 형 테일넷 계정이라 로그인만으로는 가를 수 없다) | `local`. 보낸 기기는 `tailscale serve`가 넣은 `X-Forwarded-For`로
  찾되, 그 값은 루프백 상대 소켓이 root(tailscaled)일 때만 믿는다(다른 로컬 프로세스는 헤더를 위조할 수 있다 — `/proc/net/tcp`의
  uid). 기기 이름은 `tailscale whois`의 고정 노드 ID(`device_id`)로 남긴다. 형 기기 목록 설정:
  `"dashboard": {"tailnet": {"owner_devices": [{"id": "<StableID>", "name": "<표시 이름>"}]}}`(`tailscale status --json`의 Peer.ID).
- **전달**: 노드 밖 전달 유닛(받는 도리를 돌리는 호스트의 사용자 타이머)이 `orders --undelivered --json` 으로 새 지시를
  읽어 받는 도리의 받은편지함에 한 줄 넣고 `order-delivered` 로 한 번만 기록한다. 기존 계정 전환 권한만 쓴다.
- **되돌려 적기**: 받는 도리가 `order-update` 로 상태·맡은 도리·도리 방 글 링크(https 한 주소만)·메모를 적는다.
  유돌은 노드 게이트 `order-status <번호> <상태> [--dori] [--post-url] [--note]` 로만 쓰며 기록자는 항상 유돌이다.
- **할 일 완료(유돌)**: 유돌은 처리한 할 일을 노드 게이트 `todo-done <할 일 id> [--note <200자 이내>]` 로만 완료로 바꾼다.
  게이트는 `progress <id> --status 완료 [--note] --by 유돌` 을 부르고, `progress` 는 이미 완료면 저장하지 않고 `ALREADY` 를 낸다.
  지우기·되돌리기·다른 칸 바꾸기는 없다([소개](../기능소개/유돌-대시보드-할일-완료.md)).
- **문지기 확인용 읽기**: `GET /api/orders/<번호>` 는 노드 문지기 전용이다. 헤더 `X-PB-Gate-Token` 이 보드 루트의
  `orders-gate.token`(0600, `serve` 가 처음에 만든다)과 같고, 테일넷 헤더·테일넷 주소로 오지 않은 요청만 받는다(아니면 403).
  답은 번호·시각·쓴 사람·경로(`via`)·보낸 기기(`device` = 고정 노드 ID, `device_name`, `device_ip`)·본문 sha256·상태·
  관련 할 일/프로젝트·사용 횟수이고 본문은 없다. 문지기는 `via == owner-device`이고 `device`가 비어 있지 않을 때만 형 명령으로 본다.
  문지기가 지시를 쓰기 근거로 쓰면 `POST /api/orders/<번호>/use` 로 사용 횟수를 올리고 기록에 남긴다.
