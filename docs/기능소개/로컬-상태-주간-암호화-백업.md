# 로컬 상태 주간 암호화 백업 (SC-3)

## 무엇을

노드 계정의 `~/.hermes` 로컬 상태(자가 스킬·감사 원장·큐레이션 카운터)를 주 1회
암호화 아카이브로 Google Drive 전용 폴더 `autophagy-backups/<계정>/`에 올린다.
업로드 전 로컬 키로 암호화하므로 Drive에는 평문이 놓이지 않는다.

## 왜

`~/.hermes`의 자가 스킬과 메모리는 git 밖 **유일본**이다 — 노드 디스크가 죽으면
에이전트의 맞춤형 변화가 전부 사라진다. 노드 로컬 백업(`/srv/autophagy-private/`)은
같은 디스크라 무력해 기각됐고, 소유자 결정(2026-08-28 §10-4)대로 Drive 암호화
아카이브를 쓴다. 메모리에는 개인 정보가 있으므로 암호화는 선택이 아니라 전제다.

## 사용 시나리오

- **최초 1회(소유자, 노드에서)**: 암호화 키를 만들고 오프라인 사본을 보관한다.
  ```
  mkdir -p ~/.hermes/backup
  openssl rand -hex 32 > ~/.hermes/backup/backup.key && chmod 600 ~/.hermes/backup/backup.key
  ```
  키를 잃으면 모든 백업을 읽을 수 없다 — 키 자체는 절대 업로드되지 않는다.
- **평상시(자동)**: 매일 03:15 no-agent cron이 돌지만 **배달 주간 워터마크**가 주 1회를
  보장한다 — 같은 ISO 주에 이미 배달했으면 무음 no-op, 월요일 틱이 실패한 주는
  다음 틱이 이어받는다(워터마크는 owner-only + read-back 검증 뒤에만 전진).
- **키가 없으면**: `BACKUP-KEY-MISSING`으로 fail-closed — 아무것도 업로드하지 않고
  생성 명령을 안내한다. 키 권한이 0600보다 느슨해도 같은 방식으로 거부한다.
- **복원**: 파일을 내려받아 같은 키로 복호한다(리허설 1회가 QA 조건).
  ```
  openssl enc -d -aes-256-cbc -md sha256 -pbkdf2 -iter 200000 \
    -in state-<계정>-<주>.tar.enc -pass file:~/.hermes/backup/backup.key | tar -xz
  ```

## 경계

- **백업은 산출물이 아니다** — `drive_outputs` taxonomy(카테고리·depth)는 적용되지
  않고 전용 루트를 쓴다. 다만 Drive I/O는 기존 저수준 `DriveClient` 하나를 재사용해
  파사드 conformance(업로드 구현 사본 금지)가 그대로 성립한다.
- 아카이브는 allowlist(`skills`·`selfskill-audit`·`wiki-curate`·`memory-curator`·
  `supply-chain-watch`)만 싣는다 — 자격증명(`~/.env.secrets`)은 루트가 달라 구조적으로
  포함 불가, 심링크·`__pycache__`·벤더 설치본도 실리지 않는다.
- 세대 보존: 최신 8세대 밖은 **trash**(삭제 없음), 접두사 불일치 파일은 불가침.
