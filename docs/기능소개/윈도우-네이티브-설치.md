# 윈도우 네이티브 설치 (WSL 없음)

## 무엇을

도리 기본 설치를 WSL 없이 윈도우에서 PowerShell 한 줄로 설치하고, 같은 줄로 업데이트한다.
상시 실행은 systemd 대신 작업 스케줄러 두 항목이 맡는다.

## 왜

README 는 Linux + systemd 전용이라고 적었고, 윈도우 연구원은 설치부터 막혔다.
형은 WSL 없이 윈도우에서 바로 도리를 쓰길 원했다.

## 사용 시나리오

**정상 경로.** 연구원이 PowerShell 에 붙여 넣는다.

```powershell
powershell -ExecutionPolicy Bypass -c "irm https://raw.githubusercontent.com/orientpine/cytoplasm/main/install.ps1 | iex"
```

빠진 도구(git·Python·bun·PowerShell 7)는 winget 이 깔고, 서명된 최신 릴리스를 확인한 뒤 포크·역할·herdr 가
설치된다. 「Dori herdr server」·「Dori serve」 두 작업이 바로 뜨고, 재부팅 뒤 로그온하면 다시 떠서 루프가 돈다.
새 릴리스가 나오면 같은 줄을 다시 실행한다. 「Dori serve」 만 새 코드로 재시작되고 리드 pane 은 그대로다.

**거부 경로.**

- 받은 `update-trust.pub` 지문이 README 값과 다르면 `CYTO-WINDOWS-FINGERPRINT-MISMATCH` 로 클론에서 아무것도 실행하지 않고 멈춘다.
- 서명 없는 더 새 태그는 무시하고 마지막 서명 릴리스에 머문다.
- 손댄 체크아웃은 업데이트를 거부한다. 손으로 바꾼 포크는 `DORI-PIN-UPDATE-REFUSED`.

두 작업 모두 창을 숨겨 띄우므로 로그온 뒤 콘솔 창이 남지 않는다(도리 포크 #368).
레거시 노드 인프라, herdr 웹, 레인 체크포인트, 분리 인수인계, `dori heavy`, 송신 게이트, 음성 설정은 Linux 전용이다.

## 관련

- `install.ps1`(저장소 루트, 윈도우 입구), `automation/install/update.py`, `automation/install/dori.py`,
  `automation/install/dori_herdr.py`, `automation/dori_pin.py`, `dori/herdr.toml`
- 서명 확인은 `automation/update_trust.py` 재사용. 승인 게이트는 관여하지 않는다(설치 경로).
- CI `windows-install` 잡이 `tests/windows/install-update.ps1` 을 깨끗한 windows-latest 에서 돌린다.
- 안내: [설치 가이드 「윈도우」](../guide/install.md#윈도우네이티브-wsl-없음)
