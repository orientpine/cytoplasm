# 기능 소개: 일정 다이제스트 일별 승인 스레드

**PR:** #509 · **스킬:** `calendar`(mail 다이제스트가 위임) · **티켓:** repair `t_bacebc3a`

## 무엇을

메일 다이제스트가 일정 메일을 감지하면 캘린더 CLI에 `draft-create --digest-day <YYYY-MM-DD>`로 위임한다. 이 플래그가 있으면 초안 저장에서 끝나지 않고 **그 자리에서 승인 카드까지 게시**한다.

- 게시일(KST)마다 승인 스레드 **하나**(`캘린더 · 다이제스트 <날짜>`), 그 안에 일정마다 ✅/⛔ 카드 **하나**. 카드는 각각 독립적으로 결정한다.
- 같은 일정의 기준은 캘린더 + KST 시작 시각(분) + 제목 토큰 집합이다. 기간이나 문장부호가 바뀐 후속 메일은 **아직 결정되지 않은 카드만** 최신 내용으로 교체한다.
- 이미 ✅/⛔로 결정된 일정은 같은 메일이 다시 와도 다시 묻지 않는다.
- 결과(실행 완료·취소·실행 실패)는 그 카드 **아래 답글**로 올라가고, 일별 스레드는 다른 카드가 남아 있으므로 개별 결과로 닫지 않는다.

## 왜

카드가 붙지 않은 초안은 24시간 뒤 고아로 폐기됐고(2026-09 실측), 일정마다 스레드를 열면 소유자가 하루치 일정을 한 곳에서 볼 수 없었다. 새 승인 상태 기계를 만드는 대신 기존 요청 스레드 디렉터리·키 lease·승인 라이프사이클·원채널 통지를 재사용하고, 날짜 바인딩 하나로 스레드를, 결정론적 일정 식별자로 카드를 고정했다.

## 사용 시나리오

### 정상 경로

1. 아침 다이제스트가 세 통의 일정 메일을 감지한다. 그날 스레드 하나가 열리고 카드 세 장이 게시된다. 종료코드 0은 "카드가 실제로 게시됐다"는 뜻이다.
2. 소유자가 두 번째 카드에 ✅를 남기면 기존 캘린더 가드 경로로 일정이 생성되고, 그 카드 아래에 완료 답글이 달린다. 첫 번째 카드에 ⛔를 남기면 `cancelled`로 기억되어 다시 묻지 않는다.
3. 오후에 아직 결정하지 않은 세 번째 일정의 정정 메일이 오면, 그 카드만 같은 스레드에서 교체된다.

### 실패·복구 경로

- 게시가 끝나지 않으면 소유자에게 `캘린더 승인 카드를 게시하지 못했습니다` 통지가 가고 exit 1로 끝난다. 저장된 초안은 감시자가 **다음 틱에 3분 유예 없이** 다시 게시한다.
- 게시 응답을 잃었거나 반응 무장에 실패한 경우, 다음 틱은 스레드 이력에서 이미 올라간 카드를 찾아 그것을 살린다. 같은 카드가 둘이 되지 않는다.
- 첫 디렉터리 쓰기가 실패해도 재시도 가능한 초안이 남고, 이미 반응이 달렸지만 소비되지 않은 결정은 정정 메일이 와도 유지된다.
- 실행 실패는 `⚠️ … 실행 실패`로 카드 아래에 알린 뒤 항목을 남겨 다음 틱에 재시도한다.
- 다이제스트가 아닌 초안은 종전대로 `post-confirm`/3분 백스톱 경로를 따른다.

## 승인 카드에서 일정 구별하기 (2026-09-20 소유자 승인)

동작 종류와 draft id만 보이던 카드로는 일정 A/B를 구별할 수 없었다. **새 calendar v4
승인 카드**는 검증된 소유자 전용 스레드 안에 동작·제목·시작·종료를 각각 인용 줄로
표시한다. 시각은 `YYYY-MM-DD HH:MM (+09:00)` 형식이고 종일 일정의 날짜는 그대로다.
수정은 실제 고정된 명령에 있는 변경 항목과 유지 항목을 구별한다. 수정·삭제
초안은 대상 이벤트를 읽어 표시 문맥을 기존 해시 필드에 고정하며, 저장하지 않은 이전
값을 before→after로 추측하지 않는다. 게시 시점에 이벤트를 다시 읽어 내용을 바꾸지 않는다.

- 정상: 같은 시각의 예시 일정 A/B도 제목과 시작·종료를 보고 각 카드에 독립적으로 결정한다.
- 거부: 대상 이벤트 조회 실패/불일치/불완전한 시각이면 새 수정·삭제 초안을 저장하지 않는다.
  카드가 너무 길면 안내·스레드·게시 예약 전에 멈춘다. 게시 직전 채널이 공유/미상으로
  판정되거나 intent 바인딩과 다르면 상세를 전송하지 않는다.
- 공개 경계: 상세 허가는 **승인 카드 본문에만** 적용된다. 부모 채널 안내·스레드 이름·
  결과 통지·공유 채널은 기존 마스킹을 유지한다. 디렉터리가 설정된 소유자 전용 부모와
  실제 채널 종류를 검증하며 호출자가 전달한 비공개 여부를 믿지 않는다.
- 호환: 기존 v1/v2/v3 카드·hash·pending 재생, 다른 스킬의 기본 렌더 버전과 표면 정책은 불변이다.
  calendar만 신규 v4를 선택하며 마지막 줄은 전체 SHA-256을 인라인 코드로 표시한다.

이 검증은 합성 이벤트와 오프라인 HTTP를 사용한 로컬 회귀다. 실제 등록(C4)·노드 반영은
별도의 소유자 승인·배포 검증 대상이며, 카드 개선만으로 완료됐다고 보지 않는다.

## 승인 경계

캘린더 쓰기는 카드별 소유자 ✅ 뒤에만 일어나며, 기존 `calendar_cli.py confirm/discard` 가드를 그대로 거친다. 바인딩 파일은 게이트 디렉터리 안(`daily-threads/<날짜>.json`)에 있고 체크아웃 밖이다. 실제 노드에서의 카드·결과 read-back은 배포 이후 항목이다.
