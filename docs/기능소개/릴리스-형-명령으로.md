# 릴리스는 형 명령 글로 — 승인 카드 없이 릴리스·배포까지

## 무엇을

사이토플라즘 릴리스에 형 ✅ 카드가 없어졌다. 형이 "릴리스 내"처럼 시킨 디스코드 글 하나가
승인 근거가 되고, 짱돌이 그 글 링크로 릴리스·서명 태그·노트·노드 배포까지 끝낸 뒤 결과를
짧게 알린다. 형 명령 없이는 릴리스하지 않는다.

## 왜

형은 릴리스마다 카드의 ✅를 누르는 일이 번거로웠다(2026-11-02 21:35 KST 음성, Q447:
"그리고 릴리즈도 승인 필요 없을 것 같아. 내라고 하면 네가 해서 릴리즈하고 배포까지 하는 걸로
하자."). 형 승인 카드는 이제 바깥 사람에게 가는 것(메일·바깥 초대·바깥 공유)만 남는다.

## 사용 시나리오

1. 형이 짱돌 스레드에 음성으로 "이번 거 릴리즈하고 배포까지 해"라고 말한다.
2. 짱돌은 그 글 링크로 `automation/release.sh --owner-command <링크> --owner-inbox <수신기 inbox>
   --notes-file <노트>`를 돌린다. 음성 글은 본문이 비어 있어 수신기가 남긴 전사를 함께 싣는다.
3. 노드 agent 계정이 그 글을 디스코드에서 다시 읽어 확인한다: 형 본인의 글이고 봇 글이 아님,
   릴리스 서버의 글, 24시간 안, 글(또는 전사)에 릴리스·릴리즈·release·배포·deploy 중 하나,
   다른 릴리스에 쓴 적 없는 글. 통과하면 버전·HEAD·바뀌는 표면 전부를 묶은 승인 기록을 쓰고,
   그 기록에 글 링크와 본문(음성은 음성 파일·전사) sha256을 남긴다. 카드는 올라가지 않는다.
4. 짱돌의 워크스테이션 키로 서명 태그를 자르고 GitHub Release 노트를 게시한 뒤 노드 배포
   (`deploy_all --apply --wait-converge`)까지 이어진다. 배포의 각 단계는 같은 글을 다시 읽어
   형의 글인지 확인한 뒤에만 그 표면을 반영한다.
5. 짱돌이 질문 카드(`dori ask`)로 "릴리스 낼까?"라고 묻고 형이 「릴리스 해」 버튼을 누르면, 그 카드 링크가
   형 명령 글을 대신한다(형 2026-11-12 "봇 카드 버튼 답도 받게 해."). 노드는 그 카드가 봇 자신의 글이고
   버튼으로 접힌 답이며, 질문과 답 모두 릴리스를 말하고 답이 미루는 말이 아닌지 확인한 뒤 카드 글 sha256을
   남긴다. 형이 글을 한 번 더 쓰지 않아도 된다.
6. 적용이 끝나면 형 채널에 "✅ vX.Y.Z 적용됨 — <요약>" 한 줄이 간다.

거부되는 경우(태그·배포 없음, `release.sh` exit 4):

- 형 명령 링크 없이 실행 — `RELEASE-NO-OWNER-COMMAND`.
- 형이 아닌 사람·봇의 글, 다른 서버의 글, 24시간 지난 글, 릴리스·배포를 말하지 않은 글
  ("그거 내"처럼 짧은 말만 있는 글 포함), 전사 없는 음성 글, 이미 다른 릴리스에 쓴 글 —
  `RELEASE-COMMAND-REFUSED`.
- 카드 답인데 「나중에」·「릴리스는 미뤄」처럼 미루는 답, 릴리스를 묻지 않은 카드, 버튼이 아니라 직접 쓴 답,
  봇이 아닌 사람이 카드 모양으로 쓴 글, 웹훅 글, 아직 답하지 않은 카드, 게시 뒤 24시간 지난 카드 — `RELEASE-COMMAND-REFUSED`.
- 기록 뒤에 고친 카드는 배포 단계에서 인가되지 않는다.
- 배포 도중 그 글을 읽을 수 없거나 형 글로 읽히지 않으면 그 단계는 인가되지 않는다.

## 그대로 남는 것

- 서명 태그(서명 키는 릴리스 호스트 운영자 계정에만)와 노드의 서명 검증·되돌림 방지.
- 승인 기록의 `action_hash`(버전·HEAD·표면 전부)와 배포 단계의 표면 포함 검사.
- 이미 저장된 옛 카드 기록의 ✅ 판정.
