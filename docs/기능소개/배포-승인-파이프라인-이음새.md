# 배포·승인 파이프라인 이음새

## 무엇을

스킬 시나리오의 실행 환경을 한 러너로 통일하고, 승인된 요청의 nonce를 새로 만들지
않도록 막는다. 랜딩과 워크트리 시작 단계도 설정 누락·특권 헬퍼 드리프트·Git 평면 ref
충돌을 실제 작업보다 먼저 설명한다.

## 왜

같은 `scenario.sh`가 검토 단계마다 다른 환경에서 실행되면 한 단계의 PASS가 다음 단계의
PASS를 보장하지 못한다. 승인 뒤 재실행이 새 nonce를 만들면 이미 받은 ✅도 사용할 수
없다. 노드 설정 placeholder와 평면 ref 충돌은 원인이 아닌 DNS·Git 저수준 오류로 보여
복구가 늦어졌다. 이번 변경은 이 다섯 이음새를 명시적 fail-closed 진단으로 바꾼다.

## 사용 시나리오

정상 경로에서는 `skill_review`와 `peer_attest`가 각각 독립 실행되면서도
`AUTOPHAGY_REPO_ROOT`와 `INTEROP_RUNTIME`을 포함한 같은 환경 계약을 사용한다. 랜딩이
끝나면 기존 `release_helper_probe.sh`가 특권 설치본과 릴리스 원본의 드리프트를 읽기
전용으로 확인한다.

이미 ✅가 붙은 pending 요청을 nonce 없이 다시 요청하면 새 요청을 만들지 않고
`reason=approved-awaiting-resume`으로 정지한다. 노드 설정이 seed인 랜딩은 DNS 접근 전에
`NODE-CONFIG-BLOCK`과 `node.toml` 조치를 출력한다. `session` 같은 평면 브랜치가
`session/<name>` 생성을 막으면 `worktree.sh start`가 D/F 충돌과 `git branch -m` 조치를
먼저 안내한다.
