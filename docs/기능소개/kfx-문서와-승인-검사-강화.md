# 문서와 승인 검사에서 빠지던 경계를 닫는다

## 무엇을 · 왜

테스트가 통과해도 끊어진 안내 링크나 우회된 발신자를 놓칠 수 있었다.
사용자의 실 계정 대신 격리된 환경에서 실패를 드러내도록 검사 경계를 보강한다.

- 문서의 상대 경로와 앵커를 검사해 없는 파일·제목을 잡는다.
- 발신자가 iterator·zip·dict·첨자·구조 분해를 거쳐도 추적한다. 선택을 증명하지 못하면 통과시키지 않는다.
- 승인 lease는 frozen 예외를 다른 오류로 바꾸지 않고 잠금을 해제한다.
- meeting 테스트의 Drive 실행 경계를 주입하고 형제 테스트 import의 편집기 환경을 선언한다.
- 안전성이 확인된 스킬 시나리오는 별도 프로세스·홈·네트워크에서 실제 실행한다.

## 사용 시나리오

**정상:** 개발자가 문서 제목을 바꾸고 링크 갱신을 빠뜨리면 링크 검사가 실패한다.
`next(iter((client.send_owner_dm,)))()`처럼 감싼 발신자도 봉투 채택 검사 대상이 된다.
정상적인 승인 거부는 원래 예외로 전달되고 같은 키의 잠금을 다시 얻을 수 있다.

**실패:** 모호한 컨테이너 선택이나 외부효과 도구 호출을 숨겨 통과시키지 않는다.
시나리오에서 효과 도구를 부르면 거부 스텁에 기록되며, 스크립트가 오류를 삼켜도 테스트는 실패한다.
실행 대상으로 분류되지 않은 시나리오는 근거와 함께 보류하며 새 시나리오의 미분류도 검사한다.

## 적용 범위 · 관련

실제 실행 대상은 hello-autophagy·plaud·prompt·recall·repair·report·topics다.
모든 스킬의 실제 외부 서비스가 검증됐다는 뜻은 아니다.
Ubuntu CI는 배포판의 bwrap 전용 AppArmor 프로필을 사용하며 네트워크 격리를 끄지 않는다.
