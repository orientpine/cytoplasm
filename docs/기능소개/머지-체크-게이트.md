# 머지 체크 게이트

## 무엇을

PR 머지가 **명령 하나**로 통일된다. 그 명령은 체크가 green 일 때만 머지한다(태그는 자르지 않는다 — 아래 「개정」).

```
$ automation/merge-pr.sh 269
[merge-pr] REFUSED — failing check(s): verify. Fix them; the escape hatch does not cover a failure.

$ automation/merge-pr.sh 271
[merge-pr] checks 3 check(s) passed
[merge-pr] merging pull request 271
[merge-pr] landed pull request 271 — 머지는 축적이다. 배포하려면: automation/release.sh (VA-1)
```

## 왜

**브랜치 보호를 쓸 수 없습니다.** private + Free 조합이라 `gh api repos/.../branches/main/protection` 이 403 입니다. 켤 수 있다 해도 에이전트 토큰이 `admin` 이라 기본 설정은 그를 통과시키고, 관리자까지 묶으면 `automation/land.sh:189` 의 main 직접 착지가 서버에서 거부됩니다.

그리고 이건 가정이 아니라 관측입니다 — 2026-08-25 하루에 두 번 뚫렸습니다. PR #267 은 **빨간 CI 위에서**, PR #269 는 **체크가 큐잉되기도 전에**(`no checks reported`) 머지됐고, 둘 다 에이전트가 눌렀습니다.

push 게이트(로컬 CI 영수증)는 이걸 못 막습니다. 그건 **브랜치 push** 를 묶지 머지를 묶지 않기 때문입니다.

## PR 체크는 로컬 영수증이 못 하는 일을 한다

| | 검사 대상 |
|---|---|
| `automation/local_ci.sh` 영수증 | **브랜치 트리** |
| GitHub `pull_request` 실행 | **머지 결과 트리** |

2026-08-25 에 실제로 갈렸습니다: 머지 결과 트리 `43c50a44` 는 영수증 `57081383` 이 덮지 못하는 내용이었습니다(그 사이 main 이 13커밋 전진). 그래서 둘 다 필요합니다.

## 판정 규칙

- PR 이 **OPEN** 이고 base 가 **main** 이어야 합니다.
- 모든 체크가 **완료 + 성공**(SUCCESS/NEUTRAL/SKIPPED)이어야 합니다.
- 진행 중이면 **기다립니다**(기본 900초 마감, 넘기면 거부). #269 는 "너무 일찍 물어본" 실패였고, 이 대기가 그걸 막습니다.
- **체크 0건도, 일부만 올라온 상태도 통과가 아니라 PENDING** 입니다. `.github/workflows/ci.yml` 이 선언한 잡이 **전부** 보고해야 하고, 그 이름은 워크플로에서 파생합니다(하드코딩하면 잡이 늘 때 조용히 샙니다). 2026-08-26 첫 실사용에서 그 순간 올라와 있던 체크 1건만 보고 통과시킨 적이 있어 보강했습니다.
- **머지 불가(`CONFLICTING`)는 판정 단계에서 거부**합니다 — `gh` 가 실패한 뒤가 아니라 그 전에, 해소 절차와 함께.
- **워크플로 잡과 외부 앱 체크는 다르게 기다립니다(2026-10-01).** 외부 체크(GitGuardian 등)도 실패하면 언제나 거부하지만, 워크플로 잡이 전부 green 인데 외부 체크만 유예 뒤에도 끝나지 않으면 아래 「외부 앱 체크가 멈출 때」의 보상 스캔으로 판정합니다.
- 머지가 실패하면 **태그는 호출되지 않습니다**. 태그만 실패하면 되돌리지 않고 재실행이 조치입니다(머지는 이미 공개된 지점이므로).

## 외부 앱 체크가 멈출 때 (2026-10-01)

2026-09-30 PR #557 에서 GitGuardian 이 평소 1초 걸리던 판정을 20분 넘게 `in_progress` 로 붙잡았습니다. 재실행 API 는 404 였고, 게이트는 모든 체크를 기다렸으므로 마감 뒤 거부만 남았습니다 — 머지할 길은 모든 미정 체크를 덮는 탈출구 하나뿐이었습니다.

이제 워크플로 잡이 전부 green 이고 외부 체크만 `MERGE_PR_EXTERNAL_GRACE_SECONDS`(기본 180초) 뒤에도 끝나지 않으면, 게이트가 그 PR 의 diff(`gh pr diff`)를 `gitleaks stdin` 으로 직접 스캔합니다(저장소 `.gitleaks.toml`, 값은 `--redact`). 깨끗할 때만 머지하고, 그 사실을 stderr 에 남깁니다.

```
$ automation/merge-pr.sh 561
[merge-pr] EXTERNAL-UNSETTLED GitGuardian Security Checks after 180s — gitleaks found no secret in the diff of pull request 561.
[merge-pr] merging pull request 561
```

거부되는 경우: gitleaks 가 없을 때, diff 를 읽지 못할 때(빈 diff·`gh` 실패·diff 크기 초과), gitleaks 가 무엇이든 찾았을 때, gitleaks 자체가 실패했을 때. 워크플로 잡이 아직 진행 중이면 보상 스캔은 돌지 않습니다 — 스캔은 외부 체크의 빈자리만 메웁니다. 유예가 마감(900초)보다 길면 예전처럼 마감에서 거부합니다.

## 탈출구

`MERGE_PR_ALLOW_UNCHECKED=1` **하나뿐**이고, **체크가 아예 나오지 않을 때만**을 위한 것입니다(예: Actions 결제 중단으로 잡이 시작조차 못 하는 상황 — 실제로 2026-08-24 에 그랬습니다). **실패한 체크는 이것으로도 통과하지 못합니다.** 쓰면 매번 stderr 에 남습니다.

## 한계 (알고 쓸 것)

머지는 GitHub 서버에서 일어나므로 pre-push 훅 같은 **구조적** 강제가 원리적으로 불가능합니다. 이 게이트는 **명령을 쓰는 주체에게만** 구속력을 갖습니다 — push 게이트만큼 단단하지 않습니다. 그래서 리포 코드에서 래퍼 밖 `gh pr merge` 호출을 conformance 테스트가 금지해, 최소한 **코드 경로**로는 우회가 불가능하게 했습니다.

서버측 강제를 원하면 GitHub Pro 의 브랜치 보호가 유일한 길이고, 그때는 `land.sh` 를 PR 경유로 바꾸는 것이 선행 조건입니다.

## 개정 (2026-08-30, VA-3)

머지 직후 릴리스 태그를 자동으로 자르던 단계는 제거됐다 — **머지는 축적이고 배포는
릴리스다**. 서명 태그는 소유자 ✅ 1회를 받는 `automation/release.sh`(VA-1)가 자른다.
체크 게이트(모든 워크플로 잡 완료+성공, 체크 0건=PENDING, `MERGE_PR_ALLOW_UNCHECKED`
탈출구)는 그대로다. 상세: [머지=축적과 릴리스 백로그 다이제스트](머지-축적과-릴리스-백로그-다이제스트.md).
