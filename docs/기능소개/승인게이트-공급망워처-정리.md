# 승인 게이트·공급망 워처 정리

## 무엇을

스킬 공급망의 소유자 반응 판정을 하나로 통일하고, 삭제된 Discord 승인 메시지를 대기 상태와
구분해 종결한다. 워처는 실패의 릴리스 SHA·사유 지문을 기억해 같은 실패를 매 2분 재실행하지
않고, 마지막 tick 결과를 체크아웃 밖의 private 상태 파일에 남긴다.

## 왜

직접 승인 확인과 재조정이 같은 메시지에 서로 다른 답을 내렸고, 삭제된 메시지는 누를 대상이
없는데도 계속 대기했다. 배포 재개가 결정론적으로 실패하면 타이머가 같은 실행을 무한 반복하면서도
systemd에는 성공으로 보였고, 운영 결과는 저널을 직접 열기 전까지 드러나지 않았다.

## 사용 시나리오

- **정상 경로**: cha가 배포 요청에 ✅를 누르면 워처가 기존 `deploy-skill.sh` 파이프라인을 다시
  호출한다. 성공한 tick은 요청별 outcome/reason과 릴리스 SHA를
  `~/.hermes/supply-chain-watch/tick.json`에 기록한다.
- **반복 실패**: 같은 릴리스와 같은 실패 사유가 다시 나타나면 첫 유형만 알리고, 결정론적 실패는
  고정 유예하며 contention 같은 transient 실패만 2분부터 1시간 상한의 지수 백오프로 재시도한다.
- **삭제·레거시**: Discord 10008은 `settled`로 분류해 transient 재시도에서 제외한다. pre-schema
  레코드는 자동 삭제하거나 승인 근거로 승격하지 않으며, cha가 바인딩을 확인한 뒤
  `abandon --legacy-only`로 명시적으로 종결할 수 있다.
