# 회의록 민감 판정 제거

## 무엇을

meeting 스킬이 회의마다 내리던 민감(`patent-sensitive`) 판정과 그 효과를 모두 없앴다. 이제 모든
회의록은 특허 낱말이 들어 있어도 다른 회의와 똑같이 처리된다 — 카드·마일스톤·#team 게시·Drive
발행·과제 원장이 그대로 돌고, 추출은 계정의 주 모델과 그 폴백 체인으로 간다.

## 왜

운영자와 구성원이 모두 보안 관리자 등급이라 문서 단위 민감 차단이 필요 없어졌다. 판정은 키워드·정규식
한 번의 적중으로 확정됐기 때문에 「출원」 같은 낱말 하나로 평범한 회의의 카드가 가려지고 Drive 발행이
멈췄다. 오탐을 문서별로 정정하는 장치를 덧붙이는 대신(검토 영수증 제안) 판정 자체를 없애는 쪽으로
정리했다.

## 사용 시나리오

- **특허 이야기가 섞인 회의**: `!meeting` 으로 올린 회의록에 「특허 출원」「청구항」이 있어도 내 액션
  아이템은 실제 제목(`청구항 초안 작성 (마감 …)`)으로 Kanban 카드가 되고, 마일스톤도 그대로 적히며,
  타인 항목은 #team 에 게시되고, `DRIVE_PUBLISH_ENABLED=1` 이면 회의록이 Drive
  `autophagy/회의록/…` 에 올라간다. 노트 frontmatter 에 `patent-sensitive` 태그는 붙지 않는다.
- **발표자료·참고자료에만 특허 내용이 있을 때**: 예전처럼 문서 전체가 민감으로 바뀌지 않는다. 자료는
  추출 재료로만 쓰이고 노트 머리 표에 이름이 남는다.
- **모델이 답하지 못할 때**: 주 모델과 폴백 체인이 모두 실패하면 예전처럼 exit 6 과
  「회의록 추출 실패」 통지로 멈춘다. 다른 경로로 조용히 답하지 않는다.

## 사라진 것

- `meeting_gate.py`, 스킬 사본 `configs/sensitivity-rules.yaml`, `meeting_cli.py gate` 하위명령,
  환경변수 `MEETING_RULES_FILE`, `meeting_llm.PatentRoutingError`, `meeting_slides.gate_text`.
- 결과 JSON·라우팅 로그의 `sensitive`·`tags` 필드, 통지의 「민감 문서」 표기, `DRIVE-PUBLISH-SKIP reason=sensitive`.
