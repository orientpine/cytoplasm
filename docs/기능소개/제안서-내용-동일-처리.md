# 제안서 내용 동일 처리

## 무엇을 · 왜

제안서 본문에 특허·기밀 등의 낱말이 있어도 초안, 코퍼스, 그림, 윤문, 렌더와 발행은 같은 경로를 쓴다.
낱말에 따라 자동 태그·인용 제외·모델 제한이 걸려 필요한 근거가 산출물에서 사라지던 처리를 없앴다.
모델은 계정 Hermes 설정의 주 모델과 폴백 체인을 사용한다.

## 사용 시나리오

- 특허 기술 연구를 요청한다 → research·corpus·compose·images·refine·render·publish를 같은 순서로 실행한다 → 근거와 본문은 그대로 처리되고 Drive 권한·SHA 재조회가 확인된다.
- 개인 노트 원문을 그대로 그림 프롬프트에 넣거나 잘못된 경로·심링크를 쓴다 → 출처·경로 경계가 거부한다. 문서 낱말에 따른 거부가 아니라 접근 보안이다.
- 출처 교차 검증이 실패한 근거를 렌더에 복사한다 → 인용 검증과 원문 누출 검사가 거부한다.

## 보존한 경계

출처 키 기반 개인 노트 원문 제한과 요약/인덱스 전달, 경로 검증, 0700/0600 파일 권한,
Drive owner-only 검사·SHA 재조회, 인증·승인, gitleaks·public_gate는 유지한다.
엔진의 PUBLIC/INTERNAL 인용 상태는 내용 분류가 아니라 주입된 출처 교차 검증 결과만 나타낸다.
기존 데이터는 그대로이며, 저장 파일과 게시 카드를 이관하거나 재처리하지 않는다.
