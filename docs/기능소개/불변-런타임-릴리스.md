# 불변 런타임 릴리스 (DG-3 · DG-5)

## 무엇을
프로덕션이 실행하는 코드를 **읽기 전용 릴리스 트리**로 옮겼다. `/srv/autophagy-agent-releases/<sha>/`는
0555/0444로 봉인된 커밋 스냅샷이고, `/srv/autophagy-agent-current`는 그중 하나를 가리키는 심링크다.
cron 워처·마운트 스킬·`peer_attest`·`deploy-skill.sh`는 모두 공용 리졸버로 이 경로를 찾는다:
`AUTOPHAGY_RUNTIME_ROOT` > `current`(있으면) > `/srv/autophagy-agents`(없으면).

## 왜
상주 체크아웃이 **배포 재료이자 동시에 런타임**이었다. 그래서 다른 세션의 미커밋 편집 하나가
배포를 막았고(→ [배포 스냅샷 핀](배포-스냅샷-핀.md)), 막힌 동안 프로덕션은 조용히 낡은 코드를
돌았다. 런타임을 불변 릴리스로 분리하면 상주 체크아웃은 **드리프트 관측소**로만 남고, 그 상태가
프로덕션 동작을 좌우하지 않는다.

## 사용 시나리오

### 정상 경로 (수렴)
1. `converge-release-runtime.sh`가 원하는 sha(호출자가 `RELEASE_EXPECTED_SHA`로 지정, 없으면
   현재 origin/main)를 정한다.
2. 스냅샷 안에서 트리를 tar로 말아 root 헬퍼 `autophagy-install-release`에 `sudo -n`으로 넘긴다.
   ops는 root 소유 헬퍼를 **실행할 뿐 root가 되지는 않는다**.
3. 헬퍼가 staging에 풀어 읽기 전용으로 봉인하고, 기준 커밋과 파일 집합·blob OID·실행 비트를
   대조한 뒤에만 `os.replace`로 릴리스 디렉터리를 확정하고 `current` 심링크를 **원자적으로**
   교체한다(install이 곧 flip).
4. `current --verify <sha>`(읽기 전용, sudo 불필요)로 심링크·`.origin-sha`를 대조한다.
5. 동시 수렴은 공유 `flock`이 직렬화한다 — 늦게 끝난 옛 수렴이 새 `current`를 과거로 되돌리지 못한다.

### 실패·거부 경로
- **`current` 자리에 심링크가 아닌 실제 디렉터리가 있으면** → `RELEASE-STORE-BLOCK`, 그 디렉터리는
  건드리지 않는다.
- **아카이브에 `..`·절대경로·심링크 멤버가 있으면** → 추출 거부(공급망 경계).
- **릴리스 트리가 group/other-writable이면** → `peer_attest`가 신뢰하지 않는다(변조 가드 전제).
- **동일 sha 재설치** → 멱등(같은 디렉터리 재사용, `.staging` 잔여 0).
- **새 tar 또는 기존 릴리스가 주장한 커밋과 다르면** → `os.replace`·심링크 전환 전에 거부한다.
- **세대·용량 증가** → 최근 5세대를 유지하고 healthcheck가 개수·총 바이트를 관측한다
  (→ [릴리스 리텐션·설치 검증](릴리스-리텐션-검증.md)).

### 롤백
`rm /srv/autophagy-agent-current` **한 줄**이면 모든 리졸버가 즉시 상주 체크아웃으로 되돌아간다.
릴리스 디렉터리는 참조되지 않은 채 남을 뿐 무해하다. 이 상태에서는 상주 체크아웃이 다시
프로덕션이므로, `land.sh`도 그때는 **옛 하드 계약**으로 되돌아간다(→ [단일 랜딩 명령](단일-랜딩-명령.md)).

## 주의
- `current`가 **깨진 상태**(끊어진 심링크·심링크가 아닌 항목)는 "롤백"이 아니라 **손상**이다.
  `[[ -e ]]`는 끊어진 심링크에 대해 거짓이라 순진한 리졸버는 이를 "부재"로 읽고 릴리스 노드를
  조용히 낡은 미러로 강등한다 — `land.sh`는 이 경우 랜딩을 거부한다.
- 릴리스는 읽기 전용이다. 런타임 상태(`~/.hermes/…`)를 그 안에 쓰지 않는다.
- 수리 systemd 유닛 이관(DG-5 4.4)은 repair 서브시스템 활성화 사이클로 이연됐다 — 현재 두 유닛은
  dormant이며 런타임 목표(cron·스킬·peer_attest·deploy-skill)는 이미 릴리스 위에서 돈다.
