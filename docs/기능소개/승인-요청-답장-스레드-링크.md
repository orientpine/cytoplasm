# 승인 요청 답장에 승인 스레드 링크 싣기 (전 스킬)

## 무엇을

에이전트가 승인 카드를 올리는 명령(mail `draft`·`compose`, todo `request`, calendar `post-confirm`,
budget `snapshot`, coordination 협상)은 게시 직후 승인 스레드 링크를 한 줄 더 출력합니다.
에이전트는 소유자에게 보내는 답장에 그 링크를 그대로 넣습니다.

```
REQUESTED hash=sha256:… target=tool:gws_tasks_mutation:gws
APPROVAL-THREAD hash=sha256:… url=https://discord.com/channels/<서버>/<스레드>
```

## 왜

2026-09-23 메일 발송 답장과 할 일 등록 답장이 "승인 스레드에서 ✅를 누르면 됩니다"라고만 말해,
소유자가 어느 스레드인지 직접 찾아야 했습니다. 스레드 좌표는 승인 레코드에 이미 저장돼 있었지만
명령 출력에는 없어 에이전트가 인용할 수 없었습니다. 코드가 보내는 통지는 「소유자 메시지 계약」이
위치를 강제하지만, 에이전트가 쓰는 답장은 그 봉투를 거치지 않습니다.

## 사용 시나리오

- **정상 경로**: "TechLibrary 영상 찍기 할 일에 추가해 줘"라고 요청하면 에이전트가 `request`를
  실행합니다. 답장은 "승인 스레드: <링크> 에서 ✅를 누르면 등록됩니다" 형태가 되고, 링크를 누르면
  바로 그 카드로 이동합니다.
- **좌표 미상**: 서버 좌표가 없는 옛 바인딩은 `url=unavailable search=<값>`으로 나옵니다.
  에이전트는 링크를 추측하지 않고 그 값으로 검색하라고 안내합니다.
- **앞으로 만드는 스킬**: 승인을 게시하는 새 생산자가 이 줄을 내지 않고 면제 사유도 적지 않으면
  단위 테스트가 실패해 머지되지 않습니다.

## 관련

- 단일 정의: `automation/interop/thread_pointer.py` `approval_thread_line`. 링크 형식은
  `owner_message.discord_link` 한 곳에서 만듭니다.
- 채택: mail·todo·calendar·budget·coordination. 면제: 위키·특허 내보내기(좌표 비노출 마스킹 규칙),
  공급망 승인(운영자 스크립트), no-agent 워처 경로.
- 강제: `tests/unit/test_approval_thread_pointer_conformance.py`. 규칙은 루트 AGENTS.md
  「승인 요청 답장 링크 규칙」, 절차는 `docs/guide/스킬-제작.md` 「승인 요청 답장 링크」에 있습니다.
- 승인 해시·게시 경로·리액션 판정은 바뀌지 않습니다. 줄에는 id와 URL만 실립니다.
