# 도리 기반 사이토플라즘 — 저장소 층

## 무엇을

cytoplasm 에 `dori/` 층이 생겼다. 도리 포크를 커밋 하나로 고정하고(`dori/pin.toml`), 소유자의 기본
도리 구성 — 리드 짱도리와 비서 유도리, 선택 역할 옥도리(카톡)·무도리(회사 업무·긴 문서)·공도리(연구) — 을 역할 템플릿과
아바타로 담는다. 설치 마법사에 「도리」 선택지가 생겨, 다른 설치자도 cytoplasm 하나로 그 구성을 받는다.

## 왜

소유자 결정(2026-10-18 00:10 KST): "나는 도리 기반의 사이토플라즘을 계속 배포하고싶은데, 내가 지금
구성한 기본 도리 구성을 배포하도록 하고, 기존 사이토 플라즘의 모든 기능이 녹아들면 좋겠어." Q219
"전부 추천대로 — 저장소 층부터 시작 (추천)" 으로 저장소 안 A(cytoplasm 이 제품, 포크는 커밋 고정
의존)를 골랐다.

그 전에는 도리 구성이 소유자 PC 의 로컬 폴더에만 있었고(원격 저장소 없음), 포크의 `install.sh` 는
main 을 그대로 pull 해 무엇이 깔리는지 서명 릴리스가 정하지 못했다.

## 사용 시나리오

**다른 설치자가 도리를 고른다.**

```text
$ python3 -m automation.install.wizard
== ⓪ 설치 방식 ==
    5. dori        도리 — 리드(짱돌)·비서(유돌) 기본 구성, 옥돌·무돌·공돌은 선택(root·신뢰키 불필요)
  선택 (번호 또는 이름) [1]: 5
== ① 도리 설치 계획 — 쓰기·네트워크 없음, root 불필요 ==
DORI-PIN repo=https://github.com/orientpine/omo-dori-mode-experimental.git commit=d03905e4…
1. dori-fork ~/.dori/src 에 d03905e40a28 을 받고 SHA 를 확인한다
…
  위 계획대로 도리를 설치한다. 진행하려면 yes 를 입력한다: yes
DORI-PIN-OK ~/.dori/src d03905e4…
DORI-INSTALLED pin=d03905e40a28 roles=lead,yoodori kept=0
```

리드·비서 폴더에 `AGENTS.md`(역할 규칙)와 `avatar.md`(아바타 프롬프트)가 생기고, `dori` CLI 가 링크된다.
각 역할의 소유자 원본 그림 `avatar.jpg`(메타데이터 지움)는 저장소의 `dori/roles/<역할>/` 에 함께 있지만 설치기는 깔지 않는다.
남은 일은 `~/.dori/dori.env` 에 그 설치자의 봇 토큰·채널·소유자 id 를 넣는 것뿐이다. 소유자 실명·id·
채널은 하나도 따라오지 않는다.

**이미 도리를 쓰는 사람이 다시 돌린다.** 고쳐 쓴 `AGENTS.md` 는 바이트 그대로 두고 템플릿과의 차이만
보여 준다(`DORI-ROLE-KEEP`). 포크 체크아웃이 고정 커밋이 아니면 아무것도 하지 않고 멈춘다
(`DORI-PIN-SRC-DIFFERS`).

**고정값이 틀렸다.** `DORI-PIN-FETCH-FAIL …` 한 줄과 exit 3 으로 멈추고, 아무 폴더도 남기지 않는다.

**릴리스 뒤.** 배포 영수증에 `"dori_pin": {"repo": …, "commit": …}` 가 실려, 그 릴리스가 어떤 도리
커밋을 정했는지 영수증으로 확인한다.

**연구용 도리를 더한다(2026-10-29).** 연구 과제가 있는 설치자는 `--role gongdori`(마법사는
`--dori-role gongdori`)로 공도리(애칭 공돌)를 고른다. `~/Documents/gongdori/` 에 강화학습 실험 운영·
가설 탐색·주간 연구동향 지침과 아바타 프롬프트가 생긴다. 과제 이름·학습 노드·채널은 그 설치자의
`notes/`·설정에만 두며 템플릿에는 없다. 아바타는 소유자 원본 그림·프롬프트다.
