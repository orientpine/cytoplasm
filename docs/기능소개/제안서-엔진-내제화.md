# 제안서 엔진 내제화

## 무엇을

한글 연구계획서를 만드는 **렌더 엔진이 이 저장소 안으로 들어왔다**(`skills/proposal/engine/`).
`proposal render`·`corpus`·`visual-review` 는 이제 외부 체크아웃을 부르지 않고 같은 프로세스에서
그 코드를 직접 실행한다. 고정 SHA 핀(`PROPOSAL_DOCBOT_PIN`), 외부 경로(`PROPOSAL_DOCBOT_ROOT`),
그리고 어긋났을 때 렌더를 닫던 `ENGINE-PIN-BLOCK` 이 모두 사라졌다.

## 왜

엔진을 한 줄 고치는 데 4단 의식이 붙어 있었다 — 엔진 저장소 커밋·푸시 → 이 저장소 3개 파일의 핀
전진 → PR → 노드 런타임 env 갱신. 하나라도 어긋나면 렌더가 통째로 닫혔고, 2026-09-07 한 세션에서만
그 핀 전진을 두 번 했다. 이제 저장소 하나만 고치면 된다.

내제화가 가능했던 이유는 실측이다: 엔진이 **실제로** 쓰던 서드파티는 pydantic 하나뿐이었고
(`anthropic`·`python-docx`·`pypdf` 는 렌더 경로에서 실행되지 않는 함수 내부 import, `python-hwpx` 는
선언만 되고 import 0건), 그 pydantic 도 "frozen + 타입힌트" 수준이라 이 저장소 관례인
`@dataclass(frozen=True)` 로 옮겨졌다. 그래서 **메인 트리 stdlib 전용 불변식이 깨지지 않았다** —
스코프 venv 도, 프로비저너도, AGENTS.md 예외도 필요 없다.

## 사용 시나리오

**정상 경로.** 평소와 같다. 달라진 것은 핀을 맞출 일이 없다는 점뿐이다.

```bash
python3 -m skills.proposal.scripts.proposal_cli render --slug <slug> --json
```

산출물 manifest 의 `engine_sha` 는 이제 외부 저장소의 HEAD 가 아니라 **엔진 소스와 양식의 내용
digest** 다. 손에 든 체크아웃만으로 재현되므로, 어느 엔진이 그 문서를 만들었는지 다른 저장소 없이
판정할 수 있다.

**거부 경로.** `skills/proposal/engine/` 이나 그 안의 양식 seed 가 없으면 preflight 가 `ENGINE-BLOCK`
(exit 4)으로 닫는다. 엔진이 반쯤 있는 체크아웃으로 렌더가 시작되지 않는다.

## 관련

- 엔진: `skills/proposal/engine/`(진입점 `render.py` 의 `render_hwpx`·`engine_digest`)
- 경계 회귀: `tests/unit/test_proposal_engine_in_tree.py`(엔진 실재·양식 동봉·서드파티 0·진입점),
  `tests/unit/test_proposal_engine_pin.py`(핀 기계가 배포 표면에서 사라졌다는 기계 검사)
- 계획·실측: `.omo/plans/docbot-internalization.md`
- 공개 범위: 엔진 트리는 `configs/public-export-manifest.txt` 로 공개 내보내기에서 제외된다 —
  원본 저장소가 비공개였으므로 이 변경이 공개 자세를 조용히 바꾸지 않게 했다. 공개 승격은 소유자 판단이다.
