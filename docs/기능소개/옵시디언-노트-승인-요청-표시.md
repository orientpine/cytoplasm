# 옵시디언 노트 승인 요청 표시 — 스레드 이름과 카드가 스스로 승인 요청임을 말한다

## 무엇을

Obsidian 노트를 vault 에 쓰기 전 소유자 ✅ 를 받는 승인 요청(라이프로그 노트·MEMORY 재배치)이
`#agent-chat` 에 스레드를 열 때, **스레드 이름**이 `옵시디언 노트 승인 요청 · <노트 파일명>` 이 되고
그 안의 **승인 카드**는 첫 줄에 `옵시디언 노트 승인 요청: **<노트 제목>**` 을 적은 뒤 승인·수정 요청·취소를
서로 다른 줄로 나눠 안내한다.

```text
옵시디언 노트 승인 요청 · 2026-09-08 라이프로그 회의 준비.md      ← 채널에 보이는 스레드 이름 (41자)

옵시디언 노트 승인 요청: **노트 승인 화면 검토**
[PLAUD lifelog | plaud-sync-render-v4]
- 대상 노트: `000_PARA/Area/Lifelog/2026/2026-09-08-….md`
…
승인(✅): 이 메시지에 반응 → 요약+전문을 Obsidian vault에 저장하고 recall 검색에 인제스트
수정 요청: 승인 대신 이 스레드에 수정할 내용을 답글로 남겨 주세요
취소(⛔): 이 메시지에 반응 → 저장 취소
```

## 왜

수리 티켓 t_8a159de8(2026-09-08 소유자): "옵시디언 노트 스레드를 만들 때 현재 안내가 '스레드를
시작했다'는 사실만 표시되어, 사용자가 노트 승인 요청인지 명확히 인지하기 어렵다."

원인은 **Discord 가 채널에 남기는 시스템 메시지가 스레드 이름밖에 싣지 않는다**는 데 있다. 스레드를
열기 전 소유자가 보는 글자는 그 이름 하나뿐인데, 예전 이름은 `옵시디언 · <녹음 id>` 여서 '승인' 이라는
낱말도, 무슨 노트인지도 없었다. 즉 카드 본문을 아무리 잘 써도 **스레드를 열기 전에는 읽히지 않는다**.
카드 쪽도 승인·취소가 한 문장에 붙어 있었고 수정 요청 경로는 아예 적혀 있지 않았다.

## 사용 시나리오

1. **happy**: 라이프로그 녹음이 전사되어 노트가 동결되면 `#agent-chat` 에
   `옵시디언 노트 승인 요청 · 2026-09-08 라이프로그 회의 준비.md` 스레드가 열린다 → 소유자는 채널 목록만
   보고 "노트 승인이 대기 중" 임을 안다 → 스레드를 열면 카드 첫 줄이 같은 사실을 노트 제목과 함께 반복하고,
   ✅ 를 누르면 저장·RAG 인제스트, ⛔ 면 취소.
2. **수정 요청**: 요약이 마음에 들지 않으면 ✅ 를 누르는 대신 그 스레드에 답글을 남긴다. 카드가 그 방법을
   승인·취소와 **다른 줄에** 적으므로 세 선택지가 섞이지 않는다.
3. **긴 노트 이름**: 이름은 `<라벨> · <제목≤40자>` 를 다시 100자로 자른다. 60자 파일명도 56자로 잘려
   Discord 의 100자 상한에 걸리지 않는다.
4. **MEMORY 재배치**: `memory_relocate` 도 같은 kind 를 쓰므로 같은 이름 규칙을 그대로 받는다.

## 관련

- 스레드 이름: `automation/interop/approval_surface.py` — `KIND_LABELS[OBSIDIAN_WRITE]` 가
  `"옵시디언 노트 승인 요청"` 이고 `request_thread_name` 은 그대로 `<라벨> · <제목≤40>`[:100] 이다.
  **다른 kind 라벨은 바이트 그대로**이고 `POLICY_VERSION` 도 8 에서 움직이지 않는다 — 표면 facts 가
  바뀌지 않으므로 저장된 승인 레코드 해석·리액션 워처·리마인더가 전부 무변경이다.
- 제목 출처: 생산자 `automation/plaud_sync/effects_live.py`·`automation/memory_relocate/effects_live.py`
  가 `RequestThread(title=PurePosixPath(record.note_relpath).name)` 으로 **파일명만** 넘긴다(디렉터리·본문
  제외). AGENTS.md 「요청별 승인 스레드 규칙」의 마스킹 표도 그렇게 갱신됐다 — `#agent-chat` 은 소유자
  전용 비공개 표면이라 노트 파일명이 그 채널을 벗어나지 않는다.
- 카드: `automation/plaud_sync/render.py` `_render_v4` — 첫 줄 `옵시디언 노트 승인 요청: **<note_title>**`,
  끝에 승인(✅)/수정 요청/취소(⛔) 3줄. `action_hash` 바인딩은 손대지 않는다(카드는 표시일 뿐이다).
  렌더러는 append-only 버전형이라 `plaud-sync-render-v3` 문구는 동결된 채 그대로 재생된다.
- 회귀: `tests/unit/test_approval_surface.py`, `tests/unit/test_request_thread_adoption_conformance.py`,
  `tests/unit/test_plaud_sync_effects.py`, `tests/unit/test_memory_relocate_effects_live.py`,
  `tests/unit/test_plaud_sync_render.py`.
- 배포 주의: interop 런타임과 스킬이 함께 올라가야 한다(「요청별 승인 스레드 규칙」의 배포 순서) —
  릴리스 승인의 전량 수렴이 둘을 같이 올린다.
