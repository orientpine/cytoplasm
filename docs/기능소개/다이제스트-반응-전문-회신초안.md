# 기관메일 다이제스트: 📄 누르면 전문, ✍️ 누르면 회신 초안

## 무엇을
게이트웨이가 없어도 [20초 반응 전용 타이머](다이제스트-게이트웨이-없는-반응.md)가
같은 실행 경로를 호출한다(P5). 2분 전체 틱은 안전망으로 유지한다.
기관메일 다이제스트 스레드의 메일 카드마다 봇이 📄·✍️ 반응을 미리 달아 둔다. 형이 📄 를 누르면 그 메일의 전문과 첨부 이름이, ✍️ 를 누르면 그 메일의 회신 초안이 같은 스레드에 올라온다. 누른 즉시(몇 초 안) 시작한다(2026-10-17).

## 왜
2026-10-16 소유자 지시: "기관메일 다이제스트에서 이모지를 내가 클릭하면 회신 초안을 자동으로 써주고 혹은 전문을 자동으로 보여주는 이모지를 넣어주고". 다이제스트 카드는 요약만 보여 주므로 전문을 보거나 초안을 받으려면 에이전트에게 따로 말해야 했다.

2026-10-17 소유자 지시(음성): "다이제스트 왔을 때 이모지 달면 반응이 너무 느려 즉각적으로 반응할 수 있겠죠". 처음 판본은 2분 크론 틱만 반응을 읽어서 누른 뒤 1.5~4분 걸렸다(10/17 실측: 10:40:50 틱이 📄 3건을 10:42:46~10:43:07 KST 에 처리). 이제 게이트웨이가 이미 열어 둔 Discord 연결에서 반응을 바로 듣고 그 카드만 처리한다 — 새 서비스·새 연결은 없다.

## 사용 시나리오
- **전문 보기**: 아침 다이제스트의 「3. 연구 장비 점검 안내」 카드에서 📄 를 누른다 → 몇 초 안에 그 메일만의 새 스레드 `📄 전문 · 연구 장비 점검 안내` 가 열리고(맨 위 큰 제목) 거기에 본문(원문 인용 포함)이 올라오며, 길면 `(1/3)`처럼 나뉘고, 마지막에 `📎 첨부 2건 (이름만)` 목록이 붙는다. 다이제스트 스레드의 카드 아래에는 `📄 전문은 별도 스레드에 있습니다: <링크>` 한 줄만 남아 다른 카드와 섞이지 않는다(2026-10-17 소유자 "전문이 너무 길어 다른 거랑 섞여 — 스레드를 별도로 파서"). Discord 는 스레드 안에 스레드를 만들 수 없어 전문 스레드는 다이제스트 스레드와 같은 채널(#agent-chat)에 선다.
- **📄 를 다시 누르면**: 새 스레드를 만들지 않고 같은 스레드 링크 한 줄을 다시 남긴다.
- **회신 초안**: 같은 카드에서 ✍️ 를 누른다 → 곧바로 `✍️ 회신 초안을 쓰고 있습니다 — 1분쯤 걸려요…` 한 줄이 카드 아래에 붙고(모델이 쓰는 데 시간이 걸리므로), 초안이 만들어지고 평소의 메일 승인 카드(요청별 승인 스레드)가 올라오며, 다이제스트 스레드에는 `✍️ 회신 초안을 썼습니다 · draft …` 미리보기와 승인 카드 링크가 남는다. **이 단계에서는 메일이 나가지 않는다** — 승인 카드에서 ✅ 를 눌러야 보내고, ⛔ 면 버린다.
- **지시를 담고 싶을 때**: 반응 대신 그 카드에 답장(Reply)으로 요지를 적는다(기존 기능).
- **두 번 눌러도**: 같은 카드의 같은 반응은 한 번만 실행된다. 반응을 지웠다 다시 눌러도 다시 올라오지 않는다.
- **다른 사람이 누르면**: 무시한다. 형 계정(봇 아님)의 반응만 센다.
- **실패하면**: 다음 틱에 최대 3회 다시 시도하고, 전문 일부가 이미 올라간 뒤의 실패는 되풀이하지 않는다(같은 글이 두 번 보이지 않게). 도중에 실패하면 다음 시도가 이미 연 스레드에서 이어 간다(스레드가 둘 생기지 않게). 3번째도 실패하면 `⚠️ 📄 전문을 3번 시도했지만 가져오지 못했습니다…` 를 카드 아래에 남겨 조용히 사라지지 않게 한다.
- **게이트웨이가 멈춰 있으면**: 20초 경량 타이머가 반응만 읽는다(최근 3일·틱당 20장 순환). 2분 전체 틱도 안전망으로 남으며 같은 `digest_actions` claim으로 중복 실행을 막는다.

## 관련
- 코드: `skills/mail/scripts/digest_reaction_actions.py`(반응 판정·실행), `triage_digest.run_digest`(반응 미리 달기·카드 채널 기록), `automation/interop/digest_reaction_listener.py`(게이트웨이 인터롭 플러그인이 기존 Discord 연결에 `on_raw_reaction_add` 를 붙여 형의 📄/✍️ 를 들으면 `mail_triage_watch.py --digest-card <id>` → `triage_cli digest-react` → `run_card` 를 바로 실행; agent 계정에서만, 끄기 `DIGEST_REACTION_LISTENER=0`, 처리마다 `~/.hermes/mail-triage/logs/digest-reaction-events.jsonl` 에 받은 시각·끝난 시각·초를 남긴다), `triage_cli.cmd_watch`(기존 `mail-triage-watch` 2분 틱 — 안전망), `triage_store`(`digest_actions` 표·`digest_items.channel_id`·카드별 전문 스레드 `digest_body_threads`), `automation/interop/origin_notice.resolve_thread_id`(전문 스레드 열기·큰 제목, 이름 앞말 `전문` → 📄).
- 승인: ✍️ 초안은 기존 `draft` 경로와 메일 발신 승인 카드를 그대로 쓴다 — 새 승인 표면·새 워처 없음.
