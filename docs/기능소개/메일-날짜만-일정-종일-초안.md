# 메일의 날짜만 있는 일정을 종일 일정 초안으로

아침 메일 다이제스트가 '날짜는 있고 시각은 없는' 일정(연차평가일, 서류 제출 마감 등)도
종일(all-day) 일정 초안 카드로 올린다. 노드 운영자가 릴리스 스위치로 켜며, 기본값은 지금과 같다
(날짜와 시각이 둘 다 있어야 초안).

## 왜

분류 프롬프트(`triage-classify-v1.md`)는 날짜와 시각이 본문에 둘 다 있을 때만 일정 문장을 돌려주고,
캘린더는 시각 없는 문장을 되묻기(exit 5)로 돌려보낸다. 그래서 평가일·마감일 메일은 다이제스트에
`🗓️ 일정 예정 · 날짜 미정` 줄만 남고 승인 카드가 없었다. 기능은 PR #185 의 제안이고, 같은 PR 의
오류 수정·재검증만 별도로 맡겨졌다(Q361). 켜는 것은 아래 릴리스 스위치의 승인으로 따로 정한다.
초안을 만드는 때는 그대로 아침 다이제스트 한 번이다.

## 켜고 끄기

릴리스 호스트의 운영자 계정에서 줄바꿈 없이 `on`만 쓴다. 다른 값·공백·빈 파일은 거부한다(exit 4).

```bash
mkdir -p ~/.hermes/release-flags
printf %s on > ~/.hermes/release-flags/mail-schedule-all-day
chmod 600 ~/.hermes/release-flags/mail-schedule-all-day
```

기존 [릴리스 절차](../guide/manual-maintainer.md)를 따른다. 릴리스 카드에
`메일 다이제스트: 날짜만 있고 시각이 없는 일정(평가일·제출 마감)도 종일 일정 초안 카드로`가
표시되고 `mail-schedule-all-day:on` 표면과 HEAD가 승인에 묶인다. 승인 뒤 선언된 `push_file`이
노드 `~/.hermes/mail-schedule-all-day.mode`(0600)에 `on`을 쓰고 다시 읽어 확인한다.
다른 HEAD의 승인으로는 켤 수 없다.

파일을 지우고 다음 승인 릴리스를 하면 `off`가 배포되어 예전 동작으로 돌아간다. 표식이 없거나
`off`이면 분류 프롬프트는 바이트 그대로고, 캘린더는 날짜 하나만 있는 시각 없는 문장을 예전처럼 되묻는다
(날짜 범위·`종일`은 스위치와 상관없이 종일 — [일정 카드 선택과 날짜 읽기](일정-카드-선택과-날짜-읽기.md)).
노드 표식이 깨졌으면 메일 쪽은 `MAIL-SCHEDULE-ALL-DAY-MARKER-INVALID`를 남기고 꺼진 것으로 다룬다
(다이제스트는 멈추지 않는다).

## 사용 시나리오

1. "가상 과제 연차평가 일정 안내 — 11월 18일 연차평가" 같은 메일이 온다.
2. 다음 날 08:00 다이제스트에서 분류기가 `schedule_text = "11월 18일 연차평가"`를 돌려준다
   (켜짐일 때만, 시각을 지어내지 않는다는 규칙과 함께).
3. 메일 쪽이 캘린더에 `CALENDAR_ALL_DAY_UNDATED=1`을 넘기고, 캘린더는 노드 표식도 `on`인지
   다시 확인한 뒤 종일 초안을 만든다. Google 명령은 `start.date=11-18`, `end.date=11-19`
   (Google 규칙대로 끝 날짜는 다음 날, 제외)이고 기본색 스위치가 켜져 있으면 색도 함께 동결된다.
4. 다이제스트 메일 카드에는 `🗓️ 일정 초안 → [승인 카드] · 11/18(수) 종일 연차평가`가 보이고
   (2026년 기준), 그 아래 답글로 승인 카드가 붙는다. ✅면 종일 일정이 생긴다.

여러 날이면 `12월 22일~23일 겨울학교` → `12/22(화)–12/23(수) 종일`. 끝 날의 달을 적으면 연말을 넘길 수
있다(`12월 30일~1월 2일` → 다음 해 1월 2일까지).

지어내지 않고 되묻거나 거부하는 경우(→ 다이제스트에는 `날짜 미정` 줄):

- 시각이 있는 일정은 예전처럼 시각 일정이다. 날짜가 없거나 모호한 일정(`11월쯤`)은 되묻는다.
- 연도 없이 쓴 날짜가 올해 이미 지났으면(`10월 20일 제출 마감`을 10월 23일에 받음) 내년으로 넘기지 않고
  되묻는다. 연도를 적은 지난 날짜(`2026-10-20`, `2025년 11월 18일`)와 끝 날이 시작보다 빠른 범위는 거부한다.
  연도가 날짜에 붙어 있지 않으면(`11월 18일 평가 (2025년 공고)`) 되묻는다.
- 끝 날 대신 기간을 쓴 문장(`11월 18일부터 3일간`, `3일 동안`, `2박 3일`, `2주간`)은 끝 날을 되묻는다.
- `오전`·`오후`만 있고 시각 숫자가 없는 문장(`11월 18일 오후 연차평가`)은 시각을 되묻는다.
- 자정부터 자정까지인 시각 일정(`내일 자정부터 24시간 서버 점검`)은 종일이 아니다. 요약·다이제스트·카드
  모두 `00:00 ~ 00:00` 시각으로 보인다. 종일 표시는 Google 명령이 실제로 날짜형(`start.date`)일 때뿐이다.

소유자 Discord 지시("11월 18일 연차평가 잡아줘")는 이 스위치와 상관없이 지금처럼 시각을 되묻는다.
날짜 범위(`12월 9일(수)~10일(목)`)나 `종일`을 쓴 문장은 어느 경로든 종일 일정이다(2026-10-30).
환경 변수는 메일 다이제스트만 넘긴다.

## 알아둘 점

- 새 종일 초안은 캘린더 승인 카드 판본 v6 으로 게시되고 `시작`·`종료`를 사람이 보는 첫·마지막 날로
  보여 준다(`시작: 2026-11-18 (종일)` / `종료: 2026-11-18 (종일)`; Google 저장값의 끝은 다음 날). v1~v5 카드의
  렌더는 바꾸지 않았으므로 이미 게시·저장된 카드는 다시 그려도 바이트가 같고, 승인 해시(초안 `sha256`)도
  판본과 무관하게 같다. 기본색 스위치가 켜져 있으면 v6 카드에 색 줄도 붙는다.
- 메일 쪽은 캘린더가 `DIGEST-CARD` 줄에 날짜형(`start=2026-11-18 end=2026-11-19`)을 줄 때만 `종일`로 적는다.
  초안 레코드의 시작·끝은 그대로 KST 자정이라 같은 일정 판별(`event_key`)은 바뀌지 않는다.
- 캘린더는 환경 변수가 없으면 스위치 모듈을 불러오지 않고, 메일 쪽은 코드 트리에 스위치 모듈이 없으면
  `MAIL-SCHEDULE-ALL-DAY-UNAVAILABLE`을 남기고 꺼진 것으로 다룬다. 스킬과 코드 트리가 따로 갱신돼도
  소유자 지시·분류가 멈추지 않는다.
- 종일 표시가 세 표면에서 맞으려면 메일·캘린더 스킬이 둘 다 이 판이어야 한다. 한쪽만 옛 판이면 꺼짐이거나
  되묻기로 안전하게 남지만, 스위치를 켠 채 한쪽만 바꾸면 다이제스트 줄이 시각으로 보일 수 있다.
- 같은 날 비슷한 일정 확인(Q62, PR #163)은 종일 초안을 그날 00:00~24:00 구간으로 보고 시각 있는 기존
  일정과 비교한다. 이미 있는 종일 일정끼리의 비교는 #163 의 범위 밖이다.
