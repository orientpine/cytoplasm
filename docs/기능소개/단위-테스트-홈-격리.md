# 단위 테스트 홈 격리 — `pytest tests/unit` 이 개발자 `~/.hermes` 에 아무것도 남기지 않는다

## 무엇을

`tests/unit/conftest.py` 가 수집이 시작되기 전에 `HOME` 을 일회용 디렉터리
(`tempfile.mkdtemp(prefix="autophagy-unit-home-")`)로 바꾸고 `XDG_CONFIG_HOME`·`XDG_CACHE_HOME`·
`XDG_DATA_HOME`·`XDG_STATE_HOME` 을 지운다. 이 일은 import 시점에 해야 한다. 여러 모듈이 import 되는
순간 `Path.home()` 을 평가해 게이트 기본 경로를 굳히기 때문이다. 환경을 물려받는 자식 프로세스도
같은 HOME 을 쓰고, 프로세스가 끝나면 그 디렉터리는 통째로 지워진다. env 를 새로 만들어 자식을
띄우는 테스트는 `HOME` 을 직접 넘겨야 한다 — 빠지면 자식이 passwd 의 실제 홈으로 되돌아간다.
`tests/unit/test_unit_home_isolation.py` 가 이 배선을 고정한다.

## 왜

승인 게이트들(`calendar`, `wiki`, `entity-preflight` 등)은 `CALENDAR_GATE_DIR` 같은 override 가 없으면
`~/.hermes/<kind>-gate` 에 쓴다. 단위 스위트의 스무 개 남짓한 파일이 그 override 없이 `create_draft`
류를 불렀고, 결과는 개발자 홈의 **실제** 게이트에 초안이 쌓이는 것이었다. 지난 사이클에는 읽는 쪽
(카드 게시 백스톱이 그 초안에 닿지 않게)만 막았고 쓰는 쪽은 남겨 두었다.

실측으로 크기를 쟀다. HEAD `5e1239b7e` 에서 일회용 HOME 으로 전체 스위트를 돌리자 그 홈에
파일 19개가 생겼다(`.hermes/calendar-gate`, `wiki-gate`, `entity-preflight`, `skill-gate`,
`supply-chain-watch`, `mail-triage`, `meeting`, `patent-prep`, `proposal-status`,
`transcript-pipeline.lock`, `.config/gws/cache`, `proposals/demo`). conftest 를 넣은 뒤 같은 방식으로
전체 스위트(7944건 통과)를 돌리니 0개였다. 같은 트리에서 1575건 부분 스위트를 두 번 돌려 대조하면
`--noconftest` 는 13개, conftest 는 0개를 남긴다(증적 `docs/qa/UNIT-HOME-0911/01-unit-home-isolation.txt`).

## 사용 시나리오

1. **happy** — `pytest tests/unit` 또는 `automation/local_ci.sh run` 을 돌린다. 테스트가 어떤
   게이트에 쓰든 모두 `/tmp/autophagy-unit-home-*` 아래로 가고, 끝나면 사라진다. `~/.hermes` 는
   실행 전과 같다.
2. **가드가 잡는 경우** — 누군가 `conftest.py` 를 지우거나 HOME 교체를 약하게 만들면
   `test_unit_home_isolation.py` 가 실패한다(`Path.home()` 이 passwd 홈과 같거나 시스템 temp 밖이면
   실패). `pytest --noconftest tests/unit/test_unit_home_isolation.py` 로 그 실패를 직접 볼 수 있다.

## 이미 쌓인 잔재 정리 (소유자 선택 · 워크스테이션에서만)

이 기능은 앞으로의 오염을 막을 뿐이고, 이미 쌓인 것은 지우지 않는다. 그 디렉터리에는 실제 요청과
테스트 잔재가 섞여 있을 수 있어 소유자 데이터로 취급한다. 정리하려면 워크스테이션에서, 먼저 보고,
지우지 말고 옮긴다.

```bash
# 1) 먼저 본다 — 어떤 것이 얼마나 있는지
for d in calendar-gate wiki-gate entity-preflight; do
  printf '%s\t' "$d"; find ~/.hermes/$d -type f | wc -l
done

# 2) 삭제 대신 이름을 바꿔 옮긴다 — 되돌릴 수 있게
for d in calendar-gate wiki-gate entity-preflight; do
  mv ~/.hermes/$d ~/.hermes/$d.test-residue-$(date +%F)
done
```

**에이전트 노드에서는 절대 하지 않는다.** 그곳의 `~/.hermes/*-gate` 는 살아 있는 승인 상태
(pending 초안, lease, posting journal)이고, 옮기면 진행 중인 요청이 사라진다. 이 절차는 테스트를
돌린 개발자 워크스테이션의 홈에만 해당한다.
