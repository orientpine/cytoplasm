# 과제별×년도별 예산 시트 (budget 다중 시트 레지스트리)

## 무엇을

budget 스킬이 여러 과제의 년도별 예산 시트를 한꺼번에 조회·감시한다. 시트 목록은 repo 밖
레지스트리 `~/.hermes/budget/sheets.json`이 정의하고, Drive에서는 각 시트가
`autophagy/예산/<년도>/` 아래에 놓인다.

## 왜

기존에는 `BUDGET_SHEET_ID` 하나 — 과제가 둘 이상이거나 해가 바뀌면 감시가 한 시트에 묶였고,
원장 시트는 내 드라이브 루트에 흩어져 있었다. 이제 과제×년도 단위로 시트를 등록하면 30분
tick이 전부 순회하고, 단일 산출물 트리의 년도 폴더에 정리된다.

## 사용 시나리오

1. **등록**: `~/.hermes/budget/sheets.json`에
   `{"version":1,"projects":{"무인굴착기":{"2026":"<sheet-id>"}}}` 형식으로 추가
   (형식 예시: `configs/budget-sheets.example.json`). 레지스트리가 생기면 그것이 유일한
   소스다 — `BUDGET_SHEET_ID`가 미등재로 남아 있으면 exit 3으로 거부된다(조용한 추적 누락 방지).
2. **조회**: `!budget` → `budget_cli.py query --project 무인굴착기 [--year 2026]`.
   다과제인데 `--project`가 없으면 exit 2로 알려진 과제 목록을 안내한다.
   `budget_cli.py sheets`는 활성 시트를 ID 마스킹으로 나열한다.
3. **감시·승인**: 30분 tick이 전 시트를 순회하며 시트별로 스냅샷 diff → 변경 시 승인 요청.
   승인 키가 시트 스코프라 두 과제가 같은 tick에 변해도 승인 메시지가 서로를 대체하지
   않는다. 승인 메시지·요청 메일에 `과제 (년도)`가 표기된다.
4. **실패 경로**: 한 시트의 읽기 실패는 그 시트만 재시도 큐(`[과제/년도] …`)에 남고
   나머지는 계속 처리된다(exit 4). 레지스트리 JSON이 깨지면 전체가 fail-closed(exit 3)다.
5. **Drive 배치**: `python3 -m automation.drive_migrate_outputs --apply`(소유자 실행)가
   레지스트리 전 항목을 등록 년도 폴더로, 레거시 `BUDGET_SHEET_ID`를 현재 년도 폴더로
   옮긴다(멱등). 스킬은 시트를 ID로 읽으므로 이동해도 동작이 바뀌지 않는다.

레지스트리가 없으면 기존 `BUDGET_SHEET_ID` 단일 모드가 그대로 동작한다(완전 후방호환 —
스냅샷 스트림·claim 키 포맷 불변).

## 관련

- 스킬: `skills/budget/` (`budget_registry.py` 신규, CLI `query --project/--year`·`sheets`)
- 이동 CLI: `automation/drive_migrate_outputs.py` (예산/<년도>/ 목적지)
- 규약: `docs/guide/과제비-운영.md` §6 · `docs/guide/drive-publish.md`
- 회귀: `tests/unit/test_budget_registry.py` · `tests/unit/test_budget_multisheet.py`
- 승인 게이트: 기존 `budget_approval` 재사용(키만 시트 스코프) — 새 워처·표면 없음
