# 제안서의 근거·일정·렌더 결과를 맞춘다

## 무엇을 · 왜

코퍼스에서 계획을 만들고 HWPX로 렌더할 때 소수점, 과제별 담당, 월 구간이 사라지던 문제를 고쳤다.
그림 크기와 양식 판정도 보강해 계획에는 맞는데 문서가 다른 일정이나 과도한 용량으로 나오는 일을 줄인다.

- `TensorFlow 2.13` 같은 숫자·버전을 문장 경계에서 자르지 않는다.
- 작업 담당은 같은 출처의 같은 과제 안에서 찾고, 추진 구간마다 작업 패키지를 만든다.
- 착수·종료 월을 구조 필드로 보존한다. 병렬 작업은 기간을 중복 합산하지 않고 중간 공백은 유지한다.
- 레이아웃 프로파일은 공개 계약 한 곳에서 읽고 그 바이트도 엔진 지문에 포함한다.
- 필요한 PNG를 본문 배치 폭에 맞게 줄인다. 비정상 크기·압축 입력은 자원 상한으로 거부한다.
- 중첩 문단 삭제, 양식 절 별칭, 기존 문단 렌더 API는 각각 회귀로 보호한다.

## 사용 시나리오

**정상:** 코퍼스에 서로 다른 과제의 담당과 `5~7개월 준비, 6~14개월 평가`가 있다.
계획은 해당 과제의 담당을 선택하고, 첫해 표에는 준비 5~7월과 평가 6~12월을 그린다.
두 작업이 모두 1~12개월이면 표지와 연차 표가 쓰는 총기간도 12개월이다.
월 필드가 없는 기존 계획은 종전의 서술 구간·순차 배치로 읽힌다.

**거부·보류:** 착수·종료 월이 한쪽만 있거나 기간과 어긋나면 계획을 거부한다.
담당 근거가 모호하면 다른 과제의 이름을 빌려 채우지 않는다.
수동으로 조립한 버전 폴더의 manifest가 없으면 VersionStore 생성 여부를 확인하도록 안내한다.
윤문 입력에는 여유를 두되 기존 출력 상한은 그대로 지킨다.

생성된 제안서 문장은 공용 용어 교정 엔진을 쓰고 근거 원문은 보존한다.
로컬 렌더는 모델·네트워크 없이 실행할 수 있지만 Drive 발행과 모델 호출의 기존 승인·민감도 규칙은 유지된다.

## 적용 범위 · 관련

비공개 개발본의 엔진 기준이며 엔진 공개 범위는 넓히지 않았다.
