# 검색·전사·메모리 자동화의 내용 분류 제거

검색 결과, 전사본, 라이프로그, 판단 근거와 메모리를 문서 내용으로 분류하지 않는다.
특허·기밀 같은 낱말이 있어도 같은 검색, 추출, 큐레이션과 계정 모델 경로를 사용한다.
키워드 때문에 근거가 빠지거나 모델 호출을 건너뛰고 추가 승인을 요구하던 문제를 없앤다.

## 사용 시나리오

- `recall search "특허 일정" --json`: 정상 검색 임계값을 충족한 근거를 원문 그대로 반환한다.
  모델 설정 파일을 읽어 결과를 가리거나 표시를 덧붙이지 않는다.
- 화자 수 질의와 라이프로그 추출: 옵트인 설정과 모델을 사용할 수 있으면 모든 초안을
  같은 계정 설정으로 처리한다. 모델이나 프롬프트가 없으면 기존 오류 계약을 따른다.
- Obsidian 노트의 위키 후보·판단 트윈 추출·메모리 재배치: 문서 내용에 따른 제외가 없다.
  중복·빈 본문·주간 상한·근거 검증은 유지하며 실제 저장과 삭제는 기존 승인·해시 검증을 따른다.
- 발명 신고 초안: 자동 내용 태그와 제공자 제한 없이 계정 주 모델·폴백을 사용한다.
  반출은 여전히 소유자 승인, 대상 해시, 만료, 단일 사용 nonce와 목적지 ACL을 검증한다.

## 유지하는 보안

| 장치 | 유지 이유 | 회귀 테스트 |
|---|---|---|
| 경로·slug·심링크 검증, 실행 사본 가드 | 허용된 자원만 읽고 쓴다 | `test_patent_prep_skill.py`, `test_patent_export.py`, `test_governed_copy_guard_conformance.py` |
| 소유자 승인·거부 우선·해시·만료·nonce·ACL·암호화 | 외부효과의 인가와 대상 무결성 | `test_patent_export.py`, `test_patent_export_watch.py`, `test_memory_relocate_apply.py` |
| 자격증명 감지와 로그 마스킹 | 비밀을 모델·운영 로그에 전달하지 않는다 | `test_memory_curator_classify_veto.py`, `test_codex_llm.py`, `test_interop_protocol.py` |
| 엔티티 모호성 확인과 PII 감사 저장소 | 수신자·일정 대상의 정확성과 접근 통제 | `test_entity_preflight_gate.py`, `test_entity_preflight_audit.py`, `test_entity_preflight_e2e.py` |
| 크기·프롬프트 상한, 런타임 파일 권한 | 입력과 상태 저장 경계를 지킨다 | `test_stt_speaker_ask.py`, `test_plaud_sync_lifelog_extract.py`, `test_rag_ingest_pipeline.py` |
| 실제 응답 제공자·모델 기록 | 폴백으로 누가 답했는지 확인한다 | `test_served_route_logging.py` |
| staging 인증·하드 예산 | 내용과 관계없는 사용 권한과 지출 상한 | `test_litellm_content_dispatch.py` |

엔티티 감사의 `sensitive_*` 이름은 PII 접근 통제용 기존 데이터 계약이며 문서를 분류하지 않는다.
지식 팩은 분류 필드를 저장하지 않으며 새 근거와 로더도 분류값을 넣지 않는다.
공유 보고의 경로·이메일·토큰·계정 식별자 마스킹과 예산 결과의 메타데이터 전용 계약은 유지한다.

기존 데이터는 그대로 둔다. 과거 별도 저장 파일, 게시된 승인 카드와 저장된 노트를 이관하거나
재처리하지 않는다. 프롬프트의 독립 `<<<PROMPT>>>` 마커 아래 본문은 그대로이며,
분류 게이트를 설명하던 머리말만 정리했다.
