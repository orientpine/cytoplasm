# 공개 릴리스 컷

## 무엇을

`automation/public_export.sh` **한 번의 실행**이 private 개발 저장소의 한 커밋을 공개
배포본으로 내보냅니다. fresh-history 스냅샷 커밋을 만들고, **그 커밋에** 업데이트
신뢰키로 서명한 annotated 릴리스 태그를 붙이고, 커밋과 태그를 `push --atomic`으로 함께
보냅니다. 그 뒤 사용자 노드가 2분 안에 그 태그를 검증하고 수렴합니다.

절차 전문(사전조건·매니페스트 원장·키 회전·나쁜 릴리스 대응)은
[플랫폼 운영자 매뉴얼](../guide/manual-maintainer.md)이 소유합니다.

## 왜

공개 배포에는 서로 다른 두 요구가 동시에 있었습니다. ① private 이력·QA 증적·개인
운영 문서는 나가면 안 된다 ② 그런데도 사용자 노드는 받은 코드가 **진짜 유지보수자의
것**임을 검증할 수 있어야 한다.

①을 위해 공개본은 fresh history로 냅니다. 그런데 그러면 private의 커밋 SHA가 공개
저장소에 존재하지 않으므로, private에서 미리 서명한 태그는 **공개 저장소에 없는 객체를
가리킵니다.** 사용자 노드는 `refs/heads/main`과 같은 커밋을 가리키는 서명 태그만
후보로 삼기 때문에, 그 상태에서는 검증할 태그가 아예 없어 자동 업데이트가 **연합
전체에서** 멈춥니다(`UNSIGNED-HEAD`).

그래서 커밋 생성·서명·push를 사람이 나눠 할 수 없게 **한 스크립트 안에 묶었습니다.**
순서를 지키는 것이 규율이 아니라 구조가 됩니다.

## 사용 시나리오

- **정상 컷**: 변경을 private `origin/main`에 랜딩한 뒤 스크립트를 1회 실행합니다.
  스크립트가 워킹트리 clean·비-shallow·태그 미중복을 확인하고 → private 트리와 전체
  이력을 gitleaks로 스캔하고(스캔 직전 카나리아 2개를 심어 **스캐너가 실제로 읽었는지**
  먼저 증명합니다) → 스냅샷을 전개해 매니페스트 제외 항목을 지우고 → 내보낸 트리에서
  `pytest tests/unit`을 다시 돌리고 → 커밋·서명·자체 `verify-tag`·atomic push·원격
  read-back까지 마친 뒤 `PUBLIC-EXPORT-OK` 한 줄로 끝납니다. 실측(v1.0.0): 내보낸
  트리에서 `3902 passed`, gitleaks 4개 스캔 전부 0건.
- **거부 — 랜딩을 잊었을 때**: 워킹트리에 미커밋 변경이 있으면
  `PUBLIC-EXPORT-BLOCK: source worktree is dirty; commit or remove every change first`로
  시작조차 하지 않습니다. 공개본에 git에 없는 바이트가 실리는 경로를 원천 차단합니다.
- **거부 — 새 문서를 원장에 기록하지 않았을 때**: `configs/`·`docs/guide/`·`docs/patch/`
  아래 새 파일은 제외 매니페스트나 공개 원장 둘 중 하나에 반드시 있어야 합니다. 없으면
  내보낸 트리에서 돌리는 `pytest`가 실패해 **릴리스가 멈춥니다** — 조용히 공개되지
  않습니다.
- **거부 — 대상을 잘못 지정했을 때**: 대상 원격이 private origin으로 해석되면
  `destination resolves to the private source origin`, 대상 디렉터리가 private 워킹트리
  안이면 `target must be outside the private source working tree`로 멈춥니다.
- **컷 이후**: GitHub Release 노트에 신뢰키 지문을 재게시합니다(신규 설치가 **설치기가
  아닌 경로로** 대조하는 대역외 값입니다). 사용자 노드는 2분 타이머에서 태그를 검증하고
  `current`를 전환한 뒤 게이트웨이 재시작·스모크까지 성공해야 확정하며, 실패하면 자동
  롤백 후 그 설치의 소유자에게 1회 알립니다.
- **나쁜 릴리스**: 옛 태그를 다시 올려 되돌릴 수 **없습니다.** 롤백 방지 floor가
  `RELEASE-ROLLBACK`으로 거부합니다(공격자 강제 다운그레이드 방어 — 비대칭은 의도된
  것입니다). 취소는 문제를 revert해 private에 랜딩하고 **더 높은 버전**을 컷하는 것입니다.
