# H5 위생 배치

## 무엇을

최종 품질 감사, mail·wiki 배포 시나리오, 승인 표면 계획, 온보딩 복구 문서의 네 가지
위생 격차를 한 번에 닫는다. 프로덕션 기능이나 승인 경로는 바꾸지 않는다.

## 왜

F2는 CI와 달리 수정하지 않는 vendor 트리를 lint해 감사 신호를 흐렸고, mail·wiki 시나리오는
배포 전 unit suite에서 실행되지 않았다. AS-R3 S5에는 이미 폐기된 producer를 전제로 한 라이브
절차가 남았으며, 노드 재구축 때 대시보드 자격증명 조회 alias를 복원할 안내도 온보딩 킷에 없었다.

## 사용 시나리오

- **Happy path**: PR에서 unit suite와 F2를 실행하면 mail·wiki 시나리오가 checkout 밖의 tmp
  runtime에서 signed-confirm까지 통과하고, F2는 repository 소유 코드만 lint해 green이 된다.
- **실패/거부**: 부모 프로세스에 Discord 자격증명이 있어도 테스트 자식은 명시적 화이트리스트만
  받는다. `INTEROP_RUNTIME`을 staging하지 않으면 signed-confirm 단언이 실패한다. S5는 제품에
  없는 강제 재초안 옵션을 만들지 않고, 폐기된 live leg를 `NOT_APPLICABLE/retired`로 남긴다.
- **복구**: 노드 재구축 후 `docs/guide/onboarding-kit.md` §9에서 alias 복구 정본을 찾아간다.
  실제 자격증명 값은 mode-600 파일 밖으로 출력·기록하지 않는다.
