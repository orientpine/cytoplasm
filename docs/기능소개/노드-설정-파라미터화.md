# 노드 설정 파라미터화

## 무엇을

노드 이름, SSH 대상, Unix 계정, `/srv` 계열 경로, Hermes gateway 유닛명과 signed-update 정책을
`NodeConfig` 하나로 해석합니다. Python은 `automation/node_config.py`, 셸은
`automation/node_config_sh.py --print-env`를 사용하며 systemd·sudoers는 같은 값으로 렌더합니다.

## 왜

배포·헬스체크 코드에 한 설치의 호스트명과 계정이 직접 들어 있으면 다른 연구자가 자기
노드에서 실행할 수 없습니다. 반대로 기존 설치에서 값을 바꾸면 운영 회귀가 생기므로,
추적 시드와 무설정 기본값은 기존 운영값을 그대로 유지합니다. 잘못된 TOML·미지 필드·상대
경로는 추측하지 않고 실행 전에 거부합니다.

## 사용 시나리오

- **기존 설치**: `~/.hermes/node.toml`이 없으면 `configs/node.example.toml`의 worked example을
  그대로 읽습니다. 기존 호스트·계정·경로와 동일하게 동작합니다.
- **새 설치**: example을 `~/.hermes/node.toml`로 복사해 노드명·계정·경로를 바꾸고
  `require_signed_updates = true`로 설정하면 배포, reconcile, healthcheck와 렌더된 systemd·sudoers가
  같은 값을 사용합니다. 런타임 파일에서 이 필드를 생략해도 secure default는 `true`입니다.
- **거부 경로**: TOML 문법 오류, 알 수 없는 필드, 상대 경로 또는 잘못된 계정·유닛명은
  `NodeConfigError`로 fail-closed 종료합니다.

## 관련

- 계획: W-F1-A
- 시드: `configs/node.example.toml`
- 로더·셸 브리지: `automation/node_config.py`, `automation/node_config_sh.py`
- 자산 렌더러: `automation/node_asset_renderer.py`
- 승인 게이트 의미는 변경하지 않으며, 운영 랜딩·재시작은 별도 소유자 감독 단계입니다.
