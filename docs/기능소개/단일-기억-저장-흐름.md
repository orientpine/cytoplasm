# 단일 기억 저장 흐름

## 무엇을

명시적인 기억 요청을 한 번만 분류하고, 그 결과 하나로 canonical 저장소와 허용된 보조
저장소를 순서대로 처리한다. 프로젝트 지식은 위키, 짧고 안정적인 전역 선호는 위키와
`MEMORY.md`, 재사용 절차는 skill, 임시 상태는 tasks/session으로 보낸다.

## 왜

같은 요청을 저장소마다 다시 판단하면 위키와 `MEMORY.md`에 불필요하게 이중 기록되거나,
민감도·임시 상태 정책이 저장 경로별로 달라질 수 있다. 단일 흐름은 최초 `MemoryRoute`를
모든 어댑터가 공유하게 하고 canonical 결과를 먼저 확정해 이런 우회를 막는다.

## 사용 시나리오

### 안정적인 전역 선호

1. cha가 “앞으로 답변은 항상 짧은 한국어를 선호해. 기억해줘”라고 요청한다.
2. 진입점은 요청을 정확히 한 번 분류해 `wiki` canonical과 `memory_md` co-write를 얻는다.
3. 기존 owner-gated 위키 CLI가 먼저 초안을 만들고, 성공 또는 이미 존재하는 중복으로
   판정된 경우에만 `MEMORY.md` 어댑터가 짧은 사실을 기록한다.
4. 결과에는 저장소별 `success|duplicate|rejected|retryable_failure|not_attempted`가 남아,
   무엇이 기록됐고 무엇이 기록되지 않았는지 정확히 안내할 수 있다.

동일 요청을 재시도하면 각 어댑터가 본문에서 만든 동일한 content key로 중복을 감지한다.
canonical을 다시 만들지 않고, 앞서 실패한 보조 저장만 재시도할 수 있다.

### 거부·부분 실패

- 민감 요청에 별도 승인이 없으면 어떤 저장 어댑터도 호출하지 않고
  `sensitive_rejected`로 끝난다.
- canonical 저장이 실패하면 보조 저장은 `not_attempted`다.
- canonical이 성공한 뒤 보조 저장만 실패하면 `partial_failure`와 두 저장소의 개별 결과를
  함께 반환한다.
