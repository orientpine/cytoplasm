# 메모리 승격 확인 종결

## 무엇을

메모리 큐레이터가 이미 `reconciled` 또는 `abandoned`로 종결한 승격의 확인 메시지에 처리 완료 표기를 덧붙이고, 대응 위키 초안을 durable archive로 옮긴다. 새 승인 메시지나 워처를 만들지 않고 기존 큐레이터 tick의 리마인더 단계 바로 앞에서 수행한다.

## 왜

승격 처리가 끝나도 확인 메시지와 `saved` 초안이 남아 소유자 DM에서 미처리 승인처럼 보였다. 그러나 메시지 삭제·재게시는 원문과 `action_hash`, 이미 누른 반응을 잃을 수 있다. 따라서 상태·초안·메시지의 교차 바인딩을 전부 확인한 뒤 원문을 보존하는 append-only 편집만 허용한다.

## 사용 시나리오

- **정상**: 소유자가 메모리 승격을 승인하고 큐레이터가 위키 저장과 자체 메모리 회수를 마친다 → 다음 tick이 `draft_id`, 메시지 ID, promotion key·slug·노트 해시, 원격 `action_hash`를 모두 대조한다 → 확인 메시지 끝에 처리 완료가 한 번만 붙고 초안은 `archive/` 영수증으로 보존된다.
- **불일치·취소**: 초안이 이미 소멸했거나 어느 바인딩 하나라도 다르다 → `UNBOUND`로 OWNER 원장에만 남기고 메시지 편집·archive를 모두 수행하지 않는다. 고아 메모리 초안은 `closure_cli --dry-run`의 `ORPHAN` 목록으로만 보이며 outbox를 재사용하지 않는다.
- **사전 점검**: 격리된 `MEMORY_CURATOR_STATE`와 `WIKI_GATE_DIR`를 지정하고 `python3 -m automation.memory_curator.closure_cli --dry-run`을 실행한다 → `CLOSE`·`UNBOUND`·`ORPHAN` 목록과 요약을 출력하되 파일 바이트는 바꾸지 않는다.
