# 기관메일 다이제스트: 읽기 쉽게 정리하고 메일마다 바로 회신하기

## 무엇을

- 아침 기관메일 다이제스트는 채널에 **머리글 메시지 하나**만 올린다. 메일은 그 머리글에 단 스레드 안에 **메일당 메시지 하나**씩 올라가므로, 20건이 와도 채널은 조용하다.
- 카드에는 사람 이름만 보이고, 참조는 `A, B, C 외 N명`으로 줄여 보여 준다.
- 메일 메시지에 Discord **답장(Reply)** 으로 회신 요지를 적으면, 그 메일의 회신 초안이 기존 승인 카드로 올라온다.

## 왜

2026-10-07과 10-08 다이제스트가 깨져 보였다. 원인은 세 가지였다.

1. 발신과 참조 이름이 `\"이름\"`처럼 역슬래시가 겹쳐 보였다. 웹메일이 이미 이름을 따옴표로 감싸 주는데, 메일 파일에 쓰면서 YAML 이스케이프가 한 번 더 붙었다. 다이제스트는 그 겹을 벗기지 않은 채 Markdown 이스케이프를 다시 얹었다.
2. 본문 전체를 2,000자마다 잘라 보냈기 때문에 카드가 주소나 낱말 중간에서 끊겼다.
3. 카드마다 `UID`와 `발신(마스킹) sha256:…` 같은 내부 값이 보였고, 참조 목록은 주소까지 모두 펼쳐져 있었다.

회신하려면 "N번 메일…"이라고 번호를 다시 적어야 했고, 번호가 몇 번째 다이제스트를 가리키는지도 모호했다.

## 사용 시나리오

**다이제스트 읽기.** 08:00에 `#agent-chat`에 머리글(건수와 회신 방법)이 오고, 그 스레드 `📬 기관메일 다이제스트 10-08 08:00 · N건` 안에 메일 카드가 하나씩 올라온다. 스레드를 열 수 없는 DM 폴백에서는 카드가 같은 채널에 이어서 올라온다. 머리글은 ✅를 요청하지 않는다.

```
### 3. 회의 일정 문의
-# ↩️ 이 메시지에 답장하면 회신 초안 · 회신 키 `1008-0800-3`
🔴 중요 · ↩️ 회신 필요
> 요약 · 다음 주 회의 참석 여부를 묻는 메일
수신 10-08 08:10 · 발신 홍길동
참조 김가상, 이가상, 박가상 외 2명
```

**메일별 회신.** 스레드 안의 위 메시지에 답장으로 "목요일 오후 참석 가능하다고 회신"이라고 적는다. 에이전트는 답장 문맥에 있는 회신 키로 다음 명령을 실행한다.

```
triage_cli.py reply-request --key 1008-0800-3 --author-id <내 id> --instruction "목요일 오후 참석 가능하다고 회신"
```

그러면 그 메일의 회신 초안이 요청별 승인 스레드에 ✅/⛔ 카드로 올라오고, 에이전트의 답장에는 그 스레드 링크가 실린다. 실제 발송은 카드의 ✅ 뒤 `watch`가 한다. 보낸편지함 중복 검사와 영수증 기록도 기존 경로와 같다.

**거부되는 경우**

| 상황 | 결과 |
|---|---|
| 다른 사람이 답장함 | `REPLY-REQUEST-IGNORED not-owner` (exit 2). 초안을 만들지 않는다. |
| 같은 메일에 다시 답장함 | `초안이 이미 있음` (exit 2). 두 답장이 동시에 와도 잠금 때문에 초안은 하나만 생긴다. |
| 예전에 쓰던 키나 지어낸 키 | `REPLY-REQUEST-UNKNOWN` (exit 3) |

## 관련

- 이름 정리: `skills/mail/scripts/mail_contacts.py`
- 카드 렌더와 메시지 분할: `skills/mail/scripts/triage_digest.py`의 `render_item`, `render_digest_parts`
- 회신 키 저장: `triage_store.digest_items`의 `reply_key`·`message_id` 열. 기존 DB에는 열을 자동으로 추가한다.
- 명령: `triage_cli.py reply-request`. 내부적으로 `draft`와 같은 승인 카드 생산자 `triage_approval.request_approval`을 쓴다.
- 회귀 테스트: `tests/unit/test_mail_digest_reply.py`. 합성 이름만 쓰고, 노드에서 본 이스케이프 모양을 그대로 재현한다.
- 승인 게이트: 새 게이트는 없다. 채팅 메시지의 ✅는 승인이 아니다.
