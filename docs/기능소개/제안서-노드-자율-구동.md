# 제안서 노드 자율 구동 — 노드의 agent 가 v11 수준 제안서를 스스로 쓴다

## 무엇을

`proposal` 스킬이 워크스테이션 없이 **노드의 agent 계정만으로** 제안서 파이프라인 전체를 돌릴 수 있게 한
묶음이다. 세 가지가 새로 생겼다.

- **codex 이미지 전송기** — `PROPOSAL_IMAGE_TRANSPORT=codex` 이면 그림을 OpenAI API 키가 아니라
  소유자의 Codex OAuth 세션으로 만든다. `codex exec` 가 내장 `image_gen` 도구(gpt-image-2)를 호출하고,
  스킬은 결과 PNG를 기존 캐시·매니페스트 경로에 태우며, 원장에는 전송기별 청구 주체(codex →
  `chatgpt-subscription`, USD 0, 건수)를 기록해 `PROPOSAL_IMAGE_MONTHLY_CAP_USD`를 소비하지 않는다.
- **엔진 프로비저너** `automation/proposal_engine_provision.sh` — 핀 고정된 kimm-docbot 렌더 엔진과
  im-not-ai 윤문 호스트를 노드에 내려놓고 `~/.env.secrets` 에 `PROPOSAL_*` 를 멱등 upsert 한 뒤, 노드에서
  `proposal_config.py --preflight` 가 `ok: true` 인지 read-back 한다.
- **preflight 확장** — `images` 단계는 키 없이도 `codex` + `~/.codex/auth.json` 이 있으면 present 이고,
  새 `visual-review` 단계가 페이지 미리보기용 브라우저(`PROPOSAL_PREVIEW_CHROME` 또는 후보 탐색)를 보고한다.

## 왜

2026-08-31 실측에서 노드에는 엔진 체크아웃도, `PROPOSAL_*` env 도, 이미지 키도, 윤문 호스트도, Chrome 도 없었다 —
v1~v11 렌더는 전부 워크스테이션에서 돌았다. 소유자 결정은 「제안서 작업은 autophagy-agent 가 수행하며
kimm-docbot 과는 무관하다(KD 는 핀으로 부르는 엔진일 뿐)」이므로, 엔진은 **노드가 GitHub 자격증명 없이**
받을 수 있어야 한다. kimm-docbot 저장소는 private 이라 프로비저너가 워크스테이션에서 핀 커밋을
`git bundle` 로 실어 보낸다 — 유지보수는 `configs/env.example` 의 `PROPOSAL_DOCBOT_PIN` 을 올려 착지한 뒤
스크립트를 다시 돌리는 것으로 끝난다.

Chrome 은 노드가 aarch64 이고 ops 에 root 가 없어 apt 로 넣을 수 없다. Playwright 의 사용자공간
`chromium-headless-shell` 을 agent 홈(`~/.cache/ms-playwright`)에 설치했고 누락 라이브러리 0 으로
한글 HTML → PDF 스모크를 통과했다. 엔진 쪽 `visual_preview` 는 `KIMM_DOCBOT_CHROME` 을 먼저 읽고
`google-chrome → chromium → chromium-browser → chrome` 순으로 후보를 찾는다. 노드의 다른 chromium 두 벌(revision 1228)은
2026-07-14 `npx playwright install`이 만든 Hermes 브라우저 도구 자산이므로, 제안서 것은 `chromium_headless_shell-1234`뿐이고 삭제할 것은 없다.

## 사용 시나리오

**정상 경로 — 노드 프로비저닝.** origin/main 체크아웃에서 한 번 돌린다.

```bash
automation/proposal_engine_provision.sh --dry-run     # 핀·번들·env 키 계획만 출력
automation/proposal_engine_provision.sh \
  --chrome /home/agent/.cache/ms-playwright/chromium_headless_shell-1234/chrome-linux/headless_shell
```

노드 agent 홈에 `~/kimm-docbot`(핀 detached, `uv sync --frozen`)과 `~/.hermes/im-not-ai`(핀,
`./install.sh --codex-only`)가 생기고, `~/.env.secrets` 에 `PROPOSAL_DOCBOT_ROOT/PIN`,
`PROPOSAL_REFINE_ROOT/PIN`, `PROPOSAL_IMAGE_TRANSPORT=codex`, `PROPOSAL_ROOT`,
`PROPOSAL_PREVIEW_CHROME`, `KIMM_DOCBOT_CHROME` 이 한 줄씩만 남는다. 마지막에 노드 preflight JSON 이 찍힌다.

**정상 경로 — 그림 생성.** 노드 agent 가 `codex login` 이 된 상태에서
`proposal_cli images --slug <slug>` 를 돌리면 `figures.json` 의 프롬프트마다 codex 가 PNG 를 만든다.
`proposal_cli preflight --json --stage images` 가 `present` 일 때만 진행한다.

**거부 경로.** 핀이 자리표시자(0×40)거나 로컬 KD 체크아웃에 핀 커밋이 없으면 `ENGINE-PIN-BLOCK`(exit 4),
노드 체크아웃이 더러우면 `ENGINE-DIRTY-BLOCK`(exit 5), im-not-ai 설치 실패는 `REFINE-INSTALL-BLOCK`(exit 6),
노드 read-back 이 `ok: true` 가 아니면 exit 7 로 멈춘다. codex 가 PNG 를 내지 못하면 이미지 단계는
`ImageGenerationError` 에 codex 출력 꼬리를 실어 실패하고 원장은 예약을 되돌린다.

**남는 소유자 몫.** ① 노드 agent 의 Codex OAuth(`codex login`) — 이미지와 윤문 둘 다 이 세션을 쓴다.
② proposal CLI는 시작 시 `proposal_env.py`로 `~/.env.secrets`의 `PROPOSAL_*`·`KIMM_DOCBOT_*`를 fill-only로
읽어 첫 실행도 재시동 없이 된다. gateway 자신의 env 갱신은 여전히 재시동(agent·peer 함께)으로 한다. ③ 바뀐 스킬은 `deploy-skill.sh proposal` 승인 ✅.
