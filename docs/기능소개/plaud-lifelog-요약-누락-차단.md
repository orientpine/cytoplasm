# 라이프로그 노트의 요약이 비지 않게 하기

## 무엇을

PLAUD 라이프로그 노트의 `## 요약` 이 비는 경로 네 가지를 막았다. 모델이 요약을 배열로
답해도 받아들이고, 요약이 정말 없으면 요약만 다시 묻고, 그래도 없으면 **왜 없는지**를
노트에 적는다.

## 왜

2026-09-04 녹음(64분, 로컬 전사)의 노트는 사람 18명·장소 3곳·결정 4건·할 일 7건이
전부 채워졌는데 `## 요약` 만 `- (요약 없음)` 이었다. 추출 호출은 성공했고 요약만
사라진 것이다. 원인은 넷이었다.

| 경로 | 무엇이 일어났나 |
|---|---|
| 배열 응답 | 프롬프트가 "마크다운 불릿 3–6개" 를 요구하는데, 모델이 그 요구를 JSON 배열로 답하면 파서가 문자열이 아니라는 이유로 통째로 버렸다 |
| 빈 요약 | Plaud 요약도 없고 첫 추출의 summary 도 비면 그대로 얼렸다 — 다시 물어보지 않았다 |
| 거절문 | 복구 호출이 JSON 을 못 내면 아무 산문이나 요약으로 받아들일 수 있었다 |
| 사유 없음 | `- (요약 없음)` 만으로는 모델이 죽은 것인지, 게이트가 막은 것인지, 녹음이 빈 것인지 구별할 수 없었다 |

## 사용 시나리오

**happy path** — 녹음이 동기화되면 평소처럼 한 번의 모델 호출로 사람·장소·결정·할 일·
요약을 함께 받는다. 요약이 채워져 있으면 **추가 호출은 없다**(호출 수 불변).

**요약이 빈 경우** — Plaud 요약도 없고 첫 추출도 요약을 주지 못하면, 전사본만 담은
좁은 요청(`prompts/lifelog-summary-v1.md`)이 한 번 더 나가 요약만 만든다. 승인 카드의
미리보기도 그 요약을 인용하므로 소유자는 ✅ 전에 내용을 볼 수 있다.

**그래도 없는 경우** — 노트의 한눈에 줄에 이렇게 적힌다.

```
- 요약:: 없음 (모델이 전사본에서 요약을 만들지 못함)
```

게이트로 건너뛴 경우의 `- 추출:: 생략 (민감도 게이트)` 와 구별된다. 무엇을 고쳐야
하는지가 노트만 봐도 갈린다.

**거부 경로** — 복구 호출이 "요약할 수 없습니다" 같은 산문으로 답하면 그것은 요약이
아니므로 받지 않는다. 빈 요약보다 나쁜 것은 내용이 있는 척하는 요약이다.

## 이미 만들어진 노트를 고치려면

`written`(과 `abandoned`)은 녹음이 영원히 멈추는 자리였다 — 틱도 `store.pending()` 도 다시
보지 않으므로, 낡은 코드가 만든 노트를 다시 만들 길이 없었다. 이제 노드에서 한 줄이면 그
녹음 하나만 처음부터 다시 돈다.

```bash
sudo -n -u agent bash -lc \
  'python3 ~/.hermes/scripts/plaud_sync_watch.py --reprocess <녹음 id>'
```

오디오 재다운로드 → 로컬 전사 → 추출 → 승인 카드가 다시 돌고, **노트 경로는 녹음 id 에서
나오므로** ✅ 하면 같은 파일이 새 내용으로 덮어써진다. 카드는 그 녹음이 이미 갖고 있는
스레드로 가고, 옛 카드는 지우지 않는다 — 소유자가 실제로 누른 결정의 기록이다. 진행 중인
요청(`transcribing`·`planned`·`posted`·`approved`)에는 듣지 않는다(`refused`).

요약이 비어 있고 전사본의 낱말이 조각나 있는 그 노트(2026-09-04 녹음)가 이 명령의 첫
대상이다. 녹음 id 는 `plaud 상태` 나 노트 frontmatter 의 `source` 줄에서 읽는다. 재처리하면 둘 다 이번 사이클의 코드로 다시
만들어진다. **이 커밋이 노드에 배포된 뒤에** 실행해야 한다("커밋됨 ≠ 배포됨").

## 관련

- 코드: `automation/plaud_sync/lifelog_extract.py`(`_summary`·`summarize`),
  `automation/plaud_sync/lifelog_extract_live.py`(복구 배선),
  `automation/plaud_sync/lifelog_fields.py`(`NO_SUMMARY_REASON`)
- 프롬프트: `prompts/lifelog-summary-v1.md` (배포 자산 — 없으면 복구가 조용히 꺼지므로
  회귀 테스트가 존재를 고정한다)
- 승인 게이트: 변경 없음. 노트 본문이 곧 `body_sha256` → `action_hash` 이므로 요약이
  채워진 노트가 그대로 소유자 ✅ 에 바인딩된다.
- 모델 경로: 기존 Codex OAuth 단일 티어 그대로. 다른 제공자로 내려가지 않는다.
- 재처리: `automation/plaud_sync/repost.py`(`reset_for_reprocess`·`reprocess`), 워처 플래그 `--reprocess <id>`
