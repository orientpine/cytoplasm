# 유돌 — 카드 승인 할 일의 근거 메일 첨부 꺼내기·Drive 저장

## 무엇을
형이 카드로 승인한 대시보드 할 일이면, 유돌의 할 일 레인이 형에게 한 줄을 다시 받지 않고 그 할 일의 근거 메일
첨부를 꺼내고(`mail-attachment`), 글로 읽고(`mail-attachment-text`), 형 Drive 에 저장한다(`drive-save`).
노드 게이트 명령 끝에 형 글 좌표 대신 `--origin-todo <할 일 id>` 를 붙인다.

## 왜
소유자 2026-11-03 06:09 KST Q2 "고친다: 카드 승인 할 일도 근거로 받음 (따로 PR, 추천)"(Q454·Q455: 카드로 승인한
할 일은 바로, 카드 없이 자동으로 들어온 건 쓰기 전에 물음). 문지기(dori-gate)는 같은 결정을 `X-Dori-Owner-Todo` 로
받았지만 노드 게이트의 형 명령 잡은 형 디스코드 글 좌표만 받아, 할 일 레인이 근거 메일 첨부를 꺼내려 하면
`YOODORI-GATE-REFUSED owner-command jobs end with --origin-channel-id N --origin-message-id N` 으로 막혔다.

## 사용 시나리오
- 형이 메일에서 뽑힌 할 일 제안 카드에 ✅ → 대시보드에 할 일이 열린다 → 유돌 할 일 레인이
  `mail-attachment <근거 메일 uid> <첨부 이름> --origin-todo <할 일 id>` → 노드가 대시보드에 묻고 카드와 형 ✅ 를 확인한 뒤
  사용 한 번을 기록하고 첨부를 비공개 staging 에 복사한다(`STAGED …`) → `drive-save --file <그 staged 파일> --summary <설명>
  --origin-todo <할 일 id>` 로 형 Drive 에 저장한다(스위치 `auto-write-drive-save` 가 켜진 노드, 카드 없음).
- 거절(`YOODORI-GATE-REFUSED`, 아무것도 읽거나 쓰지 않고 사용 기록도 없음):
  - 할 일의 근거가 아닌 메일·첨부, 그 메일 첨부가 아닌 staged 파일(같은 이름으로 다른 바이트를 올려도 노드가 메일함에서
    다시 복사한다).
  - 자동 반영된 할 일(카드 없음), 카드 좌표가 대시보드 기록과 다름, 완료·보류, 승인 24시간 지남.
  - 카드가 이 노드 봇의 글이 아님, 형 본인 계정(봇 아님)의 ✅ 가 없음, 형 ⛔ 가 있음, 카드를 못 읽음.
  - 대시보드에 묻지 못함, 사용 기록 실패, 잘못된 id.
  - 다른 명령(메일 쓰기·문서·전사·일정 등)에 `--origin-todo`. 바깥으로 나가는 일(메일 발송·공유)은 지금처럼 ✅ 카드다.
  - drive-save 스위치가 꺼진 노드(할 일로는 카드를 올리지 않는다).
