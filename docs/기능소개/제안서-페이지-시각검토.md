# 제안서 페이지 시각 검토

## 무엇을

최종 HWPX를 페이지별 PNG와 PDF로 펼쳐 에이전트가 문서를 **직접 보며** 시인성을 판단한다.
양식 판형, 글꼴, 들여쓰기, 표, 그림 크기, 캡션과 떠있는 그림 뒤의 본문 채우기를 QA 화면에
반영한다.

## 왜

기존 검증은 문단 길이·불릿 비율·그림 수·쪽수 같은 수치에 치우쳤다. 그래서 테스트가 모두
통과해도 제목만 남은 쪽, 표 머리글 고립, 큰 공백 같은 결함을 사용자가 먼저 발견했다.
임시 미리보기 도구도 최신 그림 배치를 인라인으로 잘못 표시해 공백을 과장했다.

## 사용 시나리오

**정상 경로.**

```bash
python3 -m skills.proposal.scripts.proposal_cli visual-review \
  --slug excavator --json
```

현재 버전의 HWPX SHA에 묶인 `pages` 목록이 나온다. 에이전트는 목록의 PNG를 전부 열어 제목
고립, 그림 전용 쪽, 표 머리글 분리, 공백, 페이지별 밀도 편차를 확인한다. 같은 HWPX는 기존
결과를 재사용하고 불변 버전 안의 파일은 바꾸지 않는다.

**거부 경로.** 엔진 SHA가 핀과 다르거나 체크아웃이 더러우면 `ENGINE-PIN-BLOCK`으로 멈춘다.
Chrome·`pdftoppm` 실행이 실패하거나 페이지 이미지가 하나도 없으면 성공으로 보고하지 않는다.

이 미리보기는 시각 QA용이다. 한/글의 정밀 렌더링과 제출용 PDF 내보내기를 대신하지 않는다.

## 관련

- 스킬 진입점: `skills/proposal/scripts/proposal_visual_review.py`
- 페이지 렌더러: kimm-docbot `hwpx/visual_preview.py`
- 사용자 계약: `skills/proposal/SKILL.md`
- 출력: `~/.hermes/proposal/visual-reviews/<slug>/<version>/<hwpx-sha256>/`
