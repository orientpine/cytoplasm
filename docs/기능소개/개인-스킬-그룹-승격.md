# 개인 스킬 그룹 승격

## 무엇을

팀원이 자기 개인 스킬의 **깨끗하게 커밋된 한 HEAD**를 sha 고정 tarball과 관리형 스킬
매니페스트 v1로 묶어 그룹 관리자에게 검토 요청할 수 있다. 관리자가 승인한 제출물만
기존 `publish_cli.py`의 입력이 될 수 있으며, 실제 발행은 기존 deploy 승인·publish 승인·
서명 태그 파이프라인을 그대로 거친다.

## 왜

기존에는 팀원이 검증한 개인 스킬을 그룹에 제안하는 표준 경로가 없었다. 파일을 임의로
복사하면 검토한 바이트와 발행 바이트가 어긋나고, 제출을 곧바로 import하면 한 팀원의
실수가 그룹 공급망으로 자동 전파된다. 이 기능은 **제출**, **관리자 검토**, **발행**을
분리해 그 두 위험을 막는다.

## 사용 시나리오

### 정상 경로

1. 팀원이 개인 repo를 커밋하고 `submission_cli`를 실행한다.
2. 기존 `personal_provenance_check`가 dirty·untracked·detached 상태를 거부하고, 통과한
   HEAD에서만 tarball과 `ManagedManifest` v1을 만든다.
3. 두 첨부파일의 sha가 묶인 요청이 기존 공급망 승인 표면에 한 번 게시된다.
4. 관리자가 첨부와 매니페스트를 검토해 ✅한 뒤 `publish_cli --submission-*`를 직접 실행한다.
5. `publish_cli`가 제출 승인과 현재 roster를 재검증하고, 기존 두 발행 게이트를 모두 통과한
   뒤에만 관리형 repo에 커밋·서명 태그·push한다.

### 실패·거부 경로

- 개인 repo가 dirty이거나 untracked 파일이 있으면 패키지를 만들지 않는다.
- tarball 또는 매니페스트가 게시 전후 바뀌면 sha 불일치로 관리자 입력이 되지 않는다.
- 관리자 반응이 없거나 ⛔가 있으면 `publish_cli`가 거부한다.
- 제출이 채널에 남아 있어도 자동 import·자동 publish·자동 mount는 전혀 일어나지 않는다.
