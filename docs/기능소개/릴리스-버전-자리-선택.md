# 릴리스 버전 자리 선택과 MAJOR 게이트

## 무엇을 바꿨나

워크스테이션 릴리스 명령에서 다음 버전의 증가 자리를 직접 선택할 수 있다.

```bash
automation/release.sh --bump patch
automation/release.sh --bump minor
automation/release.sh --bump major
```

기본값은 기존과 같은 `patch`다. `--no-deploy`와 함께 쓸 수도 있다. 원격 태그 중
`v숫자.숫자.숫자` 형식만 릴리스 기준으로 인정하므로 `v2.0.0-rc1` 같은 시험 태그가
정식 릴리스 계산을 멈추거나 왜곡하지 않는다.

버전 계산과 별도로 릴리스 계획기는 운영 계약에 해당하는 값을 이전 태그와 현재 HEAD에서
읽어 비교한다. 승인 표면의 `POLICY_VERSION`, `automation/` 아래의 스키마 버전 상수,
노드 설정의 `_FIELD_NAMES`, 승인 디렉터리가 요구하는 설정 키가 바뀌면 MAJOR 신호다.
이 신호가 있는데 `--bump major`가 아니면 승인 요청을 만들기 전에 exit 4로 거부한다.
MAJOR 릴리스라면 패치 노트 첫머리에 `MAJOR: 운영자 조치 필요 — ...` 줄을 넣어 필요한
검토 대상을 소유자에게 드러낸다.

## 왜 필요한가

기존 `release.sh`는 언제나 patch 자리만 올렸다. 그 결과 실제로 운영 계약을 바꾸는
MAJOR급 변경 3건도 patch 버전으로 나갔다. 버전 이름만 보고는 호환성 위험이나 운영자
조치 필요 여부를 알 수 없었고, 사람이 매번 변경 파일을 기억해 판별해야 했다.

새 게이트는 Git의 `base..head` 두 리비전에서 값을 직접 비교한다. 현재 작업 트리의 우연한
상태가 아니라 승인받을 정확한 커밋 범위가 판단 근거이며, 승인 레코드 형식은 바꾸지 않는다.

## 사용 시나리오

### 정상: minor 기능 릴리스

현재 최신 정식 태그가 `v1.0.9`이고 호환되는 기능을 묶어 내보낸다면 다음처럼 실행한다.

```bash
automation/release.sh --bump minor
```

계산된 버전은 `v1.1.0`이다. MAJOR 신호가 없으면 기존 승인과 서명 태그 절차가 이어진다.

### 거부: 정책 버전을 patch로 릴리스

`automation/interop/approval_surface.py`의 `POLICY_VERSION`이 바뀐 범위에서 다음 명령을
실행하면 계획 단계가 실패한다.

```bash
automation/release.sh --bump patch
```

오류에는 `POLICY_VERSION` 신호가 표시되고 명령은 exit 4로 끝난다. 변경의 의미를 확인한
뒤 `--bump major`로 다시 실행해야 하며, 생성되는 승인 패치 노트에도 MAJOR 안내가 남는다.

### 재실행: HEAD 의 태그를 그대로 쓴다

태그가 잘린 뒤 `deploy_all` 이 실패하면 `release.sh` 는 exit 10 으로 끝나고, 사람이 다시 돌리거나 완결 타이머가 이어받는다. 그 재실행은 `release_version_for`(`automation/release_tag_lib.sh`) 가 HEAD 에 이미 붙은 태그를 돌려주므로 같은 버전으로 deploy 만 재개한다. 이름 불일치 검사(C079)가 있기 전에는 문제가 없었지만, 그 검사가 들어간 뒤 next 를 다시 계산하면 검사가 자기 태그를 거부한다 — 2026-09-03 v1.1.1 의 완결기 attempt 2 가 `tag at HEAD is v1.1.1, not requested v1.1.2` 로 죽은 것이 그 모양이다. 회귀: `tests/unit/test_release_sh.py::test_a_rerun_after_the_tag_was_cut_resumes_the_deployment_under_the_same_version`.

## 관련 파일

- `automation/release.sh`: 옵션 해석, 버전 계산 및 계획기 배선
- `automation/release_tag_lib.sh`: 정식 태그 필터링, 증가 자리 계산, 요청 태그 일치 확인
- `automation/release_plan.py`: MAJOR 신호 비교와 패치 노트 표시
- `automation/release_approval.py`: 계획 CLI의 `--bump` 전달과 거부 메시지
