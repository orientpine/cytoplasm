# 배포 체크아웃 지연 감지 (DG-1 A)

## 무엇을
`healthcheck.sh`가 ops 배포 체크아웃(`/srv/autophagy-agents`)이 `origin/main`보다 **뒤처졌는지**를 감지한다.
프로브는 이제 노드에서 **로컬로** 돌고, 뒤처짐은 `git ls-remote`(로컬 ref를 쓰지 않는 네트워크 읽기)로 진짜 origin과 대조해 잡는다.

## 왜
드리프트 안전망 3층이 프로덕션에서 전부 죽어 있었다(2026-07-29 실측):
- **프로브가 매 cron tick 거부됐다** — 원격 명령이 SSH allowlist에 없어 `rc=126`(`healthcheck probe denied`)이고,
  중첩 `sudo -n -u ops`도 sudoers에 없어 또 `rc=126`. 이중 거부라 프로브는 추가된 이래 아무것도 검사한 적이 없다.
- **뒤처짐은 구조적으로 못 봤다** — `merge-base --is-ancestor HEAD origin/main`은 behind일 때 성공하고,
  fetch를 안 하니 비교 기준 `origin/main` ref 자체가 낡아 있었다. 실제로 ops가 origin보다 **11커밋 뒤처진** 채 아무도 몰랐다.

프로브를 로컬 실행으로 바꾸면 allowlist·sudo 문제가 통째로 사라진다(healthcheck는 `<primary-node>`에서 ops로 돌고 체크아웃은 그 머신의 로컬 경로다).

## 사용 시나리오

### 정상 경로
1. cron이 5분마다 `sudo -n -u ops healthcheck.sh`를 돈다.
2. checkout 프로브가 로컬에서 `checkout_mirror_verdict`를 판정: `mirror-clean`이면 PASS.
3. ops가 뒤처졌으면 `mirror-behind` → **프로덕션이 무엇을 돌리는가로 채점**한다: 릴리스가 `origin/main`에 있으면 PASS + `MIRROR-BEHIND-WARN`(관측소만 지연), 릴리스가 낡았으면 FAIL + `release-stale`, 릴리스가 아예 없으면(롤백 형태) 미러가 곧 프로덕션이므로 FAIL. 상세: [관측 미러 자동 수렴](관측-미러-자동-수렴.md).
4. origin을 못 읽으면(네트워크 블립) `mirror-unknown-remote` → **PASS + `BEHIND-UNKNOWN`** 으로 degrade — 크라이울프 금지.

### 실패·거부 경로
- 체크아웃에 로컬 커밋이 있으면 → `mirror-ahead`, 종전대로 `format-patch → git am` 안내(never `reset --hard`).
- 추적 파일이 수정됐으면 → `mirror-dirty` → FAIL.
- 전체 SSH 경로가 죽으면 → checkout(로컬)은 통과하고 원격 9개가 실패 → **SSH-borne 체크만 세어 `INFRA_FAILURE`** 로 끝난다(개별 티켓 폭주 방지, d7ed0ad 보존).

## 주의
- **프로브의 read-only 불변식**: `ls-remote`만 쓴다. `fetch`·`pull`·`reset` 없음 — 로컬 ref를 절대 바꾸지 않는다. 미러를 실제로 따라오게 하는 것은 탐지가 아니라 수렴의 일이며, 배포 리컨실러가 안전할 때만 `pull --ff-only`로 한다([관측 미러 자동 수렴](관측-미러-자동-수렴.md)).
- 프로브·채점·가이드 로직은 `automation/checkout_mirror_probe.sh`에 있다(healthcheck.sh를 250 pure-LOC 상한 아래로 유지하고, land.sh가 같은 판정을 재사용).
- **잔여**: 수리 티켓 경로(`report_repair`의 SSH 명령)도 allowlist에 없어 `REPAIR_TICKET_FAILED rc=126`가 난다.
  즉 드리프트를 *감지*해도 자동 *티켓*은 안 된다(FAIL 로그로만). allowlist 갱신은 소유자 작업 — `docs/features.md` 후속 과제.
