# 헬스체크: 프로브 증적과 허용목록 지문

## 무엇을
헬스체크의 **관측성** 두 곳을 메웠다.
1. **프로브별 증적** — 체크마다 rc·소요 시간(ms)·실패 경계(transport/service)를 한 줄로 남긴다.
2. **허용목록 지문** — 래퍼 재생성 판정 지문에 **프로브가 실제로 내는 명령 본문의 해시**를 포함한다.
3. **런타임 패키지 대조** — 배포기가 실제로 싣는 파일만 릴리스 쪽에서 골라 비교한다.

## 왜
- (1) 2026-08-17 같은 tick 에서 embedding·Qdrant 가 실패하고 5분 뒤 회복했는데, probe별 rc·지연·SSH/HTTP 구분이 남지 않아 transport·서비스·자원 중 무엇이었는지 **고를 수 없었다**. 원인을 모르면 retry·timeout 을 추측으로 넣게 된다.
- (2) 지문이 `LIVE_CHECKS` 와 매니페스트 2종만 해시해서, 프로브가 **원격 명령 문자열만** 바꾸면 지문은 그대로였다. 그 명령은 래퍼 허용목록에 없으니 exit 126 으로 거부되고, 결과는 조용한 UNKNOWN 이다.
- (3) `regression_bank`·`research_trends` 배포기는 패키지의 **일부 파일만** 싣는다(`bank_state.py`·`weekly_bank.py` / `research_trends*.py`·`topics_import.py`). 패키지 전체를 대조하면 `__init__.py` 같은 미배포 파일이 매 tick `ABSENT` 로 잡혀 거짓 실패가 된다.

## 사용 시나리오
**실패 원인 귀속(happy path)** — 프로브가 실패하면 증적에 `probe=<이름> rc=<코드> elapsed_ms=<ms> class=transport|service` 가 남는다. rc 124/255 는 transport(타임아웃·SSH), 나머지는 service 다. 재발 시 같은 줄을 모아 원인을 고른 뒤에만 임계값을 손댄다.

**지문 변화 감지** — 프로브 명령이 바뀌면 `bash automation/healthcheck_probe_wrapper.sh --inputs-digest <node>` 값이 달라지고, 드리프트 프로브가 재생성 필요를 알린다. 노드에서 `--install <node>` 로 재생성하면 `WRAPPER-INSTALLED ... inputs=<digest>` 가 나온다.

**증적은 판정을 바꾸지 않는다(실패 경로)** — 증적 기록이 실패해도 프로브의 PASS/FAIL 과 종료코드는 그대로다. 관측이 판정을 흔들면 관측을 끄게 되기 때문이다.
