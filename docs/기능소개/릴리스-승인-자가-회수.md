# 릴리스 승인 자가 회수

## 무엇을

✅를 받은 릴리스라도 태그 전에 `origin/main`이 전진하면, 다음 `automation/release.sh` 실행이 옛 요청을 감사 보관하고 현재 tip의 새 승인 요청을 한 번 게시한다. 완결 타이머는 이런 막힘을 요청당 한 번 알리고, 회수된 승인 카드에는 만료 상태 회신이 붙는다.

## 왜

예전에는 승인 후 main이 전진한 요청이 이후 릴리스까지 막았다. 완결 타이머는 같은 HEAD 불일치만 반복했고, 소유자가 같은 제목의 카드 여러 장에서 유효한 요청을 골라야 했다.

승인은 검토한 커밋에만 유효하다. 새 커밋까지 옛 ✅로 배포하는 대신 **옛 레코드를 보존해 회수하고 새 ✅를 요구**한다.

## 사용 시나리오

- **정상 복구:** 릴리스 카드에 ✅한 뒤 새 커밋들이 합쳐졌다. 완결 타이머가 재요청이 필요하다고 한 번 알린다. 최신 clean tip에서 로컬 CI를 통과한 뒤 `automation/release.sh`를 실행하면 옛 카드는 `⛔ 만료 — …` 회신으로 구분되고 새 카드 한 장이 게시된다. 새 카드의 변경 내용을 검토해 ✅하면 태그·배포가 이어진다.
- **새 승인을 하지 않으면:** 새 요청은 대기 상태로 남는다. 옛 카드에 누른 ✅만으로 새 tip이 태그되지 않는다. 취소·확인 불가도 자동 승인으로 바뀌지 않는다.
- **Discord가 응답하지 않으면:** 타이머 통지는 다음 틱에 다시 시도한다. 회수 카드의 상태 회신 실패는 로그에 남지만 이미 성공한 감사 회수는 유지된다. 원 카드·소유자 리액션·보관된 결정 레코드는 지우지 않는다.
