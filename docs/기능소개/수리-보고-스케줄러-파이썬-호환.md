# 수리 보고 스케줄러 Python 호환

## 무엇을

Hermes의 no-agent cron이 사용하는 Python 3.11에서도 수리 보고 소비자 모듈을 정상 로드해, 내부 큐의 보고 요청을 스케줄에 따라 처리할 수 있게 합니다.

## 왜

개발·테스트 환경은 Python 3.12였지만 Hermes scheduler는 자체 Python 3.11을 사용합니다. 소비자 모듈이 3.12 전용 `typing.override`를 import하면서 scheduler에서는 본문 실행 전에 실패했고, 래퍼가 이를 exit 0으로 감춰 `Last run: ok`인데 ACK가 없는 상태가 발생했습니다.

## 사용 시나리오

- **정상 경로:** 수리 보고 요청이 queue에 들어오면 `repair-report-consumer` tick이 카드를 전이하고 Discord 보고와 ACK를 정확히 한 건 남깁니다.
- **실패 경로:** 향후 소비자 모듈에 Python 3.12 전용 typing import가 다시 들어오면 Python 3.11 호환 회귀 테스트가 배포 전에 실패합니다. 런타임 실패를 정상 tick으로 오판하는 래퍼의 exit-code 문제는 별도 후속 과제로 추적합니다.

## 관련

- 핵심 모듈: `automation/repair/repair_report_consumer.py`
- 회귀 테스트: `tests/unit/test_py311_syntax_guard.py`
- scheduler 래퍼: `automation/repair/cron/repair_report_consume_watch.py`
