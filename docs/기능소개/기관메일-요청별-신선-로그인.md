# 기관메일 요청별 신선 로그인 — "세션 만료" 없는 발송

## 무엇을

mailon 을 부르는 실행 하나하나가 **자기만의 브라우저 세션**을 열어 매번 새로 로그인한다.
세션 이름에 프로세스 id 와 난수가 들어가므로(`mailon-sync-send-run-<pid>-<난수>`) 동시에 도는
두 실행이 같은 브라우저 탭을 조작하는 일이 구조적으로 불가능하다. 그리고 되돌릴 수 없는
한 걸음 — **실제 발송** — 은 런타임 `data/send.lock` 으로 직렬화된다.

## 왜

2026-09-07 밤, 소유자가 ✅ 한 기관메일이 `auth_error`(인증 단계 실패 · 자동 재시도 불가)로
막혔고 안내는 "MailOn 로그인 세션이 만료되었다" 였다. **그 진단은 틀렸다.**

노드 실측으로 확인한 사실:

- agent-browser 세션은 `close` 와 함께 크롬 프로필(`/tmp/agent-browser-chrome-<uuid>`)째
  삭제되고, 같은 이름으로 다시 열어도 `document.cookie` 가 비어 있다.
  **쿠키는 실행을 넘어 남지 않는다** — 즉 발송은 이미 매번 진짜 로그인을 하고 있었다.
- 사고 시각의 로그에는 두 프로세스가 나란히 찍혀 있었다. 13:06:11 / 13:06:15 각각 로그인 시작,
  13:07:07.153 / .205 각각 "login succeeded", 13:07:13.718 / .783 각각 발송 전 중복검사.
  그날 로그인은 8회 시도 / 6회 성공이고, 실패한 2회가 마지막 동시 실행 쌍이다.

원인은 만료가 아니라 **고정 세션 이름의 공유**였다. agent-browser 는 `--session` 이름으로
브라우저를 잡으므로, 같은 이름을 쓰는 두 프로세스는 한 탭을 조작하고 한쪽의 이동·종료가
다른 쪽의 로그인 폼을 갈아치운다. 2026-07-20 에 "동시 발송이 sync 를 죽인" 같은 계열의 사고가
있었고 그때 붙인 `-send` 접미어는 send↔sync 만 갈랐지 **send↔send** 는 그대로 두었다.

세션을 격리하면 두 발송이 서로를 깨뜨리지 않는데, 그러면 이번엔 **둘 다 성공**할 수 있다.
발송 전 중복검사는 check-then-act 라 실측에서 두 프로세스가 65ms 차로 나란히 통과했다.
그래서 격리와 lock 은 한 벌이다 — 격리만 하면 사고가 "메일이 안 나감" 에서 "메일이 두 번 나감"
으로 바뀔 뿐이다.

## 사용 시나리오

- **happy**: 소유자가 승인 스레드에서 ✅ → 워처 틱이 발송 → 그 실행이 자기 세션을 열고
  자격증명·TOTP 로 새로 로그인 → compose → 발송 → 보낸편지함 확인 → 세션과 프로필 소멸.
- **동시 실행**: 워처 틱과 대화형 세션이 같은 승인을 거의 동시에 집어도, 각자 자기 브라우저를
  쓰므로 로그인이 서로를 깨뜨리지 않는다. 실제 발송 구간에서는 뒤에 온 쪽이 lock 을 기다렸다가
  자기 중복검사에서 앞선 발송을 발견하고 `duplicate-suppressed` 로 끝낸다 — 메일은 한 번만 나간다.
- **자격증명이 실제로 틀린 경우**: 그대로 fail-closed 다. 로그인 페이지를 벗어나지 못하면
  `auth_error`(retryable=False)로 끝나고 우회 경로는 없다.
- **제출이 아예 안 된 경우**: 페이지가 자기 `login()` 함수를 노출하지 않으면 25초를 침묵으로
  태우지 않고 **그 사실을 이름 그대로 말하며 즉시** 실패한다. 예전에는 같은 상황이 25초 뒤
  "로그인 페이지를 벗어나지 못함" 이라는 모호한 메시지로만 나왔다.
- **로그에 남는다**: 발송 실패는 이제 런타임 로그 파일에도 한 줄 남는다. 사고 당일 로그에
  `ERROR` 가 한 건도 없었던 이유가 이 경로의 침묵이었다.

## 검증 (마스킹)

같은 노드·같은 자격증명·같은 1분 안에서 벤더 트리만 바꿔 **동시 2건씩** dry-run 발송:

| 트리 | 결과 |
|------|------|
| 고정 세션(구) | 2건 모두 exit 2 · `external_service_error` (로그인은 둘 다 성공한 직후 무너짐) |
| 요청별 세션(신) | 2건 모두 exit 0 · `{"status":"dry_run","csrf_present":true,"network_post_count":0}` |

임시 세션 config 잔여 0, 실험이 만든 크롬 프로필 잔여 0, chrome 프로세스 0.
