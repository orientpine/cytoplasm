# 승인 리마인더

## 무엇을 하나

소유자 승인 메시지가 게시된 뒤 3시간 동안 응답이 없으면 같은 승인 표면에 리마인더를 보냅니다. 이후에도 요청이 pending이면 원래 게시 시각을 기준으로 매시간 한 번씩 보냅니다. 리마인더에는 요청 유형, 경과시간, Discord 원문 링크만 들어갑니다. DM 원문은 `https://discord.com/channels/@me/<channel>/<message>`, 서버 채널 원문은 `https://discord.com/channels/<guild>/<channel>/<message>`로 연결됩니다.

리마인더는 승인을 받는 새 메시지가 아닙니다. 사용자는 링크로 돌아가 **원래 승인 메시지**에만 ✅ 또는 ⛔ 리액션을 남깁니다. 판정은 기존 watcher의 소유자 전용, ⛔ 우선, 불확실 시 fail-closed 규칙을 그대로 따릅니다.

## 왜 필요한가

메일·캘린더·과제·수리 같은 승인 요청은 다른 Discord 대화에 밀려 보이지 않을 수 있습니다. 원문을 다시 게시하면 승인 메시지 단일성 규칙을 깨고 예전 메시지의 ✅를 놓칠 수 있으므로, 내용을 복제하지 않고 기존 메시지를 가리키는 최소정보 포인터만 보냅니다.

동시에 실행된 watcher는 기존 approval key lease와 영속 reminder claim으로 같은 시간 구간을 한 번만 전송합니다. 프로세스 재시작 뒤에도 claim이 남아 중복되지 않습니다. 승인·취소·실행·폐기·만료·supersede·원문 삭제 뒤에는 더 보내지 않으며, 새 초안이 기존 요청을 supersede하면 새 message id와 게시 시각으로 타이머를 다시 시작합니다.

## 사용 시나리오

1. mail compose가 기존 `approval_lifecycle` 파사드로 소유자 DM에 승인 메시지를 게시합니다.
2. 2시간 59분까지 기존 mail watcher는 리마인더를 보내지 않습니다.
3. 3시간 tick에서 `승인 리마인더`와 원문 링크를 보냅니다.
4. 소유자가 원문에 ✅를 남기면 같은 mail watcher가 기존 발송 절차를 수행하고 이후 리마인더는 없습니다. 봇이나 다른 사용자의 리액션은 무시합니다.
5. 필요하면 `~/.hermes/config.yaml`에서 기능을 끌 수 있습니다. `enabled: false`에서는 journal·claim·전송을 만들지 않습니다.

```yaml
approval_reminders:
  enabled: true
  initial_delay: 3h
  repeat_interval: 1h
```
