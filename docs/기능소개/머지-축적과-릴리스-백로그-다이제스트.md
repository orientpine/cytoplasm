# 머지=축적 — merge-pr 태그 분리와 릴리스 백로그 다이제스트

## 무엇을

`automation/merge-pr.sh`가 더 이상 머지 직후 릴리스 태그를 자르지 않는다. 머지는
main에 쌓일 뿐이고, 서명 태그(=배포)는 소유자 ✅ 1회를 받는 `automation/release.sh`가
자른다(VA-1). 태그 없는 창의 리컨실러 통지도 함께 재설계됐다: unsigned `origin/main`은
sha별 사고 통지 대상이 아니라 **릴리스 백로그**이며, 3일 이상 묵으면 "미배포 커밋 N건 ·
X일 경과" 다이제스트를 기간당 1건 보낸다.

## 왜

머지=배포 체제에서는 스킬 n개가 바뀐 릴리스에 ✅가 n번 필요했고, 릴리스 승인(VA-1)을
도입해도 머지마다 태그가 잘리면 그 승인이 있으나 마나가 된다. 반대로 태그 호출만 떼면
기존 통지가 문제였다 — unsigned head는 sha별 1회 사고 통지라, 머지가 정상적으로 쌓이는
동안 소유자가 머지당 한 번씩 호출당한다. 그래서 둘을 같은 사이클에 바꿨다(§7 순서 5).

## 사용 시나리오

### 정상 경로

1. PR을 `automation/merge-pr.sh <pr>`로 머지한다 — 체크 게이트는 그대로, 태그는 없다.
2. 머지가 쌓이는 동안 리컨실러는 매 틱 조용히 백로그 나이만 센다(사고 아님).
3. 릴리스할 때 `automation/release.sh`를 실행한다 — 승인 ✅ 후 서명 태그, ~2분 내 수렴.
4. 백로그가 3일을 넘기면 다이제스트 1건: 미배포 커밋 수(미러 `rev-list --count`, 관측
   불가면 "수 미상")·경과일·릴리스 명령 안내. 3일마다 반복, 릴리스가 착지하면 기존
   recovery 통지와 함께 리셋된다.

### 경계

- 머지 사이 sha가 전진해도 백로그 나이는 이어진다 — sha별로 리셋하면 활발히 머지할수록
  다이제스트가 영영 오지 않는다.
- 전송 실패는 durable pending notice로 다음 틱에 재시도된다(기존 규율 그대로).
- `land.sh`의 직접 착지 경로와 리컨실러의 서명 전용 계약(MD-1)은 이 변경의 대상이 아니다.
