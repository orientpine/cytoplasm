# 오너 통지 단일 채널 (ON-1·ON-2·ON-3)

## 무엇을

소유자에게 가는 모든 **통지**(일일 지출·주간 연구동향·아침 자가 스킬 감사·헬스체크·
리마인더·구매 검토 요청·인터롭 위임 결과·수렴 실패 알림)를 `automation/owner_notice.py`
파사드 **한 경로**로 모으고, 목적지를 설정 키 하나로 정한다:
`owner_notice_channel_id`(`~/.hermes/interop/config.json`, env `OWNER_NOTICE_CHANNEL_ID` 우선).
설정되면 그 채널(**`#notifications`**)로만 보내고, 미설정이면 기존 소유자 DM이다.

## 왜

승인은 v7이 이미 `#agent-chat` 스레드로 옮겼지만 **통지는 아직 DM으로 흩어지고
있었다** — 파사드 밖에서 `/users/@me/channels`를 직접 여는 발신자가 6곳(실측)이었다.
정기 통지 트래픽이 대화 채널을 오염시키지 않도록 별도 채널로 분리한다(§10-6 확정,
2026-08-28). 사본이 여섯이면 반드시 드리프트한다 — 목적지 결정은 한 곳만 안다.

## 어떻게

- **ON-1**: 파사드가 채널을 해석한다. 설정되면 **그 채널로만**(DM 폴백 없음 — 게시
  실패는 `False`로 호출자 큐잉·재시도, 「절대 예외를 던지지 않는다」 계약 불변).
  설정을 읽을 수 없어도(EACCES 포함) 던지지 않고 미설정으로 답한다(ProtectHome 교훈).
- **ON-2**: 직접 DM 발신 6곳(reminder_poller·research_trends·cost-report·
  memory_curator effects·procurement review·hermes_plugin 위임 결과)을 파사드 경유로
  이관. 마스킹 규칙은 각 발신자 것 그대로 — 채널은 목적지만 바뀐다. 첨부를 보내는
  procurement는 `resolve_notice_target()`으로 대상 채널 id만 받아 첨부를 올린다
  (DM 오픈은 여전히 파사드/central directory 안에서만). research_trends의 agent-chat
  직송(2026-08-24)은 §10-6 확정으로 대체됐다.
- **ON-3**: conformance — `/users/@me/channels`를 여는 코드는 central directory와
  E2E gate driver 2곳뿐(`tests/unit/test_approval_surface_inventory.py`). 새 통지
  발신자가 DM을 다시 열면 CI RED다.

## 소유자 설정 (1회)

1. 개인 서버에 `#notifications` 텍스트 채널을 만들고 세 봇(agent·peer·**ops**)을
   초대/권한 부여한다 — ops 봇 초대 전에 채널을 지정하면 ops 발신 통지(수렴 실패·
   헬스체크)가 게시 불가로 큐잉만 된다(ON-4 롤아웃 순서).
2. 각 발신 계정의 `~/.hermes/interop/config.json`에 `"owner_notice_channel_id": "<채널 id>"`
   기입(또는 유닛 env에 `OWNER_NOTICE_CHANNEL_ID`). ProtectHome 유닛(repair·ops)은
   env 쪽을 쓴다.
3. 미설정 상태는 그대로 DM — 레거시 설치 무영향.

## 배포 주의

이관된 홈 배포 사본(`poll_reminders.py`·`send_cost_report.py`·`research_trends.py`)은
각 배포기 실행 전까지 옛 DM 경로로 돈다("커밋됨 ≠ 배포됨"). 게이트웨이 플러그인
(hermes_plugin)은 파일 갱신 후 **재시동**까지 해야 반영된다(agent+peer 세트 규칙).
