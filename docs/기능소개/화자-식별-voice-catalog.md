# 화자 식별 (voice catalog ③) — 등록된 목소리로 `화자N` 에 이름을 붙인다

## 무엇을

등록본이 하나라도 있으면, 전사가 끝난 뒤 도구가 `화자N` 군집마다 임베딩을 뽑아 카탈로그와
코사인으로 대조하고 판정 셋 중 하나를 낸다 — **확정**(범례·블록 헤더에 이름), **제안**(이름 없이
근거만), **미상**(아무것도 남기지 않음). 소유자가 손으로 물어볼 읽기 전용 명령
`stt_catalog_cli.py match` 도 같이 온다.

## 왜

전사본의 `화자N` 은 익명이고, 이름을 줄 수 있는 것은 자기소개 규칙·LLM 제안·소유자 지정뿐이었다.
그런데 라이프로그 전사본 28건에서 자기소개가 이름을 준 적은 **0건**이다 — 회의에서 사람들은
자기소개를 하지 않는다. ②에서 등록본 저장소를 만들었으니 남은 일은 그것을 쓰는 것이었다.

원래 계획(특허 초안)은 **녹음 선두에 등록본을 이어 붙여** 분리기가 같은 군집으로 묶게 하는
것이었다. 소유자가 2026-09-17 에 그 한계를 정확히 지적했다 — "녹음 파일이 올 때마다 모든
카탈로그를 붙일 수는 없잖아." 실제로 붙이는 방식은 카탈로그 크기에 무너진다: 붙인 사람 수만큼
군집이 늘어 상한 8·임계값 예산을 먹고, 군집은 전역이라 붙인 목소리가 **녹음 본체의 군집 경계까지
흔들어** 식별하려다 분리를 망친다. 그래서 붙이지 않고, 분리가 끝난 뒤 **잰다**. 사람이 1만 명이어도
벡터 곱이라 비용이 늘지 않는다.

## 사용 시나리오

1. **아무것도 하지 않는다(자동).** 라이프로그·회의 전사가 돌면 범례가 이렇게 나온다:
   ```
   - 화자: 화자1=차백동 [카탈로그 0.97] · 화자2=미상 [카탈로그 제안: 김민수 0.72] · 화자3=미상
   ```
   확정된 화자1 은 블록 헤더에도 이름이 붙고, 화자2 는 **이름이 붙지 않은 채** 근거만 남는다.
2. **제안을 확정으로 바꾼다.** 화자2 가 정말 김민수였다면 그 라이프로그 노트에 한 줄 적는다:
   `- 화자:: 화자2=김민수`. ②b 워처가 그 녹음에서 등록본을 하나 더 만들고 `#notifications` 에
   알린다 — 다음 녹음부터 그 사람의 점수가 올라간다. 에이전트는 이 줄에 **쓰지 않는다**(쓰면
   워처가 자기 제안을 소유자 명령으로 읽는다).
3. **손으로 물어본다(읽기 전용).**
   ```bash
   C=/srv/autophagy-skills/live/speechtotext/scripts/stt_catalog_cli.py
   python3 $C match <전사본.md>
   # 화자1: 차백동 0.97 → 확정
   # 화자2: 차백동 0.72 → 제안
   # 화자3: 차백동 0.59 → 미상
   ```
4. **끈다.** `SPEECHTOTEXT_IDENTIFY=0` 이면 `IDENTIFY-SKIP reason=disabled` 한 줄만 남고 전사본은
   식별 이전과 바이트 그대로다.

### 거부·생략 경로 (모두 fail-soft — 전사는 계속된다)

- 등록된 목소리가 없으면 `IDENTIFY-SKIP reason=no-catalog`.
- 노드에 sherpa-onnx C API·임베딩 모델이 없으면 `reason=no-toolchain`.
- 그 라벨에 3초 이상 블록이 없으면 그 라벨만 빠진다(전부 없으면 `reason=no-spans`).
- 추출 자식이 죽거나 시간을 넘기면 `IDENTIFY-FAIL <사유>` 뒤 이름 없이 진행한다.
- 진단 표식에는 **이름을 싣지 않는다** — 로그는 전사본보다 넓은 곳으로 흐른다.

## 어떻게 (읽는 사람이 알아야 할 것만)

- 라벨 점수는 **블록마다 재서 평균**, 사람 점수는 **등록본 중 최대**다. 이 비대칭에는 실측 근거가
  있다(`docs/qa/VC3`): 라벨의 발화를 60초로 이어 붙여 벡터 하나로 만들면 같은 마이크·같은 방의
  채널 특성이 화자 특성을 덮어, 확실한 양성(0.8559)이 다른 사람(0.8634)에게 **졌다**. 블록마다
  재서 평균하면 순서가 바로잡힌다(0.8316 > 0.7452).
- 임계값 `accept 0.80` · `suggest 0.65` · `margin 0.05` 는 그 표에서 나왔다. 표본이 녹음 1건·등록
  1명이라 실패 방향을 「확정 대신 제안」으로 두었다 — 과소 확정은 소유자의 한 줄로 회복되지만,
  잘못된 확정은 회의록에서 남의 발언 귀속이 된다.
- 임베딩은 화자 분리와 **같은 모델**을 stdlib `ctypes` 로 부른다(노드가 aarch64 라 PyPI 휠·numpy·
  onnxruntime 파이썬 패키지가 없다). 추출은 자식 프로세스라 네이티브 라이브러리가 죽어도 두
  시간짜리 전사를 데려가지 않는다. 음성은 노드 밖으로 나가지 않는다.
