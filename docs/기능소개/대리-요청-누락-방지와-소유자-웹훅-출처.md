# 대리 요청 누락 방지와 소유자 웹훅 출처

## 무엇을

두 가지를 함께 바꾼다.

1. 소유자가 단축어로 녹음해 원문 채널에 올린 글(소유자가 직접 만든 웹훅이 쓴 글)도 대리 요청의 원문으로 인정한다.
2. 대리 요청이 처리되지 않으면 그 사실을 대리 글의 스레드에 남긴다. 출처 검증에서 거부되면 즉시 사유를 남기고, 받았는데 3분 안에 오토파지의 글(답·승인 카드·질문)이 없으면 '처리 확인 실패'를 남긴다.

## 왜

2026-10-10 01:25Z 일정 7개 등록 대리 요청이 ✅ 반응만 받고 아무 답이 없었다. 원인은 둘이었다.

- 원문이 소유자 단축어 녹음이었다. 이 글은 웹훅이 쓰므로 Discord 가 작성자를 봇으로 표시한다. 출처 검증은 "작성자 = 소유자 본인(사람)"만 받았기 때문에 이 요청을 `origin_author` 로 거부했고, 에이전트 턴이 아예 열리지 않았다. 그때까지 받은 대리 요청 13건은 모두 텍스트 원문이었다.
- ✅ 는 처리 결과가 아니다. 게이트웨이는 글을 받으면 👀 를 달고, 처리 완료 콜백에서 ✅ 로 바꾼다. 훅이 글을 버려도 그 콜백은 '성공'으로 끝난다. 그래서 거부된 요청도 ✅ 를 받았고, 아무도 누락을 알 수 없었다.

소유자가 직접 쓴 요청에는 이 출처 검증이 없어서 같은 누락이 생기지 않았다.

## 신뢰 범위 (웹훅 출처)

웹훅 글은 URL 을 아는 사람이면 누구나 쓸 수 있다. 그래서 웹훅 출처는 좁게 받는다.

- 사설 설정 `owner_proxy_origin_webhook_ids`(웹훅 id 목록)에 등록한 웹훅만 받는다. 설정이 없거나 형식이 틀리면 예전처럼 거부한다.
- 원문의 `webhook_id` 와 작성자 id 가 같고, 그 글이 원문 채널(`owner_proxy_origin_channel_id`) **자체**에 있어야 한다. 그 채널의 스레드에 쓴 웹훅 글은 받지 않는다.
- 웹훅 출처라도 승인 게이트는 그대로다. 받은 요청은 에이전트 턴을 열 뿐이고, 외부효과(일정·메일·할 일 등록 등)는 여전히 소유자가 승인 카드에 누른 ✅ 가 있어야 실행된다. 이 조건은 시험으로 고정했다.
- 기록에 출처 종류가 남는다. 게이트웨이 로그는 `interop owner proxy accepted origin=<id> via=owner-webhook` 이고, 에이전트에게 넘기는 머리말은 `원문: <링크> (작성: owner-webhook)` 이다.

웹훅 URL 이 새어 나갔다고 의심되면 소유자는 Discord 에서 그 웹훅을 지우고 새로 만든다. 그다음 노드 사설 설정의 id 를 새 웹훅 id 로 바꾼다.

## 사용 시나리오

- **단축어 녹음 요청**: 소유자가 단축어로 "다음 주 월요일 2시 회의 잡아줘"라고 녹음한다. 대리 봇이 전사해 원문 링크와 함께 `#agent-chat` 에 옮겨 쓴다. 오토파지는 그 글을 받아 같은 스레드에 일정 승인 카드를 올리고, 소유자가 ✅ 를 눌러야 등록한다.
- **거부된 요청**: 원문이 24시간보다 오래됐거나 등록되지 않은 작성자의 글이면, 대리 글 스레드에 "⚠️ 이 대리 요청은 처리하지 않았습니다 — <사유> (사유 코드 `origin_stale`)"가 곧바로 달린다. 이 경우 실행된 것은 없다.
- **처리 중 끊김**: 요청은 받았지만 게이트웨이 재시동 등으로 턴이 끊겨 3분 동안 답이 없으면, 같은 스레드에 "⚠️ 이 대리 요청에 3분 동안 응답이 없습니다"가 달린다. 대기 목록은 파일에 남으므로 재시동 뒤에도 확인한다.

## 관련

- 판정: `automation/interop/owner_proxy.py`(`_origin_via`), I/O 어댑터 `automation/interop/owner_proxy_io.py`
- 안전망: `automation/interop/owner_proxy_watch.py` — 대기 목록 `~/.hermes/interop/owner-proxy-pending.json`, 통지 스레드는 결과 통지와 같은 `origin_notice.resolve_thread_id`, 무장은 게이트웨이 주 프로세스에서만 한다
- 시험: `tests/unit/test_owner_proxy.py`, `tests/unit/test_owner_proxy_watch.py`
- 규약: [interop §3.5](../guide/interop-규약.md)
- 반영: 게이트웨이 플러그인 코드라 릴리스 뒤 agent·peer 게이트웨이를 재시동해야 적용된다. 웹훅 출처를 쓰려면 노드 agent 계정 `~/.hermes/interop/config.json` 에 `owner_proxy_origin_webhook_ids` 를 넣어야 한다
