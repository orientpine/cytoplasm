# 배포 스냅샷 핀 (DG-2)

## 무엇을
`automation/origin_snapshot.sh`의 `origin_snapshot_run <mirror> <sha> <명령...>`은 명령을
**`origin/main`의 특정 커밋으로 고정된 임시 워크트리 안에서** 실행한다. 노드에 상주하는
체크아웃의 작업 트리·인덱스·HEAD는 재료로 쓰이지 않는다 — git 오브젝트 저장소만 빌린다.

## 왜
배포는 오랫동안 상주 체크아웃 `/srv/autophagy-agents`의 파일을 그대로 복사했다. 그래서
**다른 세션이 그 안에 남긴 미커밋 편집 하나가 `git pull --ff-only`를 막아, 이미 머지된 코드가
배포되지 못했다**(2026-07-27·07-29 연속 발생). 배포 재료를 커밋 SHA로 고정하면 그 체크아웃이
dirty하든 로컬 커밋으로 앞서 있든 배포는 영향을 받지 않는다.

## 사용 시나리오

### 정상 경로
1. 호출자가 배포하려는 커밋 sha를 정한다(예: 방금 push한 `dev HEAD`).
2. `origin_snapshot_run`이 **락 안에서** `fetch origin` → 원격 main이 그 sha와 같은지 대조 →
   `git worktree add --detach <임시경로> <sha>`로 트리를 만든다.
3. 트리의 `HEAD == sha`이고 `status --porcelain`이 비었는지 재확인한다.
4. `AUTOPHAGY_SNAPSHOT_DIR`을 세팅하고 그 디렉터리를 cwd로 명령을 **락 밖에서** 실행한다
   (동시 배포가 서로를 기다리지 않는다).
5. `RETURN` 트랩이 워크트리를 제거·prune하고 **명령의 종료코드를 그대로 돌려준다**.

### 실패·거부 경로
- **다른 세션이 그 사이에 push했으면** → `SNAPSHOT-BLOCK: remote main moved` + **명령을 아예
  실행하지 않고** rc 3. 내가 검증한 것과 다른 코드를 배포하는 일이 없다.
- **상주 체크아웃이 dirty하거나 앞서 있어도** → 스냅샷은 정상 성공한다(이 기능의 존재 이유).
  상주 체크아웃의 로컬 전용 커밋은 트리에 **포함되지 않는다**.
- **명령이 실패하면** → 그 rc를 보존한 채 워크트리는 정리된다(`worktree list` 잔여 0).

## 주의
- `git clone --shared --branch main`으로 대체하면 **상주 체크아웃의 로컬 커밋이 딸려 들어온다** —
  2026-07-27 사고의 재현이라 금지다. 반드시 `worktree add --detach <sha>`.
- `mktemp -d`로 실행마다 경로가 다르므로 동시 실행이 서로를 덮지 않는다.
- `deploy_provenance.sh`의 기준 ref는 이 스냅샷 sha로 고정하지 않는다 — 고정하면 race 감지기가
  자기 자신을 검사하는 동어반복이 된다.
