# 공급망 열거 실패 보존

## 무엇을

공급망 워처가 pending 디렉터리를 성공적으로 비운 경우와 디렉터리 열거 자체가 실패한
경우를 구분한다. 성공한 열거에서 사라진 요청의 재시도 억제 레코드는 정리하고, 열거
실패에서는 모든 억제 레코드를 보존한다.

## 왜

기존 열거기는 두 경우 모두 빈 튜플을 반환했다. 따라서 성공한 빈 디렉터리를 근거로
`tick.json`의 고아 `failures`를 안전하게 정리할 수 없었고, 파일이 단조 증가했다.
반대로 빈 결과만 보고 정리하면 일시적인 파일시스템 오류 한 번에 살아 있는 요청의
재시도 상태를 잃을 수 있었다.

## 사용 시나리오

- **정상:** 배포가 끝나 pending 레코드가 CAS로 회수된다 → 다음 2분 tick의 열거가
  성공하고 해당 key가 없다 → 그 key의 오래된 억제 레코드만 삭제된다. 디렉터리가
  완전히 비었으면 고아 억제 레코드를 전부 정리한다.
- **보존:** pending 디렉터리 열거가 `OSError`로 실패한다 → 결과는
  `succeeded=False`가 된다 → 워처는 `failures`를 한 건도 지우지 않고 다음 tick을
  기다린다.
- **계속 억제:** 성공한 열거에 key가 여전히 있으면 기존 attempts,
  next-attempt-at, 릴리스 지문 판정을 그대로 사용한다.
