# 문서 검토 안내도 공용 통지 경로를 쓴다

## 무엇을 · 왜

doctype·proposal·procurement의 검토 안내를 `owner_notice` 공용 경로로 보낸다.
각 스킬이 따로 보내던 동안에는 통지 목적지·실패 처리·첨부 전달 정책이 갈라질 수 있었다.
문서가 무엇인지, 어디에서 검토할지, 다음 행동은 무엇인지를 기존 소유자 메시지 봉투로 전달한다.

## 사용 시나리오

**정상:** 검토할 문서가 준비되면 소유자는 설정된 통지 표면에서 안내를 받는다.
이미 확보한 Drive 링크가 있으면 그 문서를 가리키고, 링크가 없으면 파일명과 검색 안내를 사용한다.
procurement의 첨부도 같은 파사드 경계를 거쳐 전달한다.

**실패:** 첨부를 읽거나 전송하지 못한 경우를 성공으로 보고하지 않는다.
통지 실패를 문서 생성 성공으로 혼동하지 않으며 기존 실패·호환 경로를 유지한다.
링크를 얻기 위해 문서를 임의로 재발행하거나 추측 URL을 만들지 않는다.

## 승인 경계 · 관련

검토 안내는 실행 승인이 아니다. 문서별 기존 소유자 승인과 외부 발행 게이트를 그대로 따른다.
공용 파사드 채택은 신규 통지 경로를 하나 더 만드는 변경이 아니다.
실제 노드 반영은 릴리스 배포 후 확인한다.
