# 문서 보드 정리

## 무엇을

`features.md`·`follow-ups.md`·`done.md`와 계획 SSOT를 실제 코드·머지 이력에 맞춰 다시 대조한 최종 정합화 작업이다. G0–G8이 남긴 묶음을 중복 없이 합치고, 완료된 항목은 근거와 소개 링크를 보존해 DONE으로 옮겼다.

## 왜

출처별로 쌓인 후속 과제에는 이미 해소된 결함, 같은 문제의 중복 기록, 실측과 다른 수치가 섞여 있었다. 특히 보드 정리 중 순삭제를 놓치면 열린 과제가 조용히 유실될 수 있으므로, 각 제거를 머지 PR·커밋에 연결하고 커밋마다 A6 링크 정합성을 검증했다.

## 사용 시나리오

- **정상 경로**: cha가 `features.md` 요약표에서 `37개 / 19묶음`을 확인한다 → 관심 묶음 링크를 열면 `follow-ups.md`의 실제 열린 항목으로 바로 이동한다 → 완료 근거는 `done.md`에서 PR 번호와 기능 소개로 확인한다.
- **보수적 경로**: 해결 여부가 불확실한 항목은 삭제하지 않는다 → 열린 follow-up으로 남겨 다음 작업자가 근거를 추가한 뒤 종결한다.
- **링크 안전성**: follow-up이 품던 기능 소개 링크를 제거할 때 같은 커밋에서 DONE으로 이전한다 → `test_features_board_conformance.py`의 A6가 중간 커밋에서도 계속 통과한다.

## 관련

- 보드: `docs/features.md`, `docs/follow-ups.md`, `docs/done.md`
- 계획 SSOT: `.omo/plans/autophagy-agents.md`
- 실행 계획: `.omo/plans/parallel-followup-sweep.md`
- 정합성 검사: `tests/unit/test_features_board_conformance.py`
- 문서 작업이며 외부효과·승인 게이트·배포는 없다.
