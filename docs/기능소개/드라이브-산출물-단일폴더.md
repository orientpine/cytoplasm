# 드라이브 산출물 단일 폴더

## 무엇을

에이전트가 만든 문서 산출물은 전부 Drive의 **한 루트 폴더**(`autophagy`) 아래로 들어간다. 그 안에서 종류별(`주간동향`·`제안서`·`예산`·`회의록`·`구매`·`문서`) → 연도별 → 날짜 프리픽스가 붙은 파일이나 번들 폴더로 정리된다. 같은 문서를 다시 만들면 새 파일이 생기는 게 아니라 **기존 파일이 갱신**된다.

## 왜

전에는 스킬마다 업로드 코드가 복사돼 있었다. report는 report대로, proposal은 proposal대로 폴더를 만들고 이름을 붙였고, 규칙을 하나 고치면 다섯 군데를 따라 고쳐야 했다. 게다가 재생성할 때마다 같은 내용의 파일이 하나씩 더 쌓여서, 어느 게 최신인지는 파일 목록을 눈으로 훑어야 알 수 있었다.

이제 이름·배치 규칙은 `drive_taxonomy` 한 곳에만 있고, 업로드는 `drive_outputs.publish`가 전담한다. 종류 등록부가 한 벌이므로 폴더 이름을 코드에 하드코딩하는 호출자가 없다.

## 사용 시나리오

**happy path — 주간 보고**

```
cha: "이번 주 연구동향 보고서 만들어줘"
→ report 스킬 생성 → publish(kind=report, ...)
→ 주간동향/2026/2026-W34_주간연구동향/ 에 3파일 (action=created)
```

같은 주에 다시 돌리면 폴더도 파일명도 그대로고 내용만 바뀐다(`action=updated`, 중복 0건). 단발 문서(제안서·회의록 등)는 첫 발행의 날짜 프리픽스를 계속 물고 가므로, 며칠 뒤 고쳐 올려도 파일이 갈라지지 않는다.

**거부·건너뜀 경로**

```
노드에 DRIVE_PUBLISH_ENABLED 미설정
→ 업로드 호출 0회, 로컬 산출물만 남음 (스킬은 정상 종료)
```

옵트인하지 않은 환경에서는 아무것도 올라가지 않는다. 민감으로 표시된 회의록은 옵트인 여부와 무관하게 `DRIVE-PUBLISH-SKIP reason=sensitive`로 멈춘다. 업로드가 실패해도 산출물 생성 자체를 깨뜨리지 않고 `DRIVE-PUBLISH-FAIL kind=… reason=…` 한 줄만 남긴다.

**특허는 여기로 오지 않는다.** `patent`는 등록부에 gate-only로 박혀 있어 이 경로로 올리려 하면 코드가 거부한다. 전용 반출 게이트가 계속 유일한 통로다.

## 관련

- 규칙(순수 로직): [`automation/drive_taxonomy.py`](../../automation/drive_taxonomy.py) — 종류 등록부, 기간 키, 깊이 상한.
- 업로드 파사드: [`automation/drive_outputs.py`](../../automation/drive_outputs.py) — upsert + owner-only 권한 확인 + 재다운로드 sha256 대조를 통과해야 성공.
- 기존 산출물 이관: [`automation/drive_migrate_outputs.py`](../../automation/drive_migrate_outputs.py) — 소유자가 dry-run으로 계획을 본 뒤 `--apply`.
- 운영 가이드: [drive-publish](../guide/drive-publish.md) — 환경 변수, 롤아웃 순서.
- 승인·게이트: Drive 쓰기는 owner-only 권한 검증을 통과해야 성공으로 친다. 특허 산출물은 전용 반출 게이트가 우선한다(위 참조).
