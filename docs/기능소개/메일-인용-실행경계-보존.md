# 기능 소개 — 메일 인용 실행 경계 보존

**완료:** 2026-09-03 · **티켓:** repair `t_dc82fb9f` · **스킬:** `mail`

## 무엇을

엔티티 프리플라이트가 소유자 검토를 마친 회신문 `body`만 정규화한 뒤, 실제 발송 argv를 만드는 실행 경계에서 `mail_quote.with_quote(body, quote)`로 원문 인용을 다시 붙인다. 인용 없는 기존 초안은 같은 함수를 지나도 본문과 승인 해시가 바이트 동일하다.

## 왜

프리플라이트 경계가 회신문으로 `--body`를 다시 만들면서 draft의 `quote`를 잃어, 2026-09-03 전달 메일이 원문 없이 나갔다. vendor mailon은 답장 명령이 아니라 새 compose를 쓰므로, 인용이 빠지면 수신자는 답장의 맥락을 알 수 없다.

## 사용 시나리오

### happy path

1. 소유자가 회신 초안을 검토하고 승인한다. draft에는 회신문 `body`, 원문 `quote`, 그리고 둘을 포함한 승인 해시가 있다.
2. `mail_preflight`가 회신문의 고유명사만 정규화한다.
3. 실행 경계가 정규화한 회신문 아래에 `quote`를 재부착해 동결한 발송 argv를 실행한다. 수신자는 회신문과 원문 인용을 함께 받는다.

### 실패/거부 경로

- 이름 해석이 모호하면 `ENTITY-CLARIFY`로 멈춘다. 승인되지 않은 다른 수신자나 본문으로 발송하지 않는다.
- `quote`가 없는 레거시 초안은 인용을 만들어 내지 않고 회신문 그대로 처리한다. 기존 quote-less 해시가 달라지지 않아 재승인을 강요하지 않는다.
