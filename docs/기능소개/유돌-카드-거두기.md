# 유돌이 자기 메일 카드를 거둔다

## 무엇을

유돌 게이트에 `card-withdraw <draft id> <사유>` 하나를 더했다. 유돌이 올렸고 형이 아직 ✅/⛔ 하지 않은 메일
발송 카드만 닫는다. 카드 글은 `⛔ 발송 취소 (유돌 거둠) — … 사유: …` 로 바뀌고, 같은 스레드에 ⛔ 발송 취소 통지가
붙으며, 메일은 나가지 않는다. 보내거나 승인하는 길은 없다.

## 왜

필요 없어진 카드(시험 메일 등)도 형이 ⛔ 를 눌러야만 닫혔다. 유돌은 카드를 올릴 수만 있고 닫을 수 없었다
(2026-10-26 18:55 KST 유돌 "내가 닫을 수 있게 하려면 취소 명령을 넣어 줘", 형 Q367 "유돌이 자기 카드를 취소만
할 수 있게").

## 사용 시나리오

- **필요 없어진 카드**: 형 "아까 그 시험 메일 카드 치워" → 유돌 `node-read card-withdraw a1b2c3 시험 메일이라 필요 없어짐`
  → `WITHDRAWN draft=a1b2c3 by=유돌` → 카드는 ⛔ 표시로 바뀌고, 그 뒤 형이 ✅ 를 눌러도 아무것도 나가지 않는다.
- **이미 닫힌 스레드 안의 카드**: 카드가 결과 통지로 닫혀 보관된 스레드 안에 있으면(28fe93 은 릴리스 스레드 안이었다)
  Discord 가 글 수정을 막는다. 거두기는 그 스레드의 보관만 풀고(이름은 그대로) 카드에 ⛔ 표시를 단다. 그래도 못
  달면 `MAIL-SUPERSEDE-MARK-FAIL … status=<HTTP> code=<Discord 코드>` 를 남기고, 레코드는 이미 만료라 ✅ 로 나가지 않는다.
- **형이 이미 결정한 카드**: ✅ 를 눌렀거나 발송 중·발송 끝·이미 닫힌 카드는 거부(`GATE-REFUSED`, rc 1). 형 결정이
  이긴다.
- **유돌 카드가 아님**: 다른 도리가 노드에서 직접 올린 카드, 다이제스트 ✍️ 로 생긴 카드, 릴리스 카드, 없는 id 는
  게이트가 `YOODORI-GATE-REFUSED not a mail card YooDori posted …` 로 거부한다(rc 2, 메일 스킬을 부르지 않음).
- **잘못된 인자**: id 가 6자리 소문자 16진수가 아니거나, 사유가 없거나 `-` 로 시작하거나 200자를 넘거나, 셸
  메타문자가 있으면 거부.

## 어떻게 유돌 카드인지 아나

게이트 로그(`~/.local/state/yoodori-gate.log`)는 이 강제명령만 쓴다. 초안의 생성 시각이 성공한(`rc=0`) 또는
게이트가 150초에 끊은(`rc=124`) `mail-compose`·`mail-draft` 호출 시간 안에 있으면 유돌 카드다. 끊긴 호출도 카드를
이미 올렸을 수 있다(2026-11-04 36b605 는 끊긴 compose 가 올린 카드라 거두기가 거부됐다). 게이트가 거부한 호출(rc 2)은
아무것도 돌리지 않았으니 세지 않는다. 2026-10-26 노드 실데이터로 맞춰 보니 10-18 이후
게이트 카드 25장은 모두 맞았고, 게이트 밖에서 올라온 3장은 모두 빠졌다. 로그나 초안을 읽을 수 없으면 거부한다.

- 기록: 초안 레코드에 `expired_reason=withdrawn-by-requester`·`withdrawn_by`·`withdraw_reason`·`withdrawn_at`,
  게이트 로그에 명령명·rc·초(사유는 남기지 않음).
- 승인: 카드를 닫기만 하므로 새 카드가 없다. 승인 규칙·발송 경로·문지기 허용 목록은 그대로다. 게이트 파일과 mail
  스킬 배포본은 릴리스(형 ✅)로 노드에 반영된다.
