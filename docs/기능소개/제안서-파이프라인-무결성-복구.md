# 제안서 파이프라인 무결성 복구 — 엔진 초안 명령·계획서 입력·가짜 그림 차단

## 무엇을

제안서 스킬이 새 주제를 **엔진의 계획·작성·검토 단계를 거쳐** 만들도록 빠진 단계와 가드를 채웠다.

- `proposal_cli.py compose` — 현재 버전의 코퍼스로 엔진 planner·writer·critic·reviser 를 live 로 돌려
  `out/drafts.json`·`.planspec.json`·`.pms.json` 을 만든다. Hermes(Codex OAuth)를 쓰며, 실패하면 이전 산출물을 건드리지 않는다.
- `proposal_cli.py figures` — `figures.json` 의 그림마다 `[[FIG:…]]` 자리를 본문에 놓는다(멱등). 엔진 writer 는
  figures.json 을 보지 않아 compose 직후 본문에 그림 자리가 없고 render 가 `UNREFERENCED_FIGURE` 로 멈췄다.
  claims 가 빈 절은 그 절 그림의 캡션·근거 id 를 claims 로 받아 근거 추적성이 0점이 되지 않는다.
- live writer 에게 양식 소제목(1-1~4-3)·보고서체·금지 표기(마크다운 표·그림 캡션·절 제목 반복)를 알린다.
  지침은 모델로 가는 길에만 붙어 replay 캐시·mock fixture 는 그대로다. 병렬 검토자는 Hermes 한 번의 응답(600초)을 기다린다.
- `inputs/PLAN.md` — 과제 설계(개요·KPI 줄·월 구간 일정)를 적는 자리. `corpus` 가 `corpus/plan-brief.md` 로 싣는다.
- `render` 는 `images` 가 만들지 않은 그림을 `UNGENERATED-FIGURES`(exit 5)로 거부한다(가짜 그림은 draft preview 로만, 게시 불가).
- `refine` 은 Codex CLI 미로그인·전송 실패를 `host-unauthenticated`/`transport-failed`(exit 6)로 정확히 보고하고
  `codex login` 조치를 안내한다. 예전에는 같은 상황이 `invariant-failed`(문장 검사 실패)로 표시됐다.
- `images`(codex 전송기)는 codex 0.144 가 갤러리에 저장하는 `exec-<id>.png` 도 받아 온다. 노드 codex 샌드박스(bubblewrap)가
  셸 복사를 막아 작업 폴더에는 그림이 오지 않고 갤러리에만 남는데, 전송기가 옛 이름 `ig_*.png` 만 찾아 생성된 그림을 모두 버렸다.
  빠진 그림은 `IMAGE-MISSING <id>: <사유>` 로 이유를 남긴다.
- Drive 게시는 gws 가 JSON 을 다시 직렬화해도, 같은 값이 돌아오고 Drive `sha256Checksum` 이 로컬 바이트와 같으면 통과한다.
- 마운트된 스킬의 렌더에서 용어 교정이 `ImportError` 로 항상 빠지던 문제를 고쳤다.

## 왜

2026-09-28 `excavator-diagnostic-closed-loop-2026` v000001 은 참조 제안서(`excavator` v000011)에 크게 못 미쳤다. 원인은 다음과 같았다.

1. 파이프라인 표에 "엔진 draft" 단계가 있었지만 CLI 명령이 없었다. 에이전트는 본문과 계획을 손으로 쓰고,
   다른 제안서의 planspec 을 복사했으며, 양식 소제목을 문자열 치환으로 끼워 넣었다.
2. 엔진 planner 는 KPI·일정 숫자를 근거에서만 뽑는다. v000011 코퍼스에는 소유자가 정리한 계획 문서 8개(각 2~4KB)가 있었지만,
   새 코퍼스는 100~400바이트 조각뿐이었다.
3. 노드 agent 의 Codex CLI 가 한 번도 로그인된 적이 없어 그림 생성과 윤문이 모두 401 로 실패했다.
   에이전트는 PIL 로 도형 그림(같은 해시 2장 포함)을 그렸고, render 는 그것을 막지 않았다.
4. 윤문 실패가 `REFINEMENT_INVARIANT_FAILED` 로 표시돼 원인 진단이 엇나갔다.
5. 첫 실측에서 엔진 초안도 양식과 어긋났다 — 절 제목을 반복하고 마크다운 표를 글자로 찍었으며, 양식 소제목은 비었고,
   그림 자리가 없어 렌더가 멈췄고, 근거 추적성은 0.00, 검토자 두 명은 60초 제한에 걸려 의견이 버려졌다.
6. JSON 재다운로드 해시가 어긋나 게시가 실패했고, 에이전트는 로컬 JSON 을 gws 형식으로 고쳐 쓰는 우회로 통과시켰다.

## 사용 시나리오

**정상.** 소유자가 "굴착기 신규 제안서"를 요청하면 에이전트는 `research` → SYNTHESIS·PLAN 작성 →
`corpus` → `compose` → figures.json 작성 → `figures` → `images` → `refine` → `render` → `visual-review` → `publish` 순서로 진행한다.
compose 가 엔진으로 절·표·계획을 만들고, 그림은 images 가 생성한다.

**거부.** PLAN.md 에 KPI 줄이 없으면 `compose` 가 `No public KPI evidence … add KPI lines to inputs/PLAN.md` 로 멈춘다.
손으로 그린 그림이 있으면 `render` 가 `UNGENERATED-FIGURES` 로 멈춘다. Codex CLI 가 로그인되지 않았으면 `refine` 은
`REFINEMENT-HOST-SKIPPED reason=host-unauthenticated` 와 `REFINEMENT-REMEDY` 를 내고, `preflight --stage refine` 은 blocked 다.

**소유자 몫.** 노드 agent 계정에서 `codex login` 을 한 번 해야 그림 생성(codex 전송기)과 윤문이 동작한다.
Hermes 게이트웨이 OAuth 와 별개의 자격증명이다.
