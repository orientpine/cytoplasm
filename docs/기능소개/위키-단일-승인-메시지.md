# 위키 확인 메시지 — 단일 라이브 승인

## 무엇을
위키 초안의 확인 메시지를 공유 승인 생명주기(`request_owner_approval`)로 게시한다.
초안 하나가 속한 승인 키(`wiki:{action}:{slug}`)에는 **살아 있는 확인 메시지가 항상 1건**뿐이며,
저장된 `confirm_message_id`는 **덮어써지지 않는다** — 옛 메시지를 지운 뒤에만 교체된다.

## 왜
기존 게이트는 `post_confirm_message`를 다시 부를 때마다 같은 초안 레코드의
`confirm_message_id`를 새 메시지 id로 **말없이 갈아치웠다**. 워처는 저장된 id 하나만
폴링하므로, cha가 먼저 올라온 메시지에 ✅를 눌러 두었다면 그 승인은 오류 한 줄 없이
**영구히 보이지 않게** 됐다(초안은 pending으로 남아 저장되지 않음).

## 사용 시나리오

### 정상 경로
1. `wiki draft`로 초안을 만들고 확인 메시지를 게시한다 → `#approvals`에 1건(✅·⛔ 선부착).
2. 같은 초안으로 다시 게시해도 **아무것도 올라가지 않는다** — 기존 메시지가 그대로 유효하다.
3. 본문을 고쳐 새 초안을 만들고 게시하면, 옛 메시지를 **먼저 지운 뒤** 레코드를 풀고
   새 메시지를 올린다(살아 있는 메시지는 여전히 1건).
4. cha가 ✅를 누르면 리액션 워처가 기존 `wiki_gate.resolve_reaction`으로 저장한다.

### 실패·거부 경로
- cha가 이미 ✅/⛔를 누른 뒤 다시 게시하면 → 메시지를 지우지 않고 `owner-decided`로 연기(거부 종료).
- 메시지 본문이 초안 sha256을 참조하지 않으면 → `binding-mismatch`로 거부(삭제·해제 없음).
- 초안 파일이 하나라도 손상되면 → `store-unreadable`로 거부(건너뛰면 중복 게시가 되므로 fail-closed).
- 리포지토리(`AUTOPHAGY_REPO_ROOT`)에서 파사드를 import하지 못하면 → 무가드 게시로 폴백하지 않고 거부.
