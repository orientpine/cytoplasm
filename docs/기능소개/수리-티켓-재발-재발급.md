# 닫힌 수리 카드의 재발이 새 카드를 연다

## 무엇을

종결(`done`·`archived`)된 수리 카드와 **같은 시그니처의 실패가 다시 나면 새 카드를 발급**하고 occurrence 를
1 부터 다시 센다. 새 카드 본문에는 `Supersedes closed card: t_…` 한 줄이 들어가 보드에서 두 카드가 이어진다.
카드 상태를 읽을 수 없으면 예전 동작(기존 카드의 occurrence 증가)을 그대로 유지한다.

## 왜

- `RepairRegistry.claim` 이 시그니처로 찾은 카드의 **상태를 보지 않아** 종결된 카드가 재발을 조용히 흡수했다.
  실측: `t_318263ba` 2,623회 · `t_c0718520` 2,233회 · `t_6f3f7e1e` 2,078회. 카드가 닫힌 뒤의 재발은 보드의
  열린 목록에 아무것도 만들지 않아 소유자가 볼 신호가 없었다.
- 상태를 보게 만든 것만으로는 부족했다. `hermes kanban create --idempotency-key` 는 **non-archived 카드가 같은
  키를 갖고 있으면 그 카드 id 를 돌려준다**(`docs/qa/RRC-0/01-cli-contract.md` ④). 키를 그대로 재사용하면
  `done` 카드의 재발이 바로 그 닫힌 카드로 되돌아가고 occurrence 만 1 로 리셋돼 이전보다 나빠진다.
- 판정은 detect 경로에 있으므로 **보드가 느릴 때 값을 치르면 안 된다**. 조회 실패는 예전 동작으로 떨어지는
  fail-soft 라, 오래 기다릴 이유가 없다.

## 사용 시나리오

**happy** — 소유자가 `t_318263ba` 를 종결한다. 며칠 뒤 같은 워처가 같은 오류로 다시 실패한다 →
detect 가 `hermes kanban show t_318263ba --json` 으로 `status: done` 을 읽고 새 카드 `t_…` 를 만든다.
새 카드는 `needs_input` 으로 블록되고, 본문 마지막 줄이 `Supersedes closed card: t_318263ba` 다.
멱등키는 `repair-<signature>-after-t_318263ba` 라 닫힌 카드와 충돌하지 않는다.

**실패(fail-soft)** — 보드가 응답하지 않는다 → 조회는 10초에 포기하고(mutation 은 60초 유지), 재발은
**예전 그대로** 기존 카드의 occurrence 를 올린다. 읽을 수 없는 보드에 카드를 두 장 만드는 쪽이 덜 세는
쪽보다 나쁘기 때문이다. `is_closed` 를 주입하지 않은 호출자도 같은 경로로 동작한다.
