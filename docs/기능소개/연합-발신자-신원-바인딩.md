# 연합 발신자 신원 바인딩 (W-F2.5-B)

## 무엇을

Discord 인터롭 봉투와 `#agents-log` 보고가 주장하는 에이전트 ID를 실제 메시지 작성자와
그룹 roster에 함께 묶는다. 세 값이 정확히 일치하는 메시지만 위임 처리 또는 개인 RAG
적재로 넘어간다.

## 왜

기존 경계는 봉투의 수신자와 보고 형식만 확인해, 다른 봇이 roster 멤버의 `sender_id`나
`agent_id`를 본문에 쓰는 사칭을 막지 못했다. 2봇 사설 길드에서는 위험이 작았지만 공개
연합에서는 위조된 동의·업무 보고가 정상 주체의 발화처럼 처리되거나 개인 지식에 남을 수
있었다.

## 사용 시나리오

### 정상 흐름

1. active 멤버의 Discord 작성자 ID가 roster의 해당 `node_label`에 연결돼 있다.
2. 그 봇이 같은 값을 `sender_id` 또는 보고 `agent_id`로 보낸다.
3. Hermes는 봉투를 처리하고, RAG 인제스트는 보고를 `peer-report`로 큐잉해 개인 컬렉션에
   적재한다.

### 실패·거부 흐름

- 다른 멤버·미등록 봇·`removed` 멤버가 정상 멤버의 ID를 주장하면 warning을 남기고
  즉시 거부한다.
- 봉투는 응답 생성과 결과 전달이 0건이며, 사칭 보고는 `LogicalDocument`·내구 큐·MCP
  `load_memory` 호출이 모두 0건이다.
- roster가 없거나 파싱되지 않으면 신원을 추측하지 않고 해당 경계를 fail-closed로 멈춘다.

- 회귀 테스트: `tests/unit/test_group_roster_sender_identity.py`,
  `tests/unit/test_interop_channel_routing.py`, `tests/unit/test_rag_ingest_discord_identity.py`
- 규약·계획: `docs/guide/interop-규약.md`, `.omo/plans/public-release.md` W-F2.5-B

  담당한다.
