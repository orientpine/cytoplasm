# 캘린더 같은 일정 중복 방지

새 일정을 만들기 전에 같은 캘린더의 그날 일정을 읽어, **같은 날짜 · 겹치는 시간 ·
비슷한 제목**의 일정이 이미 있으면 새로 만들지 않는다. 먼저 있던 일정을 남긴다.

## 왜

메일 다이제스트는 제목 낱말 묶음이 정확히 같아야 같은 일정으로 보았다. 후속 메일이
제목에 낱말 하나(예: "회의실")만 더해도 다른 일정으로 보고 카드를 또 올렸고, ✅ 하면
같은 시각에 같은 일정이 두 개 생겼다(소유자 지적 2026-10-21).

## 판정

- 같은 캘린더, 시작의 KST 날짜가 같고, `[시작, 종료)` 구간이 겹친다(끝과 시작이 맞닿기만
  하면 겹치지 않는다). 종일 일정·취소된 일정은 비교하지 않는다.
- 제목은 NFKC·대소문자 무시 뒤 글자·숫자만 남겨 비교한다(괄호·띄어쓰기·문장부호 무시).
  같거나, 짧은 쪽(4글자 이상)이 긴 쪽에 들어 있거나, `difflib.SequenceMatcher` 비율이
  **0.6 이상**이면 비슷하다. 0.6은 표준 라이브러리 `difflib.get_close_matches`의 기본
  기준값이다. 두 제목 모두에 숫자가 있는데 서로 포함하지 않으면(1차/2차, 301호/302호)
  다른 일정이다.
- 경계 시험: 시간만 겹치고 제목이 다름 → 만든다. 제목이 같고 날짜가 다름 → 만든다.
  끝과 시작이 맞닿음 → 만든다. 낱말 하나 차이 → 만들지 않는다.

## 사용 시나리오

1. **카드를 만들 때**: 메일에서 나온 일정 카드가 올라가기 전에 그날을 읽는다. 같은
   일정이 있으면 카드(v6)에 `작업: 생성 안 함 …`과 `이미 있음: <기존 제목> · <날짜 시각>`이
   보인다. 이 표시는 승인 해시 밖이며 ✅의 범위를 줄이기만 한다 — ✅ 해도 만들지 않고,
   카드 아래 답글로 `🔁 … 이미 있음`이 달린다. 그날을 읽지 못하면 표시 없이 예전 카드를 올린다.
2. **실행 직전**: ✅(또는 소유자 직접 지시) 뒤 Google에 쓰기 직전에 다시 읽는다. 같은
   일정이 있으면 만들지 않고 초안을 `duplicate`로 봉인, 감사 기록 `skipped-duplicate`를
   남기며 같은 `🔁 … 이미 있음` 답글을 단다. 그날을 읽지 못하면 만들지 않는다(fail-closed,
   다음 틱 재시도). 소유자 직접 지시는 `OWNER-COMMAND-ALREADY-EXISTS … existing=<제목 · 시각>`을 낸다.
3. **이미 생겨 버렸을 때(동시 실행 경합, 소유자 규칙 Q62)**: 만든 직후 그날을 다시 읽어
   비슷한 일정이 **먼저**(`created`가 더 이른) 있으면 방금 이 승인이 만든 일정을 지운다
   (`sendUpdates=none`). 방금 만든 일정에 참석자가 있으면 지우지 않고 기존 삭제 승인 카드를
   올려 소유자에게 먼저 묻는다. 다른 일정은 읽기만 한다.

결과 답글은 다른 결과 통지처럼 draft id와 동작만 담는다(SKILL.md 절대 규칙 3) — 어느
일정인지는 카드 본문에 있다.

## 관련

- `skills/calendar/scripts/calendar_dedupe.py`(판정·조회·건너뜀 기록), `calendar_after_insert.py`(경합 정리·기본색),
  `calendar_preflight.guarded_execute_draft`(유일한 실행 경계), `calendar_card.py`(v6 카드), `confirm_reaction_watch.py`(답글)
- 승인 해시(`draft_sha256`)·동결 argv·기존 v1~v5 카드는 바뀌지 않는다.
- 이미 생긴 운영 캘린더의 중복은 이 기능이 고치지 않는다(과거 일정은 읽기만).
