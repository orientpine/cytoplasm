# 대시보드 비밀번호 교체

## 무엇을

`<primary-node>`의 소유자용 대시보드 로그인(Kanban, report-hub) 비밀번호를 **명령 한 번으로** 안전하게
새로 발급하고, 실패하면 자동으로 원래대로 되돌리는 도구다.

## 왜

이전에는 교체 절차가 문서에 없었다. report-hub만 가이드에 한 줄 있었고 Kanban은 아무 데도 없어서,
2026-07-27 노출 대응 때 러닝 프로바이더 코드를 역공학해 검증값 형식을 알아내야 했다. 이건 단순한
불편이 아니라 위험이다 — Kanban 검증값은 `scrypt$n$r$p$salt$dk` 인코딩이라 **형식이 조금이라도
어긋나면 프로바이더가 fail-closed로 거부**해서 소유자가 자기 대시보드에서 잠긴다. 손으로 교체하는
한 이 사고는 언제든 재발한다.

또한 교체는 파일 2개(검증값 + 소유자 기록)를 동시에 맞춰야 하고, 하나만 바뀌면 잠긴다.

## 사용 시나리오

### 비밀번호를 새로 발급한다 (happy path)

```bash
ssh <primary-node> 'sudo -n -u agent python3 \
  /srv/autophagy-agents/automation/credential_rotation/rotate_cli.py kanban'
ssh <primary-node> 'sudo -n -u ops python3 \
  /srv/autophagy-agents/automation/credential_rotation/rotate_cli.py report-hub'
```

도구는 노드에서 새 비밀번호를 만들고 → 검증값을 갱신하고 → 대시보드 유닛만 재시작하고 →
**새 비밀번호로 실제 로그인을 시도해** 성공을 확인한 뒤 끝난다. 화면에는 상태만 나오고
비밀번호 자체는 절대 출력되지 않는다(노출 제거가 목적인데 다시 흘리면 의미가 없다).

확인은 `<primary-node>`에서:

```bash
autophagy-cred      # Kanban + report-hub 둘 다
```

Kanban은 세션 서명키도 같이 바뀌므로 열려 있던 브라우저 세션은 다시 로그인해야 한다. 이건 의도된
동작이다 — 유출된 비밀번호로 이미 만들어진 세션 쿠키는 비밀번호만 바꿔서는 죽지 않는다.

### 교체가 실패한다 (실패 경로)

새 비밀번호로 로그인 probe가 실패하면 도구가 **검증값·기록 파일을 원본 그대로 되돌리고 유닛을
다시 재시작한 뒤** non-zero로 끝난다. 즉 실패해도 기존 비밀번호로 계속 들어갈 수 있다. 이 자동
복구가 이 도구의 핵심 안전 장치다.

키가 하나라도 없거나 기록 파일에 `password:` 줄이 없으면 **아무것도 쓰기 전에** 중단한다.

## 노드 재구축 시 alias 복원

위 `autophagy-cred`는 **어느 프로비저닝 스크립트에도 없다** — `~<operator-account>/.bash_aliases`에만 존재하므로 노드를 재구축하면 소유자가 자기 비밀번호를 꺼내 볼 유일한 표면이 조용히 사라진다. 재구축 후 같은 파일에 다음을 다시 넣는다:

```bash
# autophagy-cred-alias — 대시보드 Basic auth 크리덴셜 조회 (owner 전용, mode-600)
alias kanban-cred="sudo -n -u agent cat /home/agent/.hermes/dashboard-cha-credentials.txt"
alias reporthub-cred="sudo -n -u ops cat /home/ops/report-hub/dashboard-cha-credentials.txt"
alias autophagy-cred="kanban-cred; echo; reporthub-cred"
```

alias 자체에는 비밀이 없다 — `sudo -n -u <account> cat <path>` 형태의 **조회 명령**일 뿐이다. 따라서 이 문서에 적어도 안전하고, 실제 값은 각 계정 홈의 mode-600 파일에만 있다. 이 사실을 문서에 고정해 둔 이유는 alias가 프로비저닝 밖에 살고 있기 때문이다(2026-08-04 확인: `provision-agent.sh`·`bootstrap-accounts.sh` 모두 미포함).
운영 명령이다. 자격증명 값·URL은 repo·QA 증적·공개 채널에 남기지 않는다.
