# 유돌이 대시보드 할 일·지시 목록 읽기

## 무엇을
유돌이 노드 게이트 읽기 명령 `todo-list [--open] [--json]` 과 `order-list [--open] [--json]` 으로 대시보드의 승인된 할 일과
형이 쓴 지시를 목록으로 받는다. 읽기만 하고 대시보드 파일은 만들거나 바꾸지 않는다.

## 왜
형이 "유돌이는 대시보드에 있는 업무를 처리하는 걸 목표로 하면 어때?", "유돌이가 대시보드 관리를 해주면 좋을 것 같아"(2026-11-02)라고 했고,
Q454 에서 "형이 넣은 할 일은 바로 처리, 메일·회의에서 자동으로 뽑힌 건 쓰기 전에 형에게 물음"을 골랐다. 그런데 유돌에게는
완료(`todo-done`)만 있고 무엇이 남았는지 볼 길이 없었다(`todo-list` 는 `unknown command` 로 거절됐다).

## 사용 시나리오
- 할 일: `todo-list --open --json` → JSON 배열. 열린 할 일(열림·진행·보류)마다 `todo_id`(`todo-done` 이 받는 id 그대로)·업무·제목·담당·마감·
  상태·진척·`source_kind`(mail/meeting)·출처 id·출처 제목(120자까지, 안의 메일 주소는 `[주소]`)·승인 시각·갱신 시각·보안 등급·메모(200자까지, 넘으면 자르고 `note_truncated`)가 마감 이른 순(마감 없음은 끝)으로 온다.
  유돌은 `source_kind` 로 메일·회의에서 뽑힌 할 일을 가려, 쓰기 전에 형에게 묻는다. `--json` 없이 보내면 한 줄에 하나(`TODO <id> status=… due=… source=…`).
- 지시: `order-list --open --json` → 끝나지 않은 지시마다 번호·작성 시각·상태·본문(500자까지, 넘으면 `body_truncated`)·걸린 할 일·업무·
  `via`·`owner_device`(형 기기에서 쓴 지시인지)·받는 도리·맡은 도리·도리 방 글 링크가 오래된 순으로 온다. 형 지시는 바로 처리한다.
- 대시보드가 아직 없으면 `[]`(빈 목록)이고 파일을 새로 만들지 않는다.
- 거절(`YOODORI-GATE-REFUSED`, rc 2): `--open`·`--json` 말고 다른 인자, 같은 인자 두 번, 셸 문자(`;` `|` `$` 등).
- 나가지 않는 것: 메일 보낸 사람·본문·주소, 지시를 쓴 로그인(메일 주소 모양일 수 있음)·기기 id·주소.

## 관련
- 코드: `automation/project_board/agent_read.py`(읽기 전용 연결, 상한·가림), `automation/project_board/cli.py`
  (`todo-list`·`order-list`), `automation/yoodori_gate/yoodori_read_gate.py`(허용 목록·인자 검사).
- 게이트 기록(`~/.local/state/yoodori-gate.log`)은 명령 이름과 rc 만 남긴다.
- 승인: 카드 없음, 읽기 전용. 완료 쓰기는 기존 [할 일 완료](유돌-대시보드-할일-완료.md), 지시 상태 쓰기는 [도리에게 지시](프로젝트-대시보드-도리-지시.md).
