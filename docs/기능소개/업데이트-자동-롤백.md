# 업데이트 재시작·스모크·자동 롤백

## 무엇을

자동 업데이트가 `current`를 새 릴리스로 전환하면 agent·peer Hermes gateway를 항상 한
세트로 재시작하고 기존 deploy-smoke를 실행합니다. 재시작 또는 스모크가 실패하면 이전
릴리스로 포인터와 실행 프로세스를 함께 되돌립니다.

## 왜

포인터만 새 코드로 바꾸면 이미 실행 중인 gateway는 구 코드를 계속 사용하고, 실패 시
포인터만 되돌리면 새 코드로 기동된 프로세스가 남습니다. 또한 실패한 SHA를 매 tick 다시
적용하면 gateway가 반복 재시작되는 플랩이 생깁니다. 따라서 적용·검증·복구와 실패 SHA
차단을 하나의 흐름으로 묶습니다.

## 사용 시나리오

- **정상 업데이트**: 새 서명 릴리스가 수렴하면 `current`가 전진하고 양 gateway가 함께
  재시작됩니다. deploy-smoke가 통과하면 새 릴리스가 유지됩니다.
- **스모크 실패**: `current`를 이전 세대로 원자적으로 복원하고 양 gateway를 다시
  재시작한 뒤 활성 상태를 확인합니다. 기존 owner notice 경로로 한 번 알리고 같은 SHA는
  다음 tick부터 재시도하지 않습니다.
- **부분 재시작 실패**: agent 또는 peer 한쪽 명령만 실패해도 정상 경로를 계속 진행하지
  않고 위와 동일한 롤백 트랜잭션으로 수렴합니다.
