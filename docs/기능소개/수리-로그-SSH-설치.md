# 수리 로그 SSH 설치

레거시 노드 설치는 수리 로그를 agent에서 ops의 비공개 저장소로 보내는 SSH 경로도
준비한다. 새 노드에서 전용 키가 빠져 수리 카드 기록이 계속 실패하던 #235를 고친다.

## 사용 시나리오

노드 설치 계획을 적용하면 agent의 `~/.ssh/autophagy-repair-log` 키 쌍을 만들고,
ops의 `authorized_keys`에 수리 로그 수신기만 실행할 수 있는 `restrict,command`
바인딩을 넣는다. agent의 `known_hosts`에는 노드 자신의 ed25519 호스트 공개키를
`127.0.0.1`용으로 추가한다. 기존 키와 다른 SSH 항목은 보존한다.

그 뒤 일일 메일 수리 작업이 실패를 발견하면 기존 수리 CLI가 같은 경로로 원문 로그를
비공개 저장소에 남길 수 있다. 카드 승인과 수리 적용 절차는 그대로다.
다시 계획하면 자산이 온전한 경우 이 설치 액션은 나오지 않는다.

키 쌍의 한쪽만 남았거나 같은 공개키에 충돌하는 권한 바인딩이 있으면 설치는 중단한다.
로컬 호스트 공개키를 읽거나 해석할 수 없어도 중단하며, 알 수 없는 키를 네트워크에서
받아 신뢰하지 않는다. 개인키 내용을 출력하지 않고 SSH 호스트키 검증도 끄지 않는다.
