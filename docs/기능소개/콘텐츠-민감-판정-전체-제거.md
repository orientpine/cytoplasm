# 콘텐츠 민감 판정 전체 제거 — 모든 내용을 같은 경로로

## 무엇을

키워드·정규식·모델로 문서·메일·전사·보고서·제안서를 "민감/특허/기밀"로 나누던 판정과 그 효과를 저장소 전체에서 없앴다. 회의 스킬(v1.18.0)에 이어 mail·report·proposal·doctype·topics·prompt·recall·patent-prep·speechtotext·RAG 인제스트·지식 계층·트윈·위키 큐레이터·메모리·Plaud 라이프로그·모델 호출 경로가 모두 같은 처리를 한다.

## 왜

소유자 결정(2026-10-09): 운영자와 구성원이 모두 보안 관리자 등급이라, 내용 낱말에 따라 게시를 막거나 마스킹하거나 모델을 제한할 이유가 없다. 판정은 오히려 비공개 노트가 자기 요약을 잃거나, 주제가 등록되지 않거나, 카드가 가려져 소유자가 무엇을 승인하는지 모르는 문제를 만들었다.

## 사용 시나리오

- **특허 낱말이 든 메일**: 예전에는 다이제스트 제목이 `[민감]` 으로 가려지고 요약이 비었다. 이제 다른 메일과 같이 요약되고 회신 초안 카드에 본문이 그대로 보인다. 발송은 여전히 소유자 ✅ 뒤에만 일어난다.
- **기밀 낱말이 든 주제 등록**: `topics add` 가 거부하던 주제가 이제 그대로 등록되고 주간 연구 동향에 포함된다.
- **특허 녹음의 라이프로그**: 예전에는 추출이 `민감도 게이트` 로 생략됐다. 이제 같은 모델 체인(주 모델 → 폴백)으로 요약·사람·장소를 뽑는다.
- **recall 검색**: `patent-sensitive` 센티널이나 제외 없이 근거가 있는 결과를 모두 돌려준다.

## 남긴 것 (보안 장치)

경로 검증(경로 탐색·심볼릭 링크), 비밀값·누출 검사(gitleaks·public_gate·leak-guard), 소유자 ✅ 승인 게이트, 인증·권한, 서명 검증, 입력 크기 제한, 배포본 실행 사본 가드, 제안서의 개인 노트 출처 경계(내용이 아니라 출처로 정하는 접근 제한), 특허 산출물의 전용 반출 게이트(Drive gate-only), 승인 스레드·결과 통지의 스킬별 고정 마스킹 규칙.

## 기존 데이터

기존 데이터는 그대로다. 분리 저장된 파일, 마스킹된 카드, 민감 태그가 붙은 색인을 옮기거나 다시 처리하지 않는다. 옛 레코드의 민감 필드는 읽을 때 무시된다. 노드에 남은 옛 규칙 파일 사본도 지우지 않는다(더 이상 읽지 않는다).
