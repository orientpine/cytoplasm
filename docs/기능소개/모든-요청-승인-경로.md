# 모든 요청에 승인 경로 — BCC 다수 메일·Drive 저장·그 밖의 외부 작업

## 무엇을

오토파지가 외부효과가 있는 요청을 받으면 "이 작업은 승인 경로가 없다"로 멈추지 않고 승인 카드를 띄운다. 형이 ✅ 를 한 번 누르면 워처가 실행하고 결과를 같은 스레드에 남긴다. 새로 생긴 경로는 셋이다.

- **숨은참조(BCC) 다수 메일**: 메일 `compose --bcc` / `--bcc-file`
- **Drive 저장(비공개)**: `python3 -m automation.effect_request request drive-save`
- **그 밖의 외부 작업**: `python3 -m automation.effect_request request command`

## 왜

2026-10-17 세미나 신청자 41명에게 안내 메일을 BCC로 보내는 요청과 조회 결과 파일의 Drive 저장 요청이 둘 다 "승인 경로가 없다"로 끝났다. 형의 지시는 이랬다: "이 경로 만들어 모든 요청에 대한 경로가 있어야 해".

## 사용 시나리오

**BCC 안내 메일.** 형: "신청자 41명에게 이 메일을 숨은참조로 보내 줘." 에이전트는 받는 사람(To)에 형 주소를 두고 신청자 목록 파일로 초안을 만든다.

```bash
python3 triage_cli.py compose --to <형 주소> --bcc-file <목록.csv> --bcc-column <주소 열> \
  --subject '<제목>' --body '<본문>' --origin-channel-id <채널> --origin-message-id <메시지>
```

카드에는 `총 수신자 42명 (받는 사람 1 · 참조 0 · 숨은참조 41)`, 도메인별 인원, 제목, 본문이 실린다. 주소는 카드에 없다. ✅ 를 누르면 메일 한 통이 41명에게 숨은참조로 나간다. mailon 은 웹메일 폼에 들어간 숨은참조 집합이 승인한 목록과 정확히 같은지 확인한 뒤에만 보낸다. 목록에 없는 주소가 끼거나 빠지면 보내지 않는다.

**조회 결과 Drive 저장.** 형: "그 결과 파일 Drive에 저장해 줘."

```bash
cd /srv/autophagy-agent-current && python3 -m automation.effect_request request drive-save \
  --file <결과.csv> --summary '세미나 신청자 조회 결과 저장' --origin-channel-id <채널> --origin-message-id <메시지>
```

카드에는 파일 이름, Drive 위치(`autophagy/문서/2026/2026-10-17_<제목>.csv`), 공유 범위(비공개 — 형 계정만), 크기, sha256 이 실린다. ✅ 뒤 워처가 요청 때 동결한 사본을 올리고 다시 내려받아 sha256 을 확인한 다음 링크를 남긴다.

2026-11-13 이슈 #241: `--file` 을 여러 번 주면 카드 하나·✅ 한 번으로 모두 저장하고, `--folder <폴더 id>` 로 형 Drive 의 아무 폴더(형만 볼 수 있는 폴더)에 저장한다. 일부가 실패하면 나머지는 올리고 실패한 파일만 다시 시도한다([소개](drive-여러-파일-한-카드.md)).

2026-10-18 Q233 "6개 다 카드 없이 바로 + 하루 요약에 남기기": 유돌 게이트가 형 본인의 지시와 `auto-write-drive-save` 전환을 확인하면 같은 인자의 `python3 -m automation.effect_request save-now`로 카드 없이 동결·비공개 발행·sha256 재검증을 수행하고, `owner_command` 영수증과 지시 좌표를 남기며 성공 표식으로 잡 러너의 하루 요약 원장에 연결한다.

**그 밖의 작업.** 전용 스킬이 없는 외부 작업(예: 실험 서버 웹훅 호출)은 `request command --summary … --target … -- <명령>` 으로 카드를 올린다. 카드에 실행할 명령 전체가 실리고, ✅ 뒤 정확히 한 번 실행한다. 실패해도 다시 실행하지 않는다.

**거절되는 경우.** 비밀번호·키 변경, 결제·송금, 로그인·2단계 인증, sudo, 승인 반응 대리 누름은 형만 할 수 있는 일이다. 명령은 `EFFECT-REQUEST-REFUSED code=owner-only:<종류>`(exit 4)와 사유를 내고, 에이전트는 그 사유를 형에게 그대로 전한다. 메일·일정·할 일·Obsidian·Drive 공유처럼 전용 경로가 있는 일은 그 명령을 안내한다. 연결된 도구 자체가 없는 일(예: 카카오톡 방 게시)은 승인 경로가 아니라 도구가 없다고 보고한다.
