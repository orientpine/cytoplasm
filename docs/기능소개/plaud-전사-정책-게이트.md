# Plaud 전사 정책 게이트

## 무엇을

라이프로그 로컬 전사에 **보류 백오프·총 실패 상한·최소 녹음 길이**를 적용한다.
Plaud 요약이 없으면 사람·장소·결정·할 일을 추출하는 **같은 LLM 호출**에서 만든
한국어 마크다운 요약을 `## 요약`에 사용한다. Plaud 요약이 있는 노트는 기존 본문 바이트를 유지한다.

## 왜

클라우드 요약·전사가 모두 없는 녹음이 매 10분 틱마다 로컬 전사를 다시 돌고,
실수로 만든 1초 녹음도 전사 대기에 남았다. 로컬 전문이 있어도 요약은 비어 있었다.
새 정책은 빈 노트의 승인 요청을 막으면서 새 녹음에 전사 슬롯을 남긴다.

## 동작·설정

노드의 기존 `PLAUD_SYNC_*` 환경 설정 경로를 사용한다. 기본값만으로 동작한다.

| 설정 | 기본값 | 의미 |
|---|---:|---|
| `PLAUD_SYNC_MIN_DURATION_MS` | 5000 | 이 값 **미만**은 발견 시 건너뜀. 정확히 같은 길이는 허용 |
| `PLAUD_SYNC_TRANSCRIBE_ATTEMPTS` | 2 | 녹음 실패가 이 횟수에 닿으면 클라우드 폴백 검토 |
| `PLAUD_SYNC_TRANSCRIBE_GIVE_UP` | 5 | 클라우드도 비어 있을 때 허용할 총 로컬 실패 횟수 |
| `PLAUD_SYNC_TRANSCRIBE_PER_TICK` | 1 | 한 틱의 로컬 전사 슬롯. 보류 중 클라우드 재확인은 별도 |

- 폴백이 보류되면 마지막 시도 뒤 **1·2·4·8·16·24시간(이후 최대 24시간)** 간격으로
  로컬 전사를 재시도한다. 기본값에서는 2회 실패 후 1시간, 3회 후 2시간, 4회 후 4시간 대기하고
  5회째 실패에도 클라우드가 비어 있으면 `abandoned`로 닫는다.
- 매 틱 클라우드는 재확인한다(전사 잠금이 바빠도 수행). 콘텐츠가 생기면 백오프 만료를 기다리지 않고
  기존 폴백 경로로 승격한다. 조회 장애는 부재가 아니므로 폐기하지 않는다.
- 일정은 선택 필드 `next_transcribe_at`(ISO-8601 UTC)에 저장한다. 필드 없는 옛 레코드도 읽는다.
  기존 실패 횟수가 총 상한 이상이면 로컬 전사를 더 돌리지 않고 클라우드를 확인한 뒤 종결한다.
- 짧은 신규 녹음은 상태 레코드·동결 노트·승인 카드가 생기지 않는다. 이미 `transcribing`인 짧은 녹음은
  다음 처리 때 원본 길이를 확인해 `N초 녹음 — 최소 길이 미만` 사유로 폐기한다.
- 환경 실패는 기존처럼 로컬 실패 횟수에 포함하지 않는다. `PLAUD_SYNC_TRANSCRIBE=0` 킬스위치도 유지한다.

## 사용 시나리오

1. **정상**: 20분 녹음 → 로컬 전문 생성 → 단일 추출 호출에서 요약 불릿 3–6개도 생성 →
   Plaud 요약이 없을 때만 채택 → 기존 소유자 ✅ 후 Obsidian 저장. 민감도 게이트는 그대로이며 추가 호출은 없다.
2. **보류**: 로컬 2회 실패·클라우드 비어 있음 → 저널에 `outcome=retry next_transcribe_at=…` →
   대기 틱에는 `outcome=waiting` → 새 녹음은 남은 슬롯으로 처리. 클라우드가 준비되면 즉시 승격한다.
3. **거부·종결**: 1초 녹음은 `outcome=skipped duration_ms=1000` 한 줄로 보고한다.
   총 상한에 닿은 실패는 `outcome=abandoned`와 `로컬 전사 N회 실패·클라우드 요약/전사 없음 — 폐기`를 남긴다.
   폐기된 레코드는 다음 틱의 대상이 아니다. 기존 게시·저장 노트는 소급 변경하지 않는다.
