# 옛 기관메일에 답장해도 인용 줄과 보낸 날짜가 바르게 나간다

## 무엇을

회신·후속 메일 아래 붙는 원문 인용이 두 가지에서 바르게 나간다.

- **줄**: 원문 HTML 없이 저장된 메일(2026-10-19 전에 수집된 메일)을 인용할 때, 낱말·문장부호마다 끊겨 있던 줄을 이어 붙여 문장 단위로 보낸다.
- **보낸 날짜**: 인용 머리의 `보낸 날짜`를 저장값의 시간대 그대로 읽어 한국 시각으로 한 번만 바꾼다.

## 왜

2026-10-29 형이 10/13 받은 메일에 답장을 보낸 뒤 "답변 메일은 정상적인데, 뒤에 붙인 기존 메일이 엔터가 이상하잖아"라고 했다. 같은 인용의 `보낸 날짜`도 11:12 가 아니라 20:12 로 나갔다.

- **줄**: MailOn 은 본문 글자를 HTML 의 글자 덩어리마다 줄을 바꿔 저장한다(`scraper.py` 의 `get_text("\n", strip=True)`). Outlook 메일은 한글·영문·숫자·문장부호가 따로 덩어리라 '안녕하세요 / , / 박사님 / !' 처럼 저장된다. 10-19 부터는 원문 HTML 을 따로 저장해 HTML 인용을 쓰지만, 그 전에 수집된 메일은 HTML 이 없어 이 글자를 그대로 인용했다.
- **날짜**: MailOn 은 받은 시각을 시간대 없이 **메일 호스트의 현지 시각**으로 저장한다(`parse_millis` 의 `datetime.fromtimestamp`, 래퍼가 `TZ` 를 그대로 넘김). 10-19 수정은 UTC 호스트를 보고 "시간대 없는 값 = UTC"로 정했는데, 한국 시간대 호스트에서는 이미 한국 시각인 값에 9시간을 한 번 더 더했다.

## 사용 시나리오

- 형이 몇 주 전 받은 거래처 메일에 답장을 시킨다. 원문 HTML 이 없는 메일이면 인용 본문이 '안녕하세요, 박사님!' 처럼 문장으로 이어져 나가고, `보낸 날짜`는 형 메일함에 보이는 받은 시각과 같다.
- 원문 HTML 이 저장된 메일(10-19 이후 수집)은 지금처럼 HTML 인용이 나가고 그 인용 본문은 바뀌지 않는다. 날짜만 바르게 나간다.
- 빈 줄이 있거나 문장부호만 있는 줄이 두 줄 미만인 글자 본문(Gmail 전달 원문 등)은 끊긴 저장 모양이 아니므로 그대로 인용한다.
- 이음은 HTML 이 없는 글자에서 줄 경계를 추정하는 것이라 완벽하지 않다. 서명·주소처럼 짧은 줄이 이어진 곳은 한 줄로 합쳐질 수 있다. 원문 HTML 이 함께 저장된 메일 31통으로 맞춰 본 결과 잘못 끊긴 줄 경계는 1,589개에서 514개로 줄고, 잘못 이어진 경계가 203개 생겼다.
- 이미 저장된 초안은 승인 해시에 묶인 본문 그대로 나간다. 이 릴리스 뒤에 만든 초안부터 바뀐다.
