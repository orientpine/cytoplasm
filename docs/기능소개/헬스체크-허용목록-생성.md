# 헬스체크 허용목록 생성 — 손으로 고치던 노드 파일을 릴리스가 만든다

## 무엇을

헬스체크가 노드로 보내는 ssh 명령의 **허용목록(강제명령 래퍼)** 을 릴리스에서 생성하고,
그 래퍼가 현재 체크 목록과 어긋나면 헬스체크가 잡아낸다.

## 왜

헬스체크 전용 ssh 키는 `authorized_keys` 에서
`command="~/.local/libexec/autophagy-healthcheck-probe"` 에 묶여 있다. 그 래퍼는
`SSH_ORIGINAL_COMMAND` 의 sha256 **정확 일치**만 통과시키고 나머지는 `exit 126` 이다.

그래서 체크를 하나 추가하면 노드의 그 파일도 함께 고쳐야 하는데, **리포에 설치기가 없어
아무도 그 사실을 말해주지 않았다.** 2026-08-20 실측:

| | |
|---|---|
| 헬스체크가 보내는 명령 | 43 |
| 허용목록 밖 → 거부 | **23** |
| 아무도 안 보내는 잔여 해시 | 14 |

거부된 23개에는 다른 세션이 추가한 체크들과, **실패한 체크가 수리 티켓을 내는 경로**가
들어 있었다. 그래서 조용했다 — 거부당한 프로브는 자기 하나만 실패하고, 그 실패를
보고하려는 티켓까지 같은 이유로 거부되므로 밖으로 나가는 신호가 없다.

## 사용 시나리오

**체크를 추가했을 때 (happy path)**

1. 새 프로브를 머지하면 2분 리컨실러가 릴리스를 수렴시킨다.
2. 다음 헬스체크 틱에서 래퍼 프로브가 FAIL 하고 재생성 명령을 그대로 찍는다:
   `WRAPPER-DRIFT: the wrapper was built from an older check list`
3. 노드 운영자 계정에서 멱등 프로비저너를 한 줄 실행한다 — **root 권한이 필요 없다**
   (운영자 계정 소유 파일):
   ```bash
   /srv/autophagy-agent-current/automation/provision-healthcheck-probe.sh <node>
   ```
   첫 실행은 `WRAPPER-INSTALLED`, 이미 같은 바이트·mode 0755면 파일을 다시 쓰지 않고
   `WRAPPER-UNCHANGED`를 낸다. 예전 `healthcheck_probe_wrapper.sh --install` 명령도
   이 프로비저너로 위임되므로 두 설치 구현이 생기지 않는다.
4. 다음 틱에서 `WRAPPER-PASS: the allowlist matches the current checks (…)`.

**래퍼가 너무 낡아 프로브 자신을 거부할 때 (실패 경로)**

프로브의 명령조차 목록에 없으면 그 거부가 곧 답이다 —
`WRAPPER-DRIFT: the wrapper rejected this probe or the node is unreachable` 로 FAIL 하고
같은 재생성 명령을 낸다. 헤더가 아예 없는 손 유지보수본도 마찬가지로 잡힌다.

## 어떻게 만드나

목록을 **추론하지 않고 관측한다.** 생성기는 헬스체크를 그대로 불러 `capture_on_node` 를
기록용으로 갈아끼운 뒤 모든 체크를 한 바퀴 돈다 — 실제 ssh 는 한 번도 나가지 않는다.
그래서 프로브가 명령을 바꿔도 생성기는 고칠 것이 없다. 목록을 여기에 베껴 적으면 그
사본이 다시 낡기 시작하는데, 그것이 애초에 없애려던 문제다.

`healthcheck_allowlist_manifest.sh --probe-hashes [node]`는 같은 관측 결과를
`sha256<TAB>command`로 정렬 출력한다. 사람이 계산한 두 번째 해시 표가 아니라 생성기 함수
하나를 래퍼·입력 지문·검토 매니페스트가 함께 쓴다. RC-1의 분산 배포 선언에서 파생된 중앙
매니페스트도 입력 지문에 들어가므로 선언이 바뀌면 설치본 드리프트가 된다.

판정은 래퍼 헤더의 `# wrapper-inputs:` 한 줄로 한다. 생성기가 그 값을 `LIVE_CHECKS` 와
워처 매니페스트에서 계산해 박아두므로, 매 5분 틱마다 전수 기록을 다시 돌리지 않는다.

**한계**: 기록은 프로브를 실제로 돌리는 것이라, 프로브가 로컬 사유로 조기 반환하면 그 뒤
명령은 기록되지 않는다. 그래서 `--install` 은 노드에서 돌린다. 잘린 채 굳어도 지문
프로브가 다음 틱에 드러낸다.

## 관련

- 생성기 `automation/healthcheck_probe_wrapper.sh` · 설치기
  `automation/provision-healthcheck-probe.sh` · 프로브
  `automation/healthcheck_wrapper_probe.sh`
- 체크 이름 `healthcheck probe allowlist matches the checks` (`healthcheck_wrapper_current`)
- 원격 프로브다 — 래퍼는 운영자 홈에 있어 cron 계정(ops)이 읽지 못한다.
- 승인 게이트가 아니다. 재생성은 노드 운영자가 직접 실행한다.
