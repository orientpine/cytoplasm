# 기능 소개 — 기관메일 회신·후속메일 원문 인용

**완료:** 2026-09-01 · **스킬:** `mail` · **모듈:** `skills/mail/scripts/mail_quote.py`

## 무엇을
기관메일 회신(`draft`)과 후속 메일(`compose --in-reply-to`)이 메일 클라이언트의 회신처럼 **원문(보낸 사람·보낸 날짜·받는 사람·참조·제목 + 본문)을 발송 본문 하단에 인용**한 채 나간다. `draft --reply-all` 은 원문의 받는 사람·참조 전원을 Cc 로 넣는 전체회신이다.

## 왜
vendor mailon 런타임에는 답장 명령이 없고 모든 발송이 새 메일 compose 라, 회신이 **새로 쓴 문장만** 실려 나갔다(2026-09-01 소유자 관찰). 상대는 무엇에 대한 답인지 스레드에서 찾아야 했고, 후속 안내 메일은 맥락이 끊겼다. 인용은 발송 본문에만 붙고 승인 메시지는 한 줄로만 알리므로, Discord 2,000자 한도와 소유자 검토 부담은 그대로다.

## 핵심 동작 (불변식)
- 발송 본문 = `<회신문>` + 빈 줄 + `-----원본 메시지-----` 헤더 블록 + 원문 본문. 원문은 wrapper `get --body` 의 mailon markdown(frontmatter + `## Body`)에서 파싱하며, 문서가 없거나 형식이 다르면 행 메타데이터로 헤더만 인용한다(예외 없음). 20,000자 초과 원문은 절단 마커.
- draft 레코드의 `body` 는 소유자가 검토하는 회신문만, `quote` 는 인용 블록, argv 는 둘을 합친 실제 발송 텍스트 — 셋 모두 승인 sha256 에 바인딩된다. 인용 없는 기존 레코드의 해시는 바이트 동일(회귀 고정).
- 전체회신 Cc = 원문 To∪Cc − 소유자(`MAILON_ID`) − 발신자. 승인 메시지에 `- Cc:` 로 표시되어 소유자가 수신자 집합을 눈으로 확정한다.
- `compose --in-reply-to` 의 인용 원문은 민감도 게이트에 합산된다 — 원문에 특허 관련 문구가 있으면 후속 메일이 민감 초안으로 격리된다.

## 사용 시나리오
1. **(happy)** cha "3번 메일, 화요일 오전으로 확정한다고 회신해줘" → `draft --uid <uid> --instruction …` → 승인 스레드에 회신문 + `- 원문 인용: 포함` → ✅ → 상대는 회신문 아래에 자기 메일 원문이 인용된 답장을 받는다.
2. **(전체회신)** cha "모두에게 전체회신해줘" → `draft … --reply-all` → 승인 메시지에 `- Cc: park@…, lee@…` → ✅ → 원문 수신자 전원에게 발송.
3. **(후속)** cha "어제 보낸 안내 메일에 이어 일정 변경 알려줘" → `compose --to … --subject "Re: …" --body … --in-reply-to <어제 메일 uid>` → 원문이 인용된 후속 메일.
4. **(안전)** 인용 원문에 `특허 출원` 이 있으면 후속 초안이 `patent-sensitive` 로 태깅되어 mail 홈의 민감 초안 저장소에 격리된다.
