# 세션 워크트리 브랜치 가드

## 무엇을

세션 워크트리가 `main`으로 직접 push하는 실수를 로컬 `pre-push` 훅이 거부한다. 세션
브랜치 push와 메인 checkout의 정식 착지 흐름은 그대로 허용한다.

## 왜

현재 GitHub 요금제에서는 private 저장소의 main branch protection을 켤 수 없다. 그래서
토큰을 가진 세션이 PR 리뷰를 건너뛰고 main을 직접 갱신할 수 있었다. 프로덕션 자체는
provenance와 승인 게이트로 보호되지만, Git 이력과 리뷰 규율을 지키는 저비용 방어가 필요했다.

## 사용 시나리오

### 정상 경로

1. cha 또는 에이전트가 `automation/worktree.sh start g0-branch-guard`로 세션을 시작한다.
2. 스크립트가 shared Git hooks 디렉터리에 가드를 멱등 설치한다.
3. 세션은 `session/g0-branch-guard`를 push하고 main 대상 PR을 연다.
4. cha가 GitHub에서 diff를 검토하고 merge한다.

### 거부 경로

세션 워크트리에서 `git push origin HEAD:main`을 실행하면 훅이 non-zero로 종료해 원격 main은
움직이지 않는다. 반면 메인 checkout에서 `automation/land.sh`가 수행하는 main push는
checkout의 `.git`이 디렉터리이므로 통과한다. 우회 환경변수는 제공하지 않는다.

## 관련

- 설치: `automation/worktree.sh`
- 훅: `automation/hooks/pre-push`
- 회귀: `tests/unit/test_session_worktree_branch_guard.py`
- 규약: [세션 워크트리 브랜치 가드](../guide/session-worktree-branch-guard.md)
- 계획: `.omo/plans/parallel-followup-sweep.md` G0

이 기능은 승인 게이트나 배포가 필요한 외부효과가 아니다. branch push와 PR 생성까지만 수행하고
main merge는 cha에게 남긴다.
