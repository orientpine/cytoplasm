# 개인 스킬 배포

## 무엇을

각 사용자가 `~/.hermes/personal-skills/<name>/`의 독립 Git 저장소에서 자기 스킬을
저작하고 `automation/deploy-skill.sh --personal <name>`으로 설치합니다. 개인 스킬도
SANDBOX → REVIEW → peer attestation → 본인 ✅ → MOUNT의 기존 4단계 게이트를 그대로
통과합니다.

## 왜

기존 기본 경로는 관리자 repo의 `skills/<name>`과 `origin/main`을 대조하므로 개인 스킬도
관리자 repo에 넣어야 했습니다. 개인 저장소에는 별도 provenance가 필요합니다. 원격 브랜치와
비교하는 대신 현재 브랜치의 커밋된 HEAD, 깨끗한 worktree, untracked 비-ignored 파일 부재를
확인하고 그 HEAD SHA를 승인 레코드에 묶습니다. 따라서 관리자 업데이트와 개인 저작 이력이
서로 섞이지 않으면서 승인 안전성은 유지됩니다.

## 사용 시나리오

### 정상 배포

1. `~/.hermes/personal-skills/my-skill/`에 `SKILL.md`와 필수 scenario를 작성합니다.
2. 해당 디렉터리에서 파일을 `git add`·`git commit`합니다. Git 저장소가 아니면 첫
   `--personal` 실행이 저장소를 초기화하지만, 커밋은 사용자가 만들어야 합니다.
3. `automation/deploy-skill.sh --personal my-skill`을 실행하고 승인 요청의 개인 HEAD SHA를
   확인한 뒤 ✅를 누릅니다.
4. MOUNT 직전에 같은 HEAD와 clean 상태를 다시 확인한 뒤, 커밋의 `git archive` 바이트만
   immutable store에 설치합니다.

### 거부 경로

- 수정·staged·untracked 비-ignored 파일이 있거나 HEAD가 미커밋/detached이면
  `DEPLOY-BLOCK`으로 stage 1 전에 중단합니다. ignored runtime residue는 배포 입력이 아니므로
  허용합니다.
- 승인 뒤 HEAD가 달라지면 MOUNT 직전 재검사에서 중단합니다.
- `managed-` 접두사는 개인 모드에서 즉시 거부하며, 같은 base 이름의 live managed skill과
  충돌해도 기존 양방향 `COLLISION-BLOCK`이 적용됩니다.
