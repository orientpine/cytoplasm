# 기능 소개 — 기관메일 첨부 발송

**완료:** 2026-07-25 · **티켓:** repair `t_c6f9e704` · **스킬:** `mail` (+ `emailAutomation`)

## 무엇을
승인형 기관메일에 **파일 첨부를 붙여 발송**한다. 첨부를 메일 제공자 화면에 업로드하고, 서버가 발급한 파일 UID로 업로드 완료를 검증한 뒤에만 실제 발송이 진행된다.

## 왜
이전엔 첨부 업로드가 미구현이라, 첨부가 있으면 발송 경로가 막히고 **일반 "검증 실패"처럼 오표시**되어 원인 파악이 어려웠다. 이제 첨부 발송이 정상 동작하고, 첨부 없는 기존 흐름은 그대로다.

## 핵심 동작 (불변식)
- **첨부 매니페스트**(파일명·크기·MIME·SHA-256)를 승인 hash에 바인딩 → 승인 후 파일을 재검증하고 발송.
- **업로드 성공(서버 UID 확보) 시에만 발송.** 부분 업로드·매니페스트 불일치는 fail-closed로 발송 중단.
- **오류 분류 정정**: 기능 미지원/업로드 실패 = `attachment_unsupported`/`attachment_*`(재시도 불가, send-failure 카운터 미증가) vs 실제 발송 실패 = `send_failed`/`send_unverified`(카운터 증가). 민감 파일 내용·경로·이름은 로그·승인·오류 메시지에 **비노출**.
- 모든 발송은 소유자(cha) `#approvals` ✅ 승인 게이트 경유(기존 불변식 유지).

## 사용 시나리오
1. **(happy)** cha "이 PDF 첨부해서 보내줘" → 에이전트가 첨부 매니페스트 포함 초안 생성 → `#approvals`에 승인 요청 → cha ✅ → 업로드 → 서버 UID 검증 → 발송. 성공 결과에 `attachment_count`·`attachment_manifest_sha256` 반영.
2. **(거부)** 존재하지 않는 파일 → `attachment_invalid`(입력 검증), 지원 안 하는 형식/미구현 → `attachment_unsupported` 로 **명확히 구분 안내**, 발송 안 함(더 이상 검증 실패로 혼동되지 않음).
3. **(안전)** 업로드 도중 일부 실패 → 발송 중단 + 중복 발송 방지 안내. 이 실패들은 send-failure 카운터를 올리지 않는다.
