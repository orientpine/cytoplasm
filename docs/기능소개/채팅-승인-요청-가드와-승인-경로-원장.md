# 채팅 ✅ 요청 가드와 승인 경로 원장

## 무엇을

두 가지 장치가 함께 움직인다. 첫째, 에이전트 답장이 승인 카드 링크 없이 소유자에게 ✅를 요청하면 게이트웨이가 그 줄을 「이 작업은 표준 승인 경로를 거치지 않았다」 안내로 바꾼다. 둘째, 게이트 대상 외부효과를 새로 추가했는데 카드 생산자·✅ 워처·테스트가 없으면 빌드가 실패한다.

## 왜

2026-10-07 경로와 본문을 받은 Obsidian 저장 요청에는 승인 카드를 올릴 명령이 없었다. 에이전트는 초안을 손으로 만든 뒤 "이 메시지에 ✅로 승인해 주십시오"라고 썼다. 소유자가 ✅를 눌렀지만 채팅 메시지의 ✅를 읽는 워처는 없으므로 아무것도 실행되지 않았다. 게이트는 승인 없는 실행만 막을 뿐이고, 승인할 길을 만들어 주지는 않는다.

## 사용 시나리오

- **승인 경로가 없는 작업**: 에이전트가 "이 메시지에 ✅ 눌러 주세요"라고 쓰면, 소유자에게는 그 줄 대신 「⚠ 이 작업은 표준 승인 경로를 거치지 않았습니다 … 승인 경로가 없다고 보고해야 합니다」가 보인다. 소유자는 ✅를 누르는 대신 경로를 만들어 달라고 요청한다.
- **정상 승인 요청**: 답장에 `APPROVAL-THREAD … url=` 링크나 Discord 스레드 링크가 있으면 답장은 그대로 나간다. 저장 완료(「✅ … 완료」) 같은 영수증도 바뀌지 않는다.
- **새 외부효과 추가**: 개발자가 `configs/external-effect-tools.yaml` 에 규칙을 더하거나 새 승인 생산자를 인벤토리에 올리면, `tests/unit/test_gated_effect_paths_conformance.py` 가 생산자·워처(선언된 cron, systemd 유닛, 또는 `manual:` 사유)·테스트 파일을 적을 때까지 RED 를 낸다.
