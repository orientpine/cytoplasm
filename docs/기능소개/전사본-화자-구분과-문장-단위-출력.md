# 전사본 화자 구분과 문장 단위 출력

## 무엇을

녹취 전사본이 이제 **한 줄에 한 문장**으로 쓰이고, 문장 묶음마다 `[00:03:12] 화자1 · 김민수`
같은 헤더가 붙는다. 화자 구분은 노드에서 sherpa-onnx 로 직접 하고, 이름은 자기소개 규칙과
회의록 LLM 이 함께 제안하며 소유자가 언제든 정정한다.

## 왜

94분짜리 실제 녹취가 문단 140줄로 나왔고 가장 긴 줄이 1,137자였다. 내용은 정확했지만 소유자가
그 안에서 아무것도 찾지 못했다. 같은 녹취를 문장 줄로 쓰면 735줄이 되고, 각 블록이 언제
시작했는지가 줄 위에 적힌다. 타임스탬프는 whisper.cpp 가 원래 토큰마다 주던 값인데 예전 경로가
구간을 한 문자열로 이어 붙이며 버리고 있었다.

화자 쪽은 더 단순한 결핍이었다. 누가 무엇을 말했는지가 전사본에 없으니 회의록의 "타인
액션아이템"은 전부 LLM 의 문맥 추론에 의존했다. 이제 라벨이 문서에 남아 회의록이 그것을 읽는다.

## 사용 시나리오

**정상 경로.** 소유자가 `autophagy/회의녹음` 폴더에 킥오프 녹음을 올린다. 5분 틱 워처가 집어
로컬 whisper.cpp(GPU)로 전사하고, 같은 오디오를 sherpa-onnx(CPU)로 화자 분리해 문장마다
`화자1`, `화자2` 를 붙인다. "저는 김민수라고 합니다"를 말한 화자에는 이름이 붙고, 전사본 머리말에
범례 한 줄이 남는다:

```
- 화자: 화자1=김민수 [자기소개 00:03:12] · 화자2=이영희 [LLM] · 화자3=미상
```

본문은 이렇게 읽힌다:

```
[00:03:12] 화자1 · 김민수
안녕하세요, 저는 김민수라고 합니다.
오늘은 해양 계측 일정부터 보겠습니다.
```

이어서 `meeting ingest` 가 돌고, 회의록 머리말에도 같은 `- 화자:` 줄이 들어간다.

**sherpa 가 없는 노드.** 바이너리나 모델 경로가 비어 있으면 stderr 에 `DIARIZE-FAIL <사유>` 한
줄만 찍고 전사를 그대로 계속한다. 결과는 화자 헤더가 없는 문장 줄 문서, 즉 예전과 같은 정보에
읽기 편한 형태다. 화자 구분 때문에 전사가 실패하는 경우는 없다.

**이름이 어긋날 때.** 규칙은 자기소개로 `화자2=이영희` 를 잡았는데 회의록 LLM 이 `박철수` 를
제안하면 규칙 이름을 유지하고 이견을 범례에 적는다: `화자2=이영희 [자기소개 00:05:40 · LLM
제안: 박철수]`. 소유자가 실제로 어느 쪽이 맞는지 알면 오디오·비용 없이 고친다:

```bash
python3 ~/.hermes/skills/speechtotext/scripts/speechtotext_cli.py polish \
  --file <전사본.md> --speakers "화자2=박철수"
```

소유자 값은 자기소개와 LLM 을 모두 이기고, 다시 다듬어도 유지된다. 이름은 판정이 아니라 제안이며
최종 결정권은 소유자에게 있다.

## 관련

- 스킬: `skills/speechtotext/` — `stt_blocks.py`(블록 문법·타임스탬프) ·
  `stt_diarize.py`(sherpa-onnx 실행·문장 배정) · `stt_speakers.py`(이름 추론·병합·범례) ·
  `stt_speaker_flow.py`(전사 → 이름 → meeting 회신 흡수) · `speechtotext_cli.py`
  (`--speaker-count` · `--no-diarize` · `polish --speakers`)
- 회의록: [`meeting`](../../skills/meeting/SKILL.md) v1.6.0 — v6 프롬프트의 `speakers` 키,
  회의록 머리말 `- 화자:` 줄, `ingest` 결과 JSON 의 `speakers` 배열
- 설정: `SPEECHTOTEXT_DIARIZE_BIN` · `_SEGMENTATION` · `_EMBEDDING` · `_THRESHOLD` ·
  `_THREADS` · `_TIMEOUT` (셋 중 하나라도 비면 화자 없이 진행)
- 승인 게이트: **바뀐 것이 없다.** 화자 분리는 노드 안에서만 돌아 음성이 밖으로 나가지 않고,
  회의록의 외부효과는 meeting 의 기존 게이트가 그대로 소유한다. 새 외부효과는 없다.
- 소개: [음성 녹취 → 전사본 → 회의록 자동화](음성-녹취-회의록-자동화.md)
