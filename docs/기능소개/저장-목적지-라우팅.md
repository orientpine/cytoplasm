# 문서 저장 목적지 라우팅

## 무엇을

문서를 저장하라는 요청을 받으면 **어디에 저장할지 코드가 결정론적으로 판정**한다. "개인노트로 저장해줘"는 Obsidian에만, 목적지를 말하지 않은 문서 저장은 cha 본인 Google Drive 비공개로, 저장 의도가 없는 대화는 아무 데도 저장하지 않는다. 애매하면 **저장하지 않고 되묻는다**.

## 왜

기존에는 이 규칙이 `SKILL.md` 산문으로만 있었다. 산문 라우팅은 LLM이 매번 다시 해석하므로, 같은 요청이 어떤 날은 Obsidian에만 가고 어떤 날은 Drive에도 올라간다. 실제로 이전 규칙은 "항상 Obsidian과 Drive에 동시 저장"이었고, 개인 노트가 의도치 않게 외부 서비스로 나가는 구조였다.

이 리포는 도메인이 겹치는 스킬의 mutating 경로에 **결정론적 코드 가드**를 요구한다(calendar↔coordination 선례). 저장 목적지도 같은 부류의 문제라 같은 방식으로 고정했다.

## 사용 시나리오

**happy path — 개인 노트**

```
cha: "이 회의 정리한 거 개인노트로 저장해줘"
→ 라우터: destinations=("obsidian",) reason=personal-note
→ Obsidian PARA 폴더에 Markdown 저장 (Drive 업로드 호출 0회)
```

Drive 동시 저장을 따로 요청하지 않는 한 Drive로는 나가지 않는다.

**happy path — 목적지 미지정**

```
cha: "이 내용으로 안내문 만들어서 저장해줘"
→ 라우터: destinations=("drive",) reason=default-drive
→ 본인 Drive에 비공개 업로드 → 재다운로드 SHA-256 + owner-only 권한 검증
```

**거부 경로 — 모호한 요청**

```
cha: "옵시디언이나 드라이브 중 하나에 저장해줘"
→ SAVE-CLARIFY reason=ambiguous candidates=obsidian,drive,local
→ exit 5, 저장 부작용 0건
```

어느 쪽인지 고르지 않았으므로 추측해서 올리지 않고 되묻는다. 특허·민감 문서는 이 기본값보다 **전용 반출 게이트가 우선**한다.
