# H3 배포 위생: 스냅샷 정리·일일 스모크·미러 조사

## 무엇을

배포 전용 임시 worktree 누수를 안전하게 회수하고, `hello-autophagy`의 sandbox 단계가
매일 실제 배포보다 먼저 깨짐을 알리며, 배포 미러 git 디렉터리의 파일 소유 분포를
읽기 전용으로 조사한다.

## 왜

스냅샷의 `RETURN` trap이 sourced caller의 trap을 오염시키면서 `/tmp`에 등록 worktree가
남은 선례가 있었다. 또한 노드 설치본·외부 CLI·파일 모드 결함은 3천여 단위 테스트가
통과해도 실제 배포 때만 드러났다. 미러에는 과거 수리 자동화가 만든 소유권·로컬 ref
잔재가 있어, 자동 삭제가 아니라 OWNER가 판단할 수 있는 근거가 필요했다.

## 사용 시나리오

- **정상 경로**: 배포 수렴이 `origin_snapshot_run`을 호출하면 6시간을 넘긴 미등록
  스냅샷만 lock 안에서 회수한다. 일일 timer는 `hello-autophagy --sandbox-only`를 실행하고
  결과를 `~/.hermes/deploy-smoke/tick.json`에 원자적으로 기록한다.
- **실패·거부 경로**: `git worktree list --porcelain`을 읽지 못하면 stale 삭제는 0건이다.
  스모크 runner가 실패하면 같은 exit code로 종료하고 tick에는 `failure`가 남는다.
  등록 worktree와 보호 브랜치는 보존하며, 미러 inventory·브랜치 삭제는 OWNER가 실제
  노드에서 별도로 수행한다.
