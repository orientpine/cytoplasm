# 공개 누출 게이트 (public_gate)

## 무엇을
커밋·push·PR 때마다 공개되면 안 되는 것을 막는 검사다. 세 가지를 본다.
- **금지 경로**: 세션 증거(`.omo`)와 웨이브 QA(`docs/qa`)는 `git add -f` 로도 들어가지 못한다.
- **설치 토폴로지**: tailnet 주소와 운영 노드 호스트명(반출 익명화와 같은 규칙).
- **비공개 금칙어**: 실명·호스트·Discord id·과제명 같은 값. 목록은 비공개 ops 저장소(`leak/denylist.txt`)에만 있고, **새로 추가되는 줄과 커밋 메시지·PR 본문**에만 대조한다. 이미 공개된 값이 무관한 편집을 막지 않는다.

찾은 값은 출력하지 않는다. 파일·줄·규칙 번호만 알려 준다(공개 저장소의 Actions 로그는 공개다).

## 왜
지금까지는 공개 배포본에 나가는 길이 `automation/public_export.sh` 하나였고, 검사도 그 반출 때만 돌았다. 공개 저장소에서 직접 개발하면 브랜치를 push 하는 순간 공개되고, 커밋 메시지와 PR 본문도 공개된다. 한 번 나간 것은 포크·캐시에 남아 회수할 수 없으므로 검사를 push **전**으로 당긴다.

## 어떻게 쓰나
- 공개 저장소 체크아웃에서 한 번: `automation/ops_link.sh <ops 저장소 경로>`. `.omo`·`docs/qa` 를 ops 저장소로 잇는 심볼릭 링크를 만들고, git 이 그 링크를 보지 못하게 하고(`/.omo` — 끝 슬래시 없이), pre-commit·commit-msg·pre-push 훅을 설치한다. 그 뒤 `automation/worktree.sh start` 가 만드는 워크트리마다 같은 연결이 자동으로 걸린다.
- 손으로 돌리기: `python3 -m automation.public_gate staged` / `message <파일>` / `range origin/main HEAD`.
- `automation/local_ci.sh run` 에 `public-gate` 단계가 들어 있어 영수증이 이 검사까지 증명한다. GitHub 에서는 `leak-guard` 잡이 고정 버전 gitleaks(카나리아 도달 확인 포함)와 이 검사를 PR 범위에 돌린다. 금칙어 목록은 저장소 비밀 `LEAK_DENYLIST` 로만 받는다.
- 수리 자동화는 브랜치를 push 하기 직전에 같은 검사를 실행 중인 런타임에서 돌리고, 거부되면 push 하지 않는다.

## 사용 시나리오
- **정상**: 기능 커밋 → 훅 통과 → `local_ci.sh run` 영수증 → push.
- **거부**: 노드 주소가 섞인 로그 한 줄을 테스트 픽스처로 붙였다 → pre-commit 이 `fixtures/x.txt:3: topology (tailnet address)` 로 거부. 값은 출력되지 않는다. 픽스처를 합성 값으로 바꾸면 통과한다.
- **설정 고장**: 금칙어 경로가 설정돼 있는데 읽을 수 없다 → `PUBLIC-GATE-CONFIG` 로 커밋을 막는다(fail-closed). 설정이 아예 없는 제3자 체크아웃은 경로·토폴로지 검사만 돈다.

## 관련
`automation/public_gate.py`, `automation/ops_link.sh`, `automation/hooks/public-gate-pre-commit`·`public-gate-commit-msg`·`pre-push`, `.github/workflows/ci.yml`(leak-guard), `automation/repair/repair_ops_work_clone.py`. 비공개 원본 체크아웃(`.omo` 추적 + 반출 매니페스트)에서는 반출 제외 경로를 건너뛰고 메시지를 검사하지 않는다 — private 이력은 반출되지 않기 때문이다.
