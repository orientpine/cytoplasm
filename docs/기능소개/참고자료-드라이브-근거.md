# 참고자료 드라이브 근거

## 무엇을

소유자가 Google Drive 「내 드라이브/KIMM」 폴더에 참고자료를 모아 두면, 에이전트가 회의록 작성 같은 작업에서 그 폴더를 뒤져 근거 구절을 찾아 쓴다. 폴더는 **읽기만** 한다. 폴더도 파일도 새로 만들지 않는다.

## 왜

에이전트가 아는 것은 그때그때 주어진 입력뿐이었다. 기관 내부에서만 쓰는 과제명·장비명·약어는 발표자료에 한 번 스쳐 지나가고, 회의록에는 잘못 적힌 채로 남았다. 소유자는 같은 용어를 매번 다시 알려줘야 했다.

정답은 이미 소유자 드라이브에 있다. 그래서 새 저장소를 만드는 대신 그 폴더를 근거로 읽는다. 루트 이름은 `DRIVE_REFERENCE_ROOT`로 바꿀 수 있고 기본값은 `KIMM`이다. `/`로 중첩 경로도 된다(`KIMM/회의자료`). Drive 접근 자체는 기존 옵트인 `DRIVE_PUBLISH_ENABLED=1`을 그대로 따르므로 새로 열어야 하는 권한이 없다.

읽는 형식은 pdf·pptx·docx·hwpx·xlsx·md·txt·csv, 그리고 Google 문서·슬라이드·스프레드시트는 내보내기로 읽는다. 읽을 수 없는 것 — Google 설문, 구형 바이너리 `.hwp`, 64MiB 초과 파일 — 은 **내려받기 전에** 사유만 남기고 뒤로 밀린다. 그래서 읽을 수 있는 자료가 먼저 조회되고, 6.8GiB 짜리 압축본을 받아 본 뒤에 못 읽는다고 말하는 일이 없다. `.hwp` 는 "hwpx 나 pdf 로 저장해 주세요"라고 안내한다. 한 파일을 못 읽어도 조회 전체는 살아 있고, 참고자료를 하나도 못 써도 회의록 작성은 계속된다. 탐색 상한은 폴더 깊이 4단계·폴더 60개·파일 400개이고, 본문까지 내려받는 것은 기본 3건이다(`--limit`).

## 사용 시나리오

**happy path — 직접 조회**

```
cha: python3 skills/recall/scripts/recall_reference.py "<질의>" --limit 3
→ KIMM 루트에서 문서 64개를 훑음
→ 질의어에 맞는 Google 스프레드시트를 CSV로 내보내 근거 구절 321자 반환
→ 파일명 · Drive 링크 · 근거 구절 출력, exit 0
```

같은 조회에서 Google 설문 2건은 내보낼 수 없어 사유만 남았다. 조회는 사유가 있어도 exit 0으로 끝난다. 사유는 본문에 적히므로 종료 코드로 분기할 필요가 없다. `--json`으로 기계용 출력도 받는다.

**happy path — 회의록 자동 사용**

meeting ingest가 회의 라벨·과제명에 **전사 본문의 상위 낱말**(구어 군더더기는 빼고 최대 6개)을 더한 질의로 참고자료를 찾아 발표자료와 **같은 Deck 경로**로 넣는다. 파일명에 과제명이 없어도 회의에서 오래 이야기한 주제라면 걸린다. 그래서 참고자료도 민감도 게이트에 함께 합산된다(특허 자료가 GLM으로 새지 않는다). 추출 프롬프트에는 「소유자 참고자료」 블록으로 들어가고, 회의록 헤더 표에 `| 참고자료 | <파일명> |` 행으로 남는다. 어떤 자료를 근거로 썼는지는 회의록만 봐도 안다.

**거부·건너뜀 경로**

```
DRIVE_PUBLISH_ENABLED 미설정
→ Drive 호출 0회, REFERENCE-DISABLED 사유만 남고 종료
```

```
DRIVE_REFERENCE_ROOT 가 가리키는 루트가 없음
→ 폴더를 만들지 않고 REFERENCE-ROOT-MISSING 으로 종료
```

없는 루트 이름으로 실행한 뒤 Drive를 다시 조회해 빈 목록임을 확인했다. 읽기 전용은 산문이 아니라 실측이다.
