# 메일 승인 요청 답장에 승인 스레드 링크 싣기

## 무엇을

메일 초안(`draft`)이나 새 메일(`compose`)을 승인 스레드에 올리면, mail CLI가 그 스레드의 Discord 링크를 한 줄 더 출력합니다. 에이전트는 소유자에게 보내는 답장에 이 링크를 그대로 넣습니다.

```
COMPOSED draft=abc123 posted=1
APPROVAL-THREAD draft=abc123 url=https://discord.com/channels/<서버>/<스레드>
```

## 왜

2026-09-23 `#agent-chat` 사례입니다. 동료 연구자에게 보낼 메일 초안을 게시한 뒤, 에이전트는 "승인 스레드에 게시했습니다 … 승인 스레드에서 ✅를 누르면 발송됩니다"라고만 답했습니다. 어느 스레드인지는 알려 주지 않아 소유자가 직접 찾아야 했습니다.

원인은 CLI 출력에 있었습니다. 출력이 `COMPOSED draft=<id> posted=1`뿐이어서 에이전트가 인용할 좌표가 없었습니다. 좌표 자체는 승인 바인딩 때 draft 레코드(`approval_guild_id`·`approval_thread_id`, 승인 해시 밖)에 이미 저장되어 있었습니다.

## 사용 시나리오

- **정상 경로**: "OO 박사님께 소개 자료 메일 써줘"라고 요청합니다. 에이전트가 `compose`를 실행하면 초안이 게시되고 `APPROVAL-THREAD … url=…` 줄이 출력됩니다. 답장은 "승인 스레드: <링크>" 형태가 되고, 소유자는 링크를 눌러 곧바로 ✅할 수 있습니다.
- **좌표 미상**: 서버 좌표가 없는 옛 바인딩은 `url=unavailable search=<draft id>`로 출력됩니다. 이때 에이전트는 링크를 추측하지 않고 draft id로 검색하라고 안내합니다. `@me` 같은 추측 링크는 만들지 않는다는 「소유자 메시지 계약 규칙」을 따릅니다.
- **미게시**: `posted=0`이면 링크 줄이 출력되지 않으며, 에이전트는 게시했다고 말하지 않습니다.
