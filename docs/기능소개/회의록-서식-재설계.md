# 회의록 서식 재설계 — 근거는 하단, 발표자료로 지시어 교정

## 무엇을

`meeting` 스킬이 만드는 회의록 노트를 연구 회의록 표준 골격으로 다시 그린다. 근거는 본문에서
떼어내 문서 하단 부록으로 내리고(같은 파일 안), `--slides`로 받은 발표자료를 대명사·모호
지시어 교정 재료로 추출 프롬프트에 넣는다.

## 왜

기존 노트는 세 가지가 겹쳐 읽히지 않았다.

1. **근거가 본문을 덮었다.** 액션아이템 한 줄이 `제목 — 마감: 2026-07-24 — 근거: 차: 데이터셋
   사전 7/24까지 작성` 이라, 근거 문장이 제목보다 길어 목록을 훑을 수 없었다.
2. **원문 전사본이 본문 중간에 통째로 있었다.** 90분 회의면 노트의 대부분이 전사본이고
   결정사항은 스크롤 위로 사라진다.
3. **뼈대가 없었다.** 일시·참석자·장소·자료가 적히는 헤더도, 한눈 요약도, 담당·마감이 보이는
   표도, 미결 질문도 없었다. 제목의 날짜는 회의 날짜가 아니라 **처리 시각**이었다.

여기에 더해, 녹취에서 뽑은 회의록은 "이거", "그쪽", "저번 거" 같은 지시어를 그대로 물고
들어온다. 무엇을 가리키는지 아는 자료(발표자료)가 손에 있어도 쓸 방법이 없었다.

## 어떻게 바뀌었나

문서는 **부록 경계선**을 기준으로 둘로 나뉜다.

| 위 (회의록 본문) | 아래 (`## 부록 · 근거와 원문`) |
|---|---|
| 메타데이터 헤더 (일시·장소·참석·발표자료·원본·작성) | A. 근거 원문 — `[근1]`…의 정의 |
| 한눈에 보기 (TL;DR) | B. 선행 근거 — 지식 파사드 `[E1]` 출처 |
| 결정사항 / 액션 아이템(표) / 마일스톤(표) | C. 원문 전사본 |
| 논의 요지 / 미결·확인 필요 / 다음 회의 | |

본문에는 `[근1]` 같은 짧은 마커만 남는다. 비어 있는 조건부 섹션은 통째로 생략해서 `- (없음)`이
여섯 줄 늘어서지 않는다. 헤더 일시는 추출한 **회의 날짜**를 쓴다.

`[^1]` 각주 문법은 일부러 쓰지 않았다. 각주를 지원하는 렌더러는 정의를 문서 맨 끝으로 옮겨
우리가 만든 부록 제목 아래를 비우고, 이 문서의 1차 소비처인 Drive 프리뷰의 지원 여부도
확인되지 않았다. 지식 파사드가 이미 쓰는 `[E1]` 평문 마커와 표기를 통일한다.

## 사용 시나리오

**happy path** — 발표자료를 함께 준 경우

```
cha: !meeting  (녹취 전사본 .md 첨부 + 킥오프 발표자료 첨부)
```

에이전트/플러그인이 CLI를 부른다.

```bash
meeting_cli.py ingest --file <전사본> --label "주간 연구 미팅" --slides <킥오프.pdf>
```

결과 노트 상단:

```markdown
# 주간 연구 미팅

| 항목 | 내용 |
| --- | --- |
| 일시 | 2026-07-15 |
| 장소 | 공학관 402호 |
| 참석 | 차, 박, 김 |
| 발표자료 | kickoff.pdf (12쪽) |

## 한눈에 보기
- 중간보고서 제출일이 8월 1일로 확정됐다
...
## 액션 아이템
| 담당 | 할 일 | 마감 | 근거 |
| --- | --- | --- | --- |
| **나** | 데이터셋 사전(변수 정의서) 작성 | 2026-07-24 | [근4] |
```

`[근4]`의 실제 문장은 문서 맨 아래 부록 A에 있다. 전사본에서 "이거 다음 주까지 정리해줘"
였던 대목은 발표자료의 슬라이드 제목과 대조되어 정식 명칭으로 바뀌고, 확신이 없으면
`이것(추정: 그림 2)`처럼 추정임이 표시되며, 못 맞추면 원문 그대로 두고 **미결·확인 필요**로
내려간다 — 지어내지 않는다.

**실패 경로 1 — 발표자료를 못 읽는 경우**: 스캔본 PDF나 없는 파일을 줘도 회의록 생성은 그대로
진행되고(exit 0), 헤더에 `scan.pdf — 읽지 못함: 텍스트 레이어가 없습니다`로 남는다.

**실패 경로 2 — 발표자료에만 특허 내용이 있는 경우**: 회의 본문이 깨끗해도 문서 전체가
민감으로 판정된다. 발표자료 텍스트가 회의 본문과 **함께** 민감도 게이트에 합산되기 때문이며,
그 결과 추출은 비-GLM 경로로만 가고 Drive 발행은 건너뛴다.
