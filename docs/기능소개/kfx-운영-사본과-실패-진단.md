# 배포 사본과 실패 원인을 더 정확히 확인한다

## 무엇을 · 왜

소스가 있어도 실행 사본에 의존 파일이 빠지거나, 복구 알림에서 마지막 실패가 지워지면 원인을 찾기 어렵다.
이번 수리는 실행 사본의 완결성과 운영 진단을 함께 보강한다.

- 자가 스킬 관측 런타임은 필요한 automation 의존 파일까지 함께 배달한다.
- 워처 복구 통지는 마지막 실패의 상세와 시각을 보존한다.
- 설치 QA는 root가 아닌 운영자 계정으로도 프로브 파일·권한·바인딩을 검증한다.
- 관측 미러는 무시되지 않는 미추적 파일을 드리프트로 보되 정상 로그 같은 ignored 파일은 구분한다.
- meeting 자료 추출은 런타임 버전 불일치와 파일·추출 실패를 구별한다.
- meeting 단독 배포에서 플러그인이 바뀌면 재시동 필요를 명시한다.

## 사용 시나리오

**정상:** 워처가 연속 실패 뒤 복구되면 소유자는 복구 사실과 직전 실패 원인을 함께 읽는다.
자가 스킬 관측은 개발 체크아웃이 없는 배포 레이아웃에서도 필요한 모듈을 찾아 제안을 만든다.
운영자가 일반 계정인 설치도 같은 프로브 계약으로 검증한다.

**실패:** 미러에 출처 불명의 파일이 생기면 읽기 전용 검사가 이를 드러낸다.
검사가 파일을 지우거나 미러를 강제로 되돌리지는 않는다.
자료 추출에 필요한 런타임이 낡았으면 그 원인을 표시해 입력 파일 문제와 구분한다.

## 운영 경계 · 관련

통지는 자동 재시동 허가가 아니다. 재시동이 결정되면 기존 규칙대로 모든 Hermes gateway를 함께 다룬다.
코드 머지와 노드 사본 갱신은 별개이며, root 정적 자산은 소유자의 프로비저닝이 필요할 수 있다.
