# 캘린더 새 일정 기본색

노드 운영자가 Google Calendar의 새 일정 색상을 선택할 수 있다. 예를 들어
세이지(`colorId` `2`)를 고르면 새 일정의 동결된 생성 명령과 소유자 승인 카드에
같은 색이 들어간다. 기존 일정의 수정·삭제는 바꾸지 않는다. 스위치를 켜기 전에 동결한
생성 초안은 해시를 그대로 두고, 실행 직후 그 새 일정에만 색을 칠한다(아래).

## 실행 시 색 채우기 (2026-10-21)

스위치를 켜기 전에 만든 카드가 켠 뒤에 ✅ 되면 기본색으로 생겼다(소유자 지적 2026-10-21).
이제 생성 실행이 끝난 직후, 동결 본문에 `colorId`가 없고 노드 표식이 색을 가리키면
**방금 이 승인이 만든 일정 하나**에 `colorId`만 `events.patch`한다(`sendUpdates=none`,
초대 메일 없음). 동결 argv·draft 해시·카드 바이트는 그대로다. 승인은 "이 일정을 만든다"였고
색은 릴리스 승인으로 켠 노드의 표시 정책이라 승인 범위를 넓히지 않는다. 다른 일정은 건드리지
않는다. 초안에 `color_fill`, 감사 로그에 `calendar.color_fill`이 남는다. 칠하지 못해도
생성은 되돌리지 않는다(`COLOR-FILL-FAILED`). 같은 일정이 이미 있어 만들지 않았거나 지운
경우에는 칠하지 않는다([중복 방지](캘린더-중복-방지.md)).

## 왜

종전 생성 명령에는 `colorId`가 없어 Google의 캘린더 기본색을 사용했다.
생성 뒤 별도 작업으로 색을 바꾸는 대신, 실행 전 고정되는 명령에서 색을 정한다.
설정 파일이 나중에 바뀌어도 이미 승인한 명령의 색은 바뀌지 않는다.

## 켜고 끄기

릴리스 호스트의 운영자 계정에서 다음 파일을 준비한다. 파일 내용은 줄바꿈 없는
Google 색상 id `1`~`11` 하나이며, 숫자 앞의 0·공백·빈 파일·다른 값은 거부한다.

```bash
mkdir -p ~/.hermes/release-flags
printf %s 2 > ~/.hermes/release-flags/calendar-default-color
chmod 600 ~/.hermes/release-flags/calendar-default-color
```

기존 [릴리스 절차](../guide/manual-maintainer.md)를 따른다. 릴리스 카드에
`새 일정 기본색: 세이지`가 표시되고, 실제 값 `2`의 digest와 HEAD가 승인에 묶인다.
승인 뒤 선언된 `push_file` 배포·재조회로 노드의
`~/.hermes/calendar-default-color.mode`(0600)를 쓴다. 다른 HEAD·다른 색의 승인으로는
활성화할 수 없다. 노드 운영 파일을 직접 고치거나 별도 승인 경로를 만들지 않는다.

파일 삭제 후 다음 승인 릴리스는 `off`를 배포한다. 미설정 및 `off`는 예전
동결 argv·draft 해시·카드 바이트를 유지한다. 배포 표식이 깨졌거나 읽히지 않으면
생성을 거부한다. 런타임은 `HERMES_HOME`(기본 `~/.hermes`) 아래에서 표식을 읽는다.

## 사용 시나리오

소유자 지시로 예시 회의를 생성한다 → 초안이 `events.insert`의 JSON 본문에
`"colorId":"2"`를 고정한다 → 승인 대상이면 기존 소유자 전용 스레드에 v5 카드의
`색: 세이지`와 기존 SHA-256을 표시한다 → 기존 게이트가 그 명령만 실행한다.
설정값이 잘못됐으면 초안 저장·카드 게시·Google 쓰기 전에 거부한다.
본인 내부 쓰기와 외부 초대의 승인 구분은 바꾸지 않는다.

현재는 노드의 **모든 새 생성**에 적용하는 기본값이다. 업무 메일 digest/card의
일정만 세이지, 개인 일정(기일·생일·모임·병원·미용)은 기본색 유지라는 정책을
자동 판별하는 기능은 없다. 개인·업무 혼용 노드는 이 예외가 구현되기 전에는
켜지 않는다. [개인 일정 예외 후속](../follow-ups.md)을 별도로 다룬다.

## 병합·배포 확인

PR 병합만으로 켜지지 않는다. 병합 상태와 merge commit은 `gh pr view <번호>
--repo orientpine/cytoplasm --json state,mergedAt,mergeCommit`으로 확인한다.
그 커밋을 포함하는 서명 릴리스, 같은 HEAD의 승인·배포 영수증,
calendar live 마운트의 해당 코드, 노드 표식 `2`를 모두 확인한다.
마지막으로 새 예시 초안의 동결 JSON에 `colorId` `2`, 카드에 `색: 세이지`가
들어가는지, 스위치 전 초안이 실행되면 `COLOR-FILLED`가 남는지 확인한 뒤에만
노드별 임시 색상 보정 타이머를 끈다.
이 기능 자체는 보정 타이머나 과거 일정 backfill을 만들거나 끄지 않는다.
