# 승인 요청 안내 메시지 (요청별 스레드가 스스로를 알린다)

## 무엇을
소유자 승인이 필요한 요청이 `#agent-chat` 에 **스레드만** 만들지 않고, 「🔔 승인 대기 · <종류> · <제목>」
안내 메시지를 먼저 게시한 뒤 **그 메시지에 스레드를 건다**. 채널을 훑는 것만으로 결정 대기가 보인다.

## 왜
Discord 는 채널에 직접 만든 스레드를 「<에이전트 봇> 님이 … 스레드를 시작하셨어요」라는
**본문 없는 시스템 줄**로 렌더한다. 승인 카드는 스레드 **안**에 있으므로 채널에는 아무 내용도 남지 않고,
스레드를 열기 전에는 그것이 읽을거리인지 눌러야 할 결정인지 알 수 없다.

- 2026-09-09 소유자 보고: "스레드에 새 메시지가 없어요. 이렇게만 나와서, 승인이 필요한 스레드인지 한눈에 안보여."
- 같은 원인의 수리 티켓 `t_e23d85a1`: **캘린더 등록 승인 요청이 사용자에게 보이지 않고 폐기됐다.**

지시 메시지가 있는 요청(대화 중 생긴 것)은 원래 그 메시지에 앵커되어 이미 채널에 맥락이 남았다.
문제는 워처가 스스로 여는 요청(plaud 라이프로그 노트, 캘린더 등록, 수리)이었고, 이제 그것들도
자기 안내 메시지를 갖는다.

## 사용 시나리오
**정상 경로** — plaud 가 새 녹음 노트를 동결하고 승인을 요청한다.
1. `#agent-chat` 에 안내 메시지가 뜬다: `🔔 승인 대기 · 옵시디언 노트 승인 요청 · <녹음 id>.md`
   / `이 메시지의 스레드에서 ✅ 실행 / ⛔ 취소로 결정해 주세요.`
2. 그 메시지에 스레드가 달리고, 승인 카드(요약 미리보기 + ✅/⛔)는 예전처럼 스레드 안에 게시된다.
3. 소유자가 ✅ 를 누르면 결과 통지가 **같은 스레드**로 돌아오고 종결 시 접두어가 붙어 아카이브된다.

**거부 경로** — 채널이 메시지 게시를 거부하면(권한·설정) 요청은 **fail-closed** 로 멈춘다.
안내를 거부하는 채널은 스레드도 거부하므로, 조용히 예전의 보이지 않는 스레드로 되돌아가지 않는다.
