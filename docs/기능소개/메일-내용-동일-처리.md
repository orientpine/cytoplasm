# 메일 내용의 동일 처리

메일에 특허·patent·기밀 같은 낱말이 있어도 다른 메일과 같은 처리 경로를 쓴다.
중요도·스팸·일정·예산·회신 필요 분류는 계속하지만, 내용 때문에 제목·요약·승인
카드를 가리거나 초안을 별도 위치에 저장하거나 모델 경로를 제한하지 않는다.

## 사용 시나리오

- “특허 검토 요청 메일에 확인했다고 회신해줘”라고 하면 계정 설정의 모델 체인으로
  초안을 만들고 다른 회신과 같은 요청별 승인 스레드에 표시한다. 소유자 승인 뒤에만 발송한다.
- 새 메일 본문에 “기밀”이 들어 있어도 공통 초안 저장소와 동일한 승인 절차를 쓴다.
- 첨부가 허용 경로 밖에 있거나 승인 이후 본문·첨부가 달라지면 여전히 발송을 거부한다.
  소유자가 아닌 사람의 반응, 잘못된 서명, 인증 실패도 실행을 허용하지 않는다.

기존 데이터는 그대로다. 과거 별도 위치의 초안과 DB 열은 기존 기록을 읽기 위해
보존하며, 이관·재처리·과거 카드 재게시를 하지 않는다. 새 초안에는 내용 판정·태그를
저장하지 않는다. 과거 초안의 승인 해시는 원래 필드로 검증한다.

명시적 `--masked` 출력과 주소·오류 로그의 비밀 가림은 내용 판정과 무관한
보안 장치이므로 유지한다. entity preflight의 증거 참조 필드도 내용 판정이 아니라
실행 검증 기록의 계약이다.

관련: `skills/mail/SKILL.md`, `triage_pipeline.py`, `triage_digest.py`,
`triage_gate.py`, `triage_llm.py`, `test_mail_content_equal.py`.
