# 피어 은퇴 뒤 메모리 삭제

## 무엇을 · 왜
피어 게이트웨이와 계정을 은퇴해도 메모리 정리가 완료되도록, 명시 설정이 있으면
agent의 USER.md·MEMORY.md만 삭제한다. 실행되지 않을 피어의 완료 영수증을 기다리지 않는다.

## 사용 시나리오
- 소유자가 항목의 삭제 반응을 누른다 → agent가 기존 카드·원문 해시·소유자 신원을 검증하고
  선택을 동결한다 → 글이 정확히 같은 항목만 agent 파일에서 백업 후 삭제한다.
  로컬 `choice-deletes/<요청키>.<항목해시>.peer-retired.json`은
  `peer_retired=true, scope=agent, status=done`을 남긴다.
- 은퇴 상태에서는 peer 사용자 조회·경로 접근·새 `.decision.json` 전달이 없다.
  피어가 없거나 실행되지 않아도 완료된다. 예전 피어 파일을 대신 지우는 기능은 아니다.
- 설정이 없거나 `peer_retired=false`면 기존 양 계정 삭제와 peer 완료 영수증 대기가 그대로다.
  설정이 깨졌거나 읽을 수 없으면 실행하지 않는다. 카드가 변조되거나 백업 삭제가 중단된 경우도
  기존 거부·재실행 방지 규칙을 따른다.

## 설정 · 배포
설정은 agent 홈 `~/.hermes/memory-relocate/peer-mode.json`의 boolean `peer_retired`다.
이 릴리스의 시드 `automation/memory_relocate/peer-mode.json`은 `true`이며,
같은 패키지의 `deploy-manifest.txt`에 `v2:file`로 선언했다.
소유자가 릴리스를 승인하면 `deploy.sh`가 기존 `push_file`로 쓰고 배포 판정이 바이트를 확인한다.
노드 손 편집이나 새 권한은 없다. 피어 배포 행은 `held;reason=peer-retired`로 보존하고
이 배포기는 피어 요청함·워처를 새로 설치하지 않는다.
