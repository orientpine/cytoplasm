# 릴리스 노트 자동 게시 — 릴리스 = 태그 + Release 노트

## 무엇을
`automation/release.sh` 가 서명 태그를 자르는 같은 단계에서 GitHub Release 노트를 게시한다. 노트 초안은
승인 요청 전에 받고, 노트가 없거나 게시에 실패하면 릴리스는 끝나지 않은 것으로 실패한다.

## 왜
노드는 태그만 보고 수렴하므로 노트가 빠져도 아무것도 깨지지 않는 것처럼 보인다. 2026-10-08 v1.16.0·v1.17.0 은
태그만 올라가 Latest 가 v1.15.1 에 멈췄고, 이미 배포된 메일 다이제스트 개편이 어떤 노트에도 실리지 않았다.
노트 게시가 손 절차(매뉴얼 §1.7)였기 때문이다.

## 사용 시나리오
- **정상** — 초안을 쓴다(첫 줄 `# <한 줄 요약>`, 아래 한국어 본문: 바뀐 것·사용자에게 보이는 변화·깨지는
  변경/운영자 할 일). `automation/release.sh --notes-file note.md` → 승인 카드 → ✅ → 태그 →
  `vX.Y.Z — <요약>` Release 가 생기고 초안 아래 `## 포함된 PR` 과 신뢰키 지문이 붙으며 `update-trust.pub` 가
  첨부된다. 가장 높은 버전이면 Latest 가 된다.
- **초안 없음** — `release.sh` 가 승인을 쓰지 않고 exit 4 로 멈춘다(`no release note draft`).
- **게시 실패**(gh 인증·네트워크) — 태그는 남고 exit 11 `RELEASE-NOTE-FAIL`. 같은 명령을 다시 돌리면 노트만
  이어서 게시한다. ✅ 뒤 완결 타이머도 같은 초안으로 게시한다.
- **직전 태그에 노트가 없음** — 새 릴리스를 열지 않는다(exit 4 `RELEASE-NOTE-MISSING`).
  `automation/release-note.sh vX.Y.Z --notes-file note.md` 로 보충한 뒤 다시 돌린다.

## 관련
