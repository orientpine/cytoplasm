# 문서·보고서·주제·프롬프트를 같은 경로로 처리

문서 등록과 초안, 노트 보고서, 연구 주제와 주간 동향, 프롬프트 등록은 본문의
낱말에 따라 처리 경로를 바꾸지 않는다. 문서마다 붙이던 분류값과 그에 따른
저장 목적지 제한·주제 거부·모델 단계 생략·모델 경로 제한을 제거했다.

## 왜 바뀌었나

같은 요청이어도 특정 낱말이 있으면 저장 요청이 무시되거나 연구 주제가
등록되지 않고, 프롬프트 본문이 별도 위치로 분리됐다. 이제 소유자가 요청한
목적지와 계정의 모델 설정으로 동일하게 처리한다.

## 사용 시나리오

- `doctype draft ... --save-request "드라이브에 저장해줘"`: 입력에 특허·기밀이라는
  낱말이 있어도 지정한 저장 어댑터를 호출한다. Obsidian 소유자 승인과 Drive의
  소유자 단독 권한·내용 해시 검증은 그대로다.
- `report report --with-evidence`: 모든 노트와 근거를 동일하게 초안에 반영하며
  설정된 발행 경로를 사용한다.
- `topics add "patent monitoring"`: 주제가 등록되고 주간 동향에서 두 논문
  출처와 종합·한국어 정리 단계를 모두 사용한다.
- `prompt add ... --body-file ...`: 모든 새 본문은 0700/0600 overlay에 inline으로
  저장된다. 기존 데이터는 그대로. 이전 분리 파일은 기존 불투명 참조로 읽고
  이동하거나 재처리하지 않는다.
- 잘못된 식별자·저장 경로, 누락된 자격증명, 승인되지 않은 Obsidian 쓰기는
  기존 보안 검사에서 거부한다. 저장 목적지가 모호하면 여전히 확인을 요청한다.

## 유지한 경계

내용에 따른 분류만 제거했다. 경로·입력 형식·크기 검증, 파일 권한, 불변 버전,
낡은 실행 사본 거부, 소유자 승인, 원격 read-back, 비밀·공개 누출 검사는 유지한다.
doctype의 본문 없는 메타데이터와 모든 예시를 동일한 위치에 보관하는 기존
저장 계약도 그대로다. 주간 동향 오류 로그의 이메일·긴 숫자 가림은 운영 로그
보호이며 문서 내용 분류가 아니므로 유지한다.

관련: `skills/{doctype,report,topics,prompt}/SKILL.md`,
`automation/research_trends/{research_trends.py,deploy.sh,deploy-manifest.txt}`,
`prompts/README.md`.
